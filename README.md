# k-fable-opus-claude-md
Fable 5 모델 제공 중단 전에 미리 야물딱지게 뽑아서 우리기 시작했고 지금도 우리고 깎고 있습니다.<br>
대규모 언어 모델(LLM)을 코딩 및 연구 작업에 투입할 때 필요한 에이전트 지침과 조사 기록을 체계적으로 정리한 지침입니다.

AI가 혼자만의 헛된 망상에 빠지거나 코드를 함부로 망치지 않도록 틀어쥐고, 한국어로 명확히 소통하며, 작은 단위로 안전하게 작업하도록 유도하는 설정들을 모았습니다.
**주의** : Gemini,Deepseek,GLM 모델은 절대 사용하지 마세요. 헛소리와 함께 전역 규칙을 무시하고, 없는 사실을 날조해서 출력합니다. Google 은 LLM 을 접어야합니다. 적어도, 돈 받고 팔면 안됩니다. 

2026년 10월~11월 기준 추천과 비추천 LLM 은 다음과 같습니다.(high ~ Xhigh 기준)

**S 티어** : claude sonnet 5.5 - 저렴해진 Opus 입니다. Opus 에 비해 찐빠를 내도 어느정도 참고 쓸만합니다. 가장 무난한 모델입니다.
**A 티어** : claude opus 5.5 - 성능은 좋은데, 좀 비싸요. 그래도 좋습니다.
**B 티어** : GPT 6.1 Sol - 너무 느리고 느려요. 좀 비싸고 멍청할때도 있습니다. 그리고 쓸때없는 검증('닭이 먼저냐 달걀이 먼저냐' 같은 바보같은 검증)을 많이합니다.
**C 티어** : GPT 6 Astra, Fable 5.1 - 너무 비쌉니다. 성능대비 가격이 비싸고 그돈이면 Opus + Sonnet 조합으로 티키타카 검증하는게 좋습니다.
**D 티어** : GPT 6.1 Terra, GPT 6 Luna, Gemini 4 Argon - 여기서부터 돈주고 쓰기 싫은 모델입니다. 저렴하던 비싸던 개구립니다. 
**F 티어** : Deepseek V4.1 flash 1017 및 Deepseek 전체 모델, muse 전체 모델, Qwen 전체 모델, Grok 전체 모델, GLM 전체 모델, MiniMax 전체 모델, Kimi 전체 모델 - 머리는 나쁜데, 똑똑한 모델을 나름 베끼려고 노력을 많이 했습니다. 증류를 많이 했지만, 무식해서 써먹지를 못합니다. 벤치마크도 치팅을 하더라구요. <br>

폐기물(AI SLOP) : Gemini 3.8/3.7/3.6 flash, 3.1 Pro 등 이하 구글 제미나이 전 모델 - 구글은 AI(LLM) 사업을 접길 바랍니다. 진심으로요. gemini 그리고 pixel 은 도대체 왜 이렇게 개판인건가요? 집안 사정과 문제도 심각한걸로 알고 있는데, 지금이라도 손실을 적게할 수 있는 좋은 시점일겁니다. 이미 늦었지만요.<br>

로컬 LLM 은 모두 거기서 거기입니다. 내 컴퓨터가 데이터센터가 아닌 이상, 장난감 이상의 용도로 사용하지 마세요. FOMO 에 이끌려 수십수백기가의 RAM 을 때려박은 맥북, 맥 미니, 맥 스튜디오 등 로컬 LLM 용 장비를 수백~수천만원 주고 사는 짓은 더더욱 한심합니다. 물론 그 한심한 사람중 한명이 접니다.<br>

이상 로컬 LLM 에 수백만원을 쓰고, AI(LLM) API 에 수천달러를 태우고, 매달 다양한 모델과 플랜으로 몇백달러를 지출하고 있는 사람이 말한 진실입니다.

## 핵심 철학

이 설정 파일들의 목적은 LLM을 “멍청하지만 똑똑한 척하는 말 많은 바보”가 아니라,  
**정확히 복명복창하고, 코드 먼저 읽고, 작게 고치고, 검증하고, 정직하게 보고하는 작업자**처럼 움직이게 만드는 데 있습니다.

기본 작업 원칙은 단순합니다.

```text
복명복창 → 읽고 → 작게 고치고 → 검증(실패 시 재수정) → 솔직히 보고한다
```

물론, 이러한 지침들로 AI(LLM)을 완벽하게 통제한다거나, 모델 성능을 향상시킬 수는 없습니다. 모델 성능은 결국 학습 데이터와 학습량이니까요.<br>
어린아이에게 '비행기 조종사가 되는법' 이라는 책을 읽게 한다고 바로 비행기 조종사가 되는건 불가능하듯이 LLM과 이 지침들도 그렇습니다.

## 주요 특징

이 프로젝트의 md파일들은 AI(LLM)가 다음처럼 행동하도록 참고하게 합니다.(말 그대로 참고일 뿐입니다. 정작, 참고 있는 사람은 바로 너와 나 우리, 인간입니다...)

- **첫 마디 복명복창**: 프롬프트 입력 즉시 지시 사항을 먼저 요약·확인하여 컨텍스트를 멕입니다. 주인장의 군대 문화가 들어갔습니다.(똑바로 하자. 잘하자.) 
- **한국어 존댓말 준수**: 모든 설명과 기술 보고는 정중한 한국어로 작성하며, 코드·명령어·식별자·로그는 그대로 말합니다.(- 모델 성능에 따라서 중국어,일본어,영어 등 출력 품질이 흔들립니다. 매좀 맞아야 쓰겄는디...)
- **코드 독해 우선**: 수정에 앞서 기존 아키텍처와 함수 호출 관계를 꼼꼼하게 먼저 확인하여 프로젝트 훼손을 방지합니다.(- 과연 그럴까요? 다시 한번 말씀드리지만, AI 의 변하지 않는 성능이란 게 있습니다.) 
- **헛추상화 차단**: 요구하지 않은 거대 인터페이스, 불필요한 추상 클래스, 사용처 없는 래퍼 생성을 금지하고 최소 설계를 유지합니다.(- deepseek,GLM,Gemini 는 개 쓰레기입니다. 없는 코드와 내용을 만들어내니까요.)
- **최소 국소 수정**: 무분별한 리팩터링을 지양하고 오류가 발생한 지점만을 정밀하게 변경합니다. (- 과연 그럴까요? 수십번의 리펙토링으로도 해결하지 못한 오류와 버그들이 산처럼 쌓여있습니다...아오...)
- **재수정 루프 완결**: `typecheck`, `lint`, `test`, `build` 등 검증을 반드시 실행하며, 실패 시 원인을 파악해 통과할 때까지 반복 수정합니다.(- 검증을 하는 편인데, 보통 냄새나는 걸 덮으려고 합니다. 치우지 않아요.)
- **500줄 규칙 (God Object 방지)**: 단일 파일 500줄 제한을 두어 무분별한 비대화를 막고 책임별로 모듈을 분할하여 유지보수성을 보장합니다.(- 이것도 모델 성능에 따라서, 그리고 바보같은 함수명을 지어서 우회합니다. 아주 그냥 말만 하면 거짓말이 자동으로....)
- **안전 가드레일**: `.env`, SSH 키, 클라우드 인증 정보 접근과 파괴적 명령(`rm -rf`, 강제 푸시)의 무단 실행을 엄격히 차단합니다.(- 여러번 당했습니다. Gemini, GPT, claude 모두에서요... 토큰을 더 쓰게 하려는 술수 일수도 있습니다.)
- **목표 지향적 작업**: 긴 작업에서도 초기의 목적함수를 잃지 않도록 마일스톤 단위의 단기 루프로 분할하여 차근차근 진행합니다.(- 긴 작업은 좀 덜 멍청한(더 똑똑한) 모델로 하십쇼. loop 와 goal 명령어로 많이 당했습니다. 특히 켜두고 주무시면, 일어나고 개작살나있는 모습들을 보실 수 있습니다. '아 내 프로젝트 어디갔냐고!!!!')
- **웹 검색 실시간 검증**: 버전별 API나 라이브러리 사양은 공식 문서를 직접 검색하여 확인하고 라이선스 및 저작권을 철저히 준수합니다.(- 절대 아닙니다. 주석과 코드에서 파쿠리를 넘어 그냥 가져온게 절반 이상입니다. LLM 모델 제공자들이 모델 학습할때 하는 짓거리니까요.)

## 사용법

### 1. 설정 파일 선택 및 복사

모델에 구애받지 않고 범용으로 쓰실 때는 `universal/`에서 고르시고, 특정 모델에 맞추실 때는 `md/계열/모델/`에서 프로젝트 성격에 맞는 문서를 고릅니다. 기본 권장 문서는 `general.md`입니다.

사용하시는 프로젝트 루트에 복사해 주시면 됩니다.

```bash
# Claude Opus 5.5 모델 전용 일반 개발 규칙 적용
cp md/claude/opus-5.5/general.md /path/to/your/project/CLAUDE.md

# 범용 펌웨어 개발 규칙 적용
cp universal/firmware.md /path/to/your/project/AGENTS.md
```

`/path/to/your/project/`는 예시 경로이므로 실제 작업하시는 프로젝트 디렉터리 경로를 적어 주시면 됩니다.

| 도구 | 권장 복사 파일명 | 근거 및 비고 |
|---|---|---|
| Claude Code | `CLAUDE.md` (또는 `AGENTS.md`) | 공식 메모리 문서 확인 완료. `AGENTS.md`도 폭넓게 지원합니다 |
| Codex | `AGENTS.md` | 공식 지원 형식입니다 |
| Antigravity CLI | `AGENTS.md` | 공식 지원 형식입니다. `GEMINI.md`는 하위 호환으로 지원됩니다 |
| Gemini CLI | `GEMINI.md` | 공식 지원 형식입니다 |
| Kimi Code, Qwen Code, Grok Build, DeepSeek Harness | `AGENTS.md` | 각 도구별 최신 로딩 규격을 함께 확인하시는 것을 권장합니다 |

여러 분야가 복합된 프로젝트에서는 기본이 되는 `general.md`를 바탕에 두고, 필요한 분야 문서의 `## 3. 분야 규칙` 부분을 덧붙여 구성하시면 편리합니다.

### 2. Claude Code 메모리 로드 확인

Claude Code를 사용하시는 경우 다음 명령어로 메모리가 올바르게 로드되었는지 확인하실 수 있습니다.

```text
/memory
```

정상적으로 인식되었다면 다음과 유사하게 표시됩니다.

```text
Project memory           Saved in ./CLAUDE.md
User memory              Saved in ~/.claude/CLAUDE.md
```

### 3. Claude Code 추천 설정 (전역 메모리 vs 프로젝트 메모리)

전역 메모리는 짧고 간결하게 두고, 프로젝트 메모리에 상세한 규칙을 두는 구성을 권장합니다.

```text
~/.claude/CLAUDE.md      # 짧은 개인 전역 규칙
./CLAUDE.md              # 프로젝트별 긴 규칙
```

전역 메모리(`~/.claude/CLAUDE.md`)에는 이런 기본 준칙 정도만 두시는 편이 좋습니다.

```md
# 전역 Claude Code 규칙

- 모든 일반 답변은 한국어 존댓말로 작성합니다.
- 코드, 명령어, 파일 경로, API 이름, 로그는 원문을 유지합니다.
- 작업 전 기존 코드를 먼저 읽고, 추측으로 수정하지 않습니다.
- 수정 후 가능한 검증 명령을 실행합니다.
- 검증하지 않은 내용은 성공했다고 말하지 않습니다.
- 위험한 삭제, 강제 푸시, 시크릿 접근은 사용자 허가 없이 진행하지 않습니다.
```

전역 설정은 최소한의 일반 준칙만 정의해 두고, 프로젝트를 진행하시면서 자주 발생하는 오류나 실수 방지 규칙을 프로젝트 메모리(`CLAUDE.md`)에 차곡차곡 누적해 나가시는 편이 훨씬 효과적입니다.

## 주의사항

이 설정 파일들은 모든 문제를 마법처럼 해결해 주는 만능 도구가 아닙니다. AI(LLM)은 멍청하고 사람은 똑똑합니다.

프로젝트 아키텍처, 권한 설정, 모델 자체의 추론 성능, 그리고 사용자의 프롬프트 지시 수준에 따라 결과는 달라질 수 있습니다. 작업 중 발생하는 문제는 기반 모델의 고유한 추론 한계나 검증되지 않은 플러그인의 영향, 또는 모호한 프롬프트 지시에서 기인하는 경우가 많습니다.

- **인간 중심 판단 (Human-in-the-loop)**  
  하네스 엔지니어링, 프롬프트 엔지니어링, 멀티 에이전트 같은 자율 실행 기법을 맹신하기보다는, 사람의 직접적인 검토와 판단을 반드시 거치는 편이 안전합니다. 엔지니어의 올바른 개입이야말로 비용 낭비와 결함을 막는 가장 확실한 가드레일입니다.

- **작업 전 Git 상태 확인 및 백업 필수**  
  중요한 프로젝트에서는 반드시 작업 전에 Git 상태를 확인하고, 백업 브랜치를 분기한 뒤 진행해 주시기 바랍니다.

```bash
git status --short
git switch -c 내-작업-브랜치
```

구형 Git 환경이라면 `checkout -b` 명령을 사용하시면 됩니다.

## 한국어 윤문 및 AI 냄새 측정기

AI가 작성한 한국어 문장에서 기계적 번역투와 어색한 문체를 걷어내는 지침입니다. 문장 간 호흡, 불필요한 과서술, 과도한 피동 표현, 인위적인 감정 표현, 대구와 도치 구문을 다룹니다.

- `ko-academic.md`: 논문, 초록, 기술 보고서
- `ko-everyday.md`: 메신저, 이메일, 후기, 블로그
- `ko-literary.md`: 소설, 수필, 칼럼, 대사

[`AI 냄새 측정기/ai-smell-meter/`](AI%20냄새%20측정기/ai-smell-meter/README.md)는 한국어와 영어 글에서 AI 특유의 문체 패턴을 점검하고 교정안을 산출하는 도구입니다.

```bash
# 문체 패턴 분석
python3 "AI 냄새 측정기/ai-smell-meter/bin/ai-smell" analyze 원고.md

# 교정문 출력
python3 "AI 냄새 측정기/ai-smell-meter/bin/ai-smell" polish 원고.md > 원고.교정.md
```

산출되는 점수는 문체 패턴의 출현 빈도일 뿐 인간 저작물 여부를 판별하는 확정 확률이 아니라는 점에 유의해 주시기 바랍니다.

## 문서를 수정할 때

지침 문서를 수정하거나 새로운 모델을 등록하실 때는 다음 위치를 기준으로 작업합니다.

| 수정 대상 | 원본 위치 |
|---|---|
| 전체 문서 공통 규칙 | `universal/contract.md` |
| 분야별 고유 규칙 | `universal/분야.md` (한국어 공통 원리는 `universal/ko-core.md`) |
| 모델별 전용 지침 | `md/계열/모델/general.md`의 모델 블록 |
| 조사, 근거, 출처 | `docs/계열/모델/` |

공통 블록은 원본 파일만 수정하신 뒤 `sync` 명령을 통해 각 문서로 일괄 반영합니다. 개별 파일에 삽입된 공통 블록을 직접 수정하지 마세요.

```bash
# 공통 블록 동기화
python3 -I scripts/docs_tool.py sync

# 전체 구조 및 정합성 검사
python3 -I scripts/docs_tool.py check --complete

# 단위 테스트 실행
python3 -I -m unittest discover -s scripts/tests
```

## 알려진 한계

- 본 조사는 조사 시점의 최신 공개 자료를 기준으로 작성되었습니다. 미출시 모델 5종(Fable 5.5, Gemini 4 Carbon, GLM-5.5, Grok 4.8, Grok 5)과 Kimi K3.1의 상태는 재검토를 거쳤으나 최신 출처는 대체로 직전 배포 시점 기준입니다. 이후 발표된 세부 변경 사항은 반영되지 않았을 수 있습니다.
- 모델별 상세 교차 검증 결과는 `docs/계열/모델/xcheck.md`에 투명하게 기재해 두었습니다. 식별자, 단가, 컨텍스트 크기는 중요한 의사결정 전에 공식 1차 문서를 통해 한 번 더 확인하시는 것이 안전합니다.
- 모델별 한국어 문체에 대한 대규모 독립 실측 자료는 아직 공개된 바가 적어 정량 규칙의 일부 수치는 프로젝트 저자의 자체 보고에 기초하고 있습니다.
