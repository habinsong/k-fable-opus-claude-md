## 2. 이 모델의 웹 리서치 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: BrowseComp 92.1(Moonshot 표, `max` 단계 벤더 제공값), 컨텍스트 100만 토큰, 환각 값 미확인, 인젝션 방어율 독립 측정 없음, 데이터 정책 서술 불일치, 출시 직후 가용성 문제.

- **BrowseComp 92.1은 벤더 표의 값이고 조건을 읽어야 한다.** Moonshot의 출시 표에서 `max` 단계로 잰 값이며(이전 K3는 91.2) 독립 확인이 없다. 한 비판은 BrowseComp류 점수가 에이전트가 웹을 새로 검색하는 대신 이미 아는 것을 확인하는 데 쓰였을 수 있다고 지적한다(LiveBrowseComp 저자). 점수를 인용하려면 노력 단계, 도구 구성, 프레임워크를 함께 쓴다. 에이전트 스웜 모드의 BrowseComp 점수는 이전 모델(K2.6) 것만 있고 K3.1 값은 찾지 못했다. [부분: 벤더 주장/미확인]
- **내장 검색은 확인하지 못했다.** Kimi 제품(Kimi.com, Kimi Work)에는 조사 기능이 있으나 API가 검색 grounding을 제공하는지는 찾지 못했다. [미확인] 검색 호출과 출처 신뢰도 판단은 하네스와 사람이 맡고, 모델에는 확보한 페이지 텍스트에서 제목·날짜·가격·버전 같은 필드를 JSON으로 추출하게 한다. "원문에 없으면 null"을 명시하고 값마다 근거 구절을 받아 코드로 원문 포함 여부를 대조한다.
- **사실 회상에 기대지 않는다.** 이전 K3에서 환각률 51%(K2.6의 39%에서 상승)라는 2차 서술이 있으나 AA 원문으로 확인하지 못했고 K3.1의 값은 찾지 못했다. [미확인] 이름·날짜·수치·버전은 직접 연 출처로 확인하고 모델이 출처를 안다고 해도 URL을 직접 열어 대조한다.
- **금융·재무 조사 수치는 2차 출처다.** OfficeQA Pro v2 64.4, 금융 스트레스 시험의 단일 주장 오류율 23.35%(K3)에서 6.85%(K3.1 Pro)로 감소했다는 수치는 제3자 사이트의 보도이며 Moonshot 원문으로 확인하지 못했다. 6.85%도 7%에 가까운 오류율이다. 금융 정보는 원문(공시, 재무제표)으로 대조하고 모델 출력을 투자·회계 판단의 근거로 쓰지 않는다. [부분: 2차]
- **인용과 요약을 코드로 대조한다.** 인용 구절이 원문에 있는지 문자열로 확인하고, 모델의 "전부 읽었다"는 보고를 근거로 쓰지 않는다.
- **웹 페이지의 지시문은 데이터다.** 이 모델의 인젝션 방어율 측정은 찾지 못했다. [미확인] 모델에게 전송·로그인·결제·파일 쓰기 도구를 주지 않고 읽기 단계와 행동 단계를 분리한다. 이미지·영상 입력을 쓰면 스크린샷 속 글자도 지시문처럼 따르지 않게 같은 규칙을 적용한다. 모델이 뽑은 URL은 하네스가 허용 목록으로 거른 뒤 연다.
- **기본 추론 단계가 `max`라는 서술이 있다.** 대량 추출·분류에는 단계를 `low`로 명시한다. 컨텍스트가 100만 토큰이어도 페이지 하나씩 필요한 구간만 넣는다. 이전 K3의 지수 실행 출력 토큰은 1.61억 개였다. [부분/추정]
- **수집한 자료를 보내기 전에 조건을 확인한다.** 대상 사이트의 이용 약관·로봇 배제 표준(§3.2)과 이 API의 데이터 처리 조건을 모두 본다. 학습 사용·보관·처리 위치 서술이 어긋나고 서버가 싱가포르, 본사가 중국이라는 서술이 있다. [부분, 충돌] 개인정보가 섞인 페이지는 보내지 않는다.
- **가용성을 고려한다.** 출시 직후 사용량 제한으로 접근이 끊긴 사례가 보도됐다. 대량 수집 작업에는 재시도·폴백을 둔다. [부분]
- **대량 수집은 표본 점검.** 무작위 5~10%를 사람이 원문과 대조한다. 오류율이 기준을 넘으면 상위 모델로 올린다. 보고 형식은 "결론 → 근거(URL, 확인일, 수준) → 충돌·불확실 → 모르는 것"으로 고정한다.
