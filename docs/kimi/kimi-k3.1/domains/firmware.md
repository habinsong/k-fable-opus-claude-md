## 2. 이 모델의 펌웨어 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 폐쇄형 API 먼저라 기기 내 실행 불가, 공격적 사이버 능력을 의도적으로 낮춤(익스플로잇 벤치마크 90.5%→81%), 임베디드 평가 없음, 환각 값 미확인, 데이터 정책 서술 불일치.

- **기기 안에서 돌릴 모델이 아니다.** 가중치가 공개돼도 규모가 매우 크다(총 약 2.8조급 서술). 개발 워크스테이션에서 API로 쓰는 보조 도구로만 쓴다. 기기 내 추론이 필요하면 소형 모델 문서(`gemma-4-e2b`, `gemma-4-e4b`)를 본다. [부분]
- **펌웨어 코드를 직접 쓰거나 고치게 하지 않는다.** 레지스터 값, 인터럽트, 부트·업데이트 경로, 서명 검증은 환각이 장치 고장이나 보안 구멍이 된다. 임베디드·펌웨어 평가는 찾지 못했다. [미확인] 터미널 작업 점수(Terminal-Bench 4.0 65.7%, 벤더 제공값)는 장치 쓰기나 실시간 제약과 무관하다. 이 영역은 `gemini-4-argon`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol` 문서를 따른다.
- **펌웨어 보안 분석에는 이 모델이 부적합할 수 있다.** 취약점 탐색, 퍼징 하네스, 익스플로잇 재현, 보안 부팅 우회 검토는 학습 데이터에서 사이버 자료를 빼 능력을 낮춘 영역이다. 정당한 방어 연구에서도 결과가 약할 수 있다. 거부 규칙이 아니라 능력 축소이므로 "답을 했으니 신뢰할 수 있다"고 읽지 않고 결과를 사람이 검증한다. 취약점 대응(CRA 보고 의무 등, §3.2)에는 별도의 검증된 도구와 상위 모델을 쓴다. [부분: 벤더 주장]
- **레지스터·타이밍을 모델의 기억에서 가져오지 않는다.** 환각 값을 확인하지 못했다(이전 K3는 51%라는 2차 서술). 데이터시트·레퍼런스 매뉴얼의 개정판과 페이지를 사람이 확보한 텍스트로 주고, 확인하지 못했으면 값을 쓰지 않는다(§3.1). [미확인]
- **써도 되는 작업.** UART·RTT 로그 분류, 맵 파일 요약, 컴파일러 경고 그룹화, 변경 이력 요약, 호스트에서 돌리는 테스트 코드(하드웨어 추상화 뒤쪽 로직)의 초안. 입력은 관련 구간만 준다. 출력은 원본 로그·맵 파일과 한 건씩 대조한다. 기본 추론 단계가 `max`라는 서술이 있어 단순 분류에는 `low`를 명시한다. [부분/미확인]
- **에이전트에 장치 접근을 열어 주지 않는다.** 플래시 소거, 퓨즈·OTP, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금은 사람이 대상 장치와 이미지를 확인한 뒤 실행한다. 프로그래머·시리얼 제어 도구는 읽기 전용부터 연결하고 권한·훅으로 쓰기 명령을 차단한다. Moonshot의 Kimi Code 안내(승인 기능 유지, diff 검토, 비밀 보호, 되돌릴 수 있는 Git 브랜치)도 따른다. [부분]
- **변경 후 검증을 강제한다.** 호스트 단위 테스트와 정적 분석을 직접 돌려 출력을 읽고, 경고를 억제하라는 제안은 따르지 않는다. 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.
- **펌웨어 소스·로그·서명 키·양산 이미지를 API로 보내지 않는다(약관 확인 전).** 학습 사용·보관·처리 위치 서술이 어긋나고 서버가 싱가포르, 본사가 중국이라는 서술이 있다. [부분, 충돌] 서명 키와 디버그 인증 정보는 약관과 무관하게 보내지 않는다(§3.4). 수출 통제·고객 계약상 국외 이전이 제한된 코드는 법무 확인 전에 보내지 않는다.
