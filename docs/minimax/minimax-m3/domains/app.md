## 2. 이 모델의 앱 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 428B MoE라 기기 내 실행 불가, 제한적 커뮤니티 라이선스(용도 금지 조항), 데이터 정책 서술 충돌(싱가포르 법인·미국 저장 서술), 모바일 개발 독립 평가 없음.

**앱에 내장할 때**
- **기기 안에서 돌릴 모델이 아니다.** 총 428B(활성 약 23B)라 전체를 메모리에 올려야 한다. 앱은 서버를 거쳐 호출하는 구조만 가능하다. 모바일 온디바이스는 `gemma-4-e2b`, `gemma-4-e4b` 문서를 본다. [부분]
- **API 키를 앱 바이너리나 리소스에 넣지 않는다.** 자체 백엔드에서 키 보관, 사용량 제한, 요청 검증, 로깅을 한다(§3.1 비밀 규칙). 모델 출력은 신뢰하지 않는 입력으로 취급해 서버에서 검증한 뒤 앱에 전달한다.
- **개인정보 선언과 실제 동작을 맞춘다.** API 정책은 싱가포르 주소의 Nanonoble Pte. Ltd.가 발행하고 데이터가 미국 데이터센터에 저장된다는 독립 안내가 있으나, 더 오래된 정책은 중국을 가리켜 충돌한다. 보관 기간은 고정값이 없고, 모든 API 입력이 학습에서 제외된다는 포괄적 약속이나 ZDR은 공개 문서로 확인되지 않는다는 평가가 있다. [부분, 충돌] 출시 전에 약관과 개인정보 정책을 원문으로 읽고 앱의 개인정보 선언(Apple 개인정보 영양 표시, Google Play 데이터 보안 양식)과 처리방침에 전송 항목과 국외 이전을 반영한다. 소비자 제품(음성, 에이전트, Talkie)의 정책과 API 정책을 혼동하지 않는다. 아동·민감정보는 확인 전에 보내지 않는다.
- **용도 금지 조항을 앱의 사용 약관에 반영한다.** 커뮤니티 라이선스는 군사 용도, 미성년자 착취, 유해한 허위 정보, 혐오 표현을 금지한다는 요약이 있다. 가중치를 직접 호스팅해 최종 사용자에게 기능을 제공하면 이 조항을 사용자 약관으로 전달해야 할 수 있다. LICENSE 원문을 법무가 확인한다(§1.5). [부분: 2차 요약/미확인]
- **호스트 선택이 컨텍스트와 가격을 바꾼다.** 같은 모델이 호스트마다 컨텍스트 한도(Fireworks는 출시 시점 50만 토큰)와 가격이 다르다. 사용할 경로의 한도를 확인하고, 사용자당 한도, `max_tokens`, 요청 빈도 제한을 서버에 두며 실제 청구서로 확인한다. [부분, 충돌]
- **모델 교체를 앱 업데이트 없이 할 수 있게 설계한다.** 후속 `minimax-m3.1-flash`가 한 달 전에 나왔다. 서버 쪽 모델 설정, 폴백 모델, 회귀 시험, 기능 플래그를 둔다.

**개발 보조로 쓸 때**
- **모바일(Kotlin·Swift) 코드에 대한 독립 평가는 찾지 못했다.** [미확인] SWE-Bench Pro 59.0%로 Opus 4.8(69.2%)에 못 미쳤다는 보도가 있다. 컴파일·린트·단위 테스트·UI 테스트로 검증하고, 수명주기·권한·비동기 처리가 걸린 구현은 상위 모델 문서(`claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon`)와 같은 과제로 비교한다. [부분: 언론]
- 스토어 규정은 기억으로 답하지 않고 공식 문서로 확인한다(§3.2). 서명 키, 프로파일, 스토어 제출·배포는 승인 후에만 한다.
