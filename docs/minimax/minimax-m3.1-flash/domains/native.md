## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 경량 변형, DeepSWE v1.1 73.7%(벤더), 독립 지수 42, 작업당 비용 $0.22, 환각률 93% 보도, 가중치 공개 여부 충돌, C/C++·Rust 독립 평가 없음.

**개발 보조로 쓸 때**
- **DeepSWE v1.1 73.7%는 벤더 제공값이다.** 독립 재현이 없고 시스템 코드 능력과 다른 지표다. 독립 지수 42는 일반 능력 지표이며, 비교 중앙값(13)에 비해 높다는 사실이 C++·Rust 정확도를 뜻하지 않는다. 같은 과제로 `minimax-m3`와 상위 모델을 비교한다. [부분: 벤더 주장]
- **C++·Rust·시스템 코드의 언어별 독립 평가는 찾지 못했다.** [미확인] 메모리 관리, 동시성, 수명, ABI는 문법이 맞아도 틀리기 쉬우므로 핵심 변경에는 쓰지 않고, 쓴다면 sanitizer(ASan·UBSan·TSan)와 테스트를 지시문으로 강제한다. 핵심 변경은 `claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon` 문서를 따르거나 우리 코드로 같은 과제를 비교한다.
- **환각 경향 때문에 시스템 API 시그니처를 모델 기억에 맡기지 않는다.** 모르는 질문에도 답을 시도해 환각률이 93%라는 보도가 있다(2차, 원문 미확인). 존재하지 않는 함수·플래그·헤더를 지어낼 수 있으므로 컴파일러 출력과 공식 문서로 확인하고, 빌드가 통과해도 의미가 맞는지는 테스트와 sanitizer로 확인한다. [부분: 2차]
- **반복 시도 전략이 어울린다.** 작업당 비용이 낮아($0.22 대 M3 $0.51) 컴파일 오류 설명, 테스트 초안, 로그 분류, 기계적 변환처럼 결과를 도구가 검증하는 작업을 여러 번 시도하기 쉽다. 같은 실패가 3번 반복되면 접근을 바꾸거나 상위 모델로 올린다(§1.2). [부분]
- **에이전트 루프에 안전장치를 먼저 둔다.** 파괴적 명령 차단(권한·훅), 작업 디렉터리 격리, 시간·토큰 한도를 설정하고, 완료 보고는 빌드·테스트·sanitizer 출력과 `git diff`로 확인한다. 모델이 완료했다고 말해도 믿지 않는다. 테스트·경고·sanitizer 설정이 바뀌었는지도 확인한다. 억제 지시문을 넣거나 검사를 끄는 제안은 따르지 않는다.
- **빠르다는 주장은 검증한다.** M3보다 거의 3배 빠르다는 MiniMax 주장과 초당 약 100 토큰(프리뷰, 미검증)은 독립 측정이 없다. 빌드-테스트 루프의 실제 지연을 우리 환경에서 직접 측정한다. [부분: 벤더 주장]
- **미공개 소스를 API로 보내기 전에 데이터 조건을 확인한다.** 싱가포르 법인·미국 저장이라는 독립 안내와 중국을 가리키는 오래된 정책이 충돌하고 학습 제외 약속과 ZDR이 확인되지 않는다. [부분, 충돌] 확인 전에는 비밀·고객 코드를 보내지 않는다(§1.6).

**애플리케이션에 내장할 때**
- **모델은 서버 API로 호출한다.** 가중치 공개 여부와 크기가 확인되지 않았으므로 데스크톱 프로그램에 번들하지 않는다. 클라이언트에 API 키를 두지 않고 자체 백엔드를 거친다. 모델 출력으로 만든 경로·명령·코드를 그대로 실행하지 않으며 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1). 오프라인 요구에는 소형 모델(`qwen3.6-27b`, `gemma-4-e4b`)을 본다. [부분/미확인]
