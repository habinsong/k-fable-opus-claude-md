## 2. 이 모델의 앱 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 기본 `high`, 긴 작업에 강점, 낮은 effort에서는 기억으로 답함, 독립 도구 호출을 한 턴에 하나씩 보낼 수 있음.

- **모바일 앱 개발에 대한 독립 평가는 찾지 못했다.** [미확인] Anthropic은 여러 파일에 걸친 기능, 대규모 리팩터링·마이그레이션, 디버깅, 몇 시간 단위 코드 리뷰가 개선됐고 컴퓨터 사용에서 실패한 단계를 더 잘 복구한다고 설명한다. [확인: 벤더 설명] 이 설명은 벤더 주장으로 읽고, 실기기·시뮬레이터 결과로 확인한다.
- **스토어 정책과 플랫폼 요건은 검색으로 확인하게 한다.** `low` effort에서는 검색 도구를 덜 부르고 기억으로 답한다. 정책 날짜·요건 같은 최신 사실은 effort를 올린 턴에서 다루거나, "이름을 사용자가 쓴 그대로 검색해서 확인하라"는 지침을 붙인다. §3.2 표는 작업 시점에 공식 문서로 다시 확인한다. [확인]
- **빌드·테스트 출력이 길다.** 토크나이저가 Opus 4.7 이전 모델보다 같은 글에서 약 30% 더 많은 토큰을 낸다. [확인] 출력은 파일로 한 번 저장한 뒤 실패한 구간만 읽는다.
- **독립 호출을 묶게 한다.** bash·편집기 하네스에서는 다음 독립 작업(예: 여러 파일 읽기)을 턴마다 하나씩 보낼 수 있다. "필요한 것을 먼저 나열하고 서로 의존하지 않는 호출은 한 번에 요청하라"를 덧붙인다. [확인]
- **긴 세션의 요약에는 남길 것을 지정한다.** 직접 컴팩션(요약)을 구현하면 겪은 문제와 해결, 시도했다 버린 접근과 이유, 사용자가 정한 제약과 선호(정확히), 현재 상태, 남은 일, 복원하기 어려운 세부(버전, 번호, 경로)를 보존하라고 지시한다. 서버 쪽 컴팩션은 이미 이렇게 한다. [확인]
- **하위 에이전트를 쓰면 리드가 기다리지 않게 한다.** 긴 빌드·테스트를 하위 에이전트에 맡길 때 시작 도구가 즉시 반환하게 하면 평균 완료 시간이 줄었다고 한다. [확인]
- **서명 키, 프로파일, 스토어 제출·배포는 승인 후에만.** 승인 규칙은 §1.6 목록뿐이다.
- **비용.** 일상적인 화면·로직 작업은 Opus 5.5나 Sonnet 5.5가 경제적이다. Fable 5.1은 막힌 문제에만 올린다. [확인: 위치]
- **데이터 보관.** 30일 보관이며 ZDR 비대상이다. 사용자 데이터나 개인정보가 있는 코드·로그를 보내기 전에 보관 정책을 확인한다. [확인]
