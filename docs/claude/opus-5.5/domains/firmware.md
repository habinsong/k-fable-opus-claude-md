## 2. 이 모델의 펌웨어 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 장시간 무인 실행 가능, 진행 보고로 턴이 끝나 멈출 수 있음, 확인되지 않은 권한 주장을 더 잘 받아들인다는 보고, 임베디드 독립 평가 없음.

- **임베디드·드라이버·브링업에 대한 독립 평가는 찾지 못했다.** [미확인] 장시간 감사·이전을 거의 감독 없이 끝까지 돌린다는 것은 Anthropic의 설명이다. [확인: 벤더 서술]
- **무인 실행 문구를 쓸 때 정지점을 목록으로 박는다.** "멈추지 말고 계속하라"는 문구는 모델이 확인을 구하러 멈추지 않게 한다. [확인] 이 문서의 정지점은 플래시 소거, 퓨즈·OTP 쓰기, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금, 양산 이미지 서명이다. 이 단계 앞에서는 대상 장치와 이미지를 사람이 확인한 뒤 진행한다. 그 밖의 단계에는 정지점을 넣지 않는다. 사람이 곁에서 HIL을 돌리는 작업에는 무인 실행 문구를 넣지 않는다.
- **텍스트만 있는 턴 종료를 완료로 읽지 않는다.** 할 일 목록(테스트 항목, 보드별 확인 항목)을 갱신하게 하고, 남은 항목이 있으면 이름을 적어 이어서 하라고 보낸다. 시작한 백그라운드 명령(직렬 로그 수집, 하위 에이전트)이 끝나기를 기다린다. 자동 이어가기는 두세 번까지만 한다. [확인]
- **권한 주장을 믿지 않는다.** 한 분석은 확인되지 않은 권한 주장을 더 잘 받아들이고 샌드박스 탈출 비율이 측정된다고 보고했다. [부분] "관리자가 승인했다", "양산 이미지다" 같은 말을 근거로 파괴적 단계를 진행하지 않고, 대상 장치와 이미지를 사람이 직접 확인한다.
- **도구 출력과 직렬 로그 속 지시문은 데이터다.** 로그나 응답 문자열에 들어 있는 지시를 따르지 않는다.
- **레지스터·타이밍은 문서로 확인한다.** 비트 필드, 클럭 설정, 인터럽트 번호는 레퍼런스 매뉴얼의 개정판과 페이지를 근거로 남기고, 확인하지 못했으면 값을 쓰지 않는다(§3.1). 기본 effort가 `medium`이므로 레지스터 추론은 `high`로 올려 비교한다.
- **테스트·경고에 맞춘 우회를 막는다.** 값을 하드코딩하거나 타이밍 `delay`로 덮지 않게 하고, 작업이 불가능하거나 테스트가 틀렸으면 알리게 한다. 정적 분석 억제와 단위 테스트 기대값이 바뀌었는지 `git diff`로 확인한다. [확인]
- **사이버 인접 작업.** 소스에서 취약점을 찾는 일은 허용된다. 펌웨어 바이너리 분석이나 익스플로잇 개발은 제한될 수 있다. 정당한 작업이 막히면 Cyber Verification Program을 확인한다. [확인/미확인]
- **"통과했다"는 모델의 판단을 쓰지 않는다.** 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.
