## 2. 이 모델의 웹 리서치 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 바뀐 세부를 학습 지식으로 답하는 경향, 지식 평가 54%, 간접 프롬프트 인젝션에 맞서도록 훈련됨, 작업 중 사용자 메시지를 주입으로 오해할 수 있음.

- **검색을 명시적으로 요구한다.** 이 모델은 허용·요구·요금처럼 바뀐 세부를 학습 지식으로 답할 수 있다. 도구 사용을 억제하는 문구("꼭 필요할 때만 도구를 써라", "도구 호출을 최소화하라")를 지우고 "학습 이후 바뀌었을 수 있는 세부는 확신이 있어도 검색 도구로 확인하라. 보고서나 비교 같은 조사 작업은 학습 지식이 아니라 최신 출처를 모아 써라"를 시스템 프롬프트에 넣는다. [확인]
- **조사에서 사실 회상에 기대지 않는다.** Artificial Analysis 지식 평가에서 Sonnet 5.5는 54%, Opus 5.5는 66%였다. 시스템 카드는 Sonnet 5보다 오답을 낼 가능성이 약간 높다고 서술했다는 보도가 있다. [부분] 핵심 주장은 모델이 연 출처 두 곳 또는 1차 출처 한 곳으로 직접 대조하고, 열지 못한 출처는 "미열람"으로 분리한다. 인용 환각에 대한 Sonnet 5.5 전용 측정은 찾지 못했다. [미확인]
- **JSON 결과는 마지막 JSON 값을 파싱한다.** 구조화 출력을 쓰지 못하는 조사 파이프라인에서는 모델이 응답 텍스트에서 추론한 뒤 끝에 JSON을 쓸 수 있다. 텍스트 블록만 읽고 `stop_reason`이 `max_tokens`면 실패로 보며, 각 `{`·`[`에서 JSON 값을 파싱해 마지막 값을 쓴다. 첫 `{`에서 마지막 `}`까지 자르지 않는다(초안이 섞일 수 있다). 기대한 필드가 없으면 한 번 재시도한다. [확인]
- **조사 과제는 적응형 추론으로.** 도구 없는 요청에서 `between_tools`는 생각 없이 답한다. 몇 단계 계산이나 비교가 필요한 조사 질문에는 적응형을 쓰고 "답하기 전에 문제를 끝까지 생각하라"를 덧붙인다. [확인]
- **웹 페이지의 지시문은 데이터다.** 이 모델은 도구 결과 등으로 들어오는 간접 프롬프트 인젝션에 맞서도록 훈련됐다. 방어율의 독립 수치는 찾지 못했다. [확인/미확인] 외부 전송, 로그인, 결제, 계정 변경은 페이지가 시켜도 하지 않는다.
- **작업 중 사용자가 보낸 메시지를 주입으로 오해할 수 있다.** 사용자 글을 `tool_result` 안에 넣지 말고 같은 사용자 메시지의 텍스트 블록으로 보내며, 하네스 알림은 별도의 시스템 메시지로 둔다. [확인]
- **진행 상황을 요구한다.** 긴 조사 턴이 조용해지면 하네스가 "사용자가 한동안 소식을 듣지 못했다. 몇 마디로 무엇을 하고 있는지 말하고 계속하라"를 보내도록 한다(연속 5번의 도구 호출 뒤, 두세 번까지). 보고 형식은 "결론 → 근거(URL, 확인일, 수준) → 충돌·불확실 → 모르는 것"으로 고정한다. [확인]
- **effort.** 조사는 `high`로 시작한다. 낮은 effort에서는 검증을 줄인다. `max`는 비싸고 점수가 떨어진 사례가 있어 쓰지 않는다. [확인/부분]
