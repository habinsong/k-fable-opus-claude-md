## 2. 이 모델의 펌웨어 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 폐쇄형 API 모델이라 기기 내 실행 불가, 도구 사용 강점은 독립 확인(Meta 점수는 회의적 평), 임베디드 평가 없음, 데이터 약관 불분명.

- **기기 안에서 돌릴 모델이 아니다.** 폐쇄형 Spark는 API로만 쓴다. 오픈 가중치 변형도 맥 스튜디오 두 대 규모라 MCU는 물론 임베디드 리눅스 SBC에도 올릴 수 없다. 개발 워크스테이션에서 API로 쓰는 보조 도구로만 쓴다. 기기 내 추론이 필요하면 소형 모델 문서(`gemma-4-e2b`, `gemma-4-e4b`)를 본다. [부분]
- **펌웨어 코드를 직접 쓰거나 고치게 하지 않는다.** 레지스터 값, 인터럽트, 부트·업데이트 경로, 서명 검증은 환각이 장치 고장이나 보안 구멍이 된다. 임베디드·펌웨어 평가는 찾지 못했다. [미확인] DeepSWE 같은 소프트웨어 엔지니어링 점수(75.4%, `max` 단계의 벤더 보고)는 장치 쓰기나 실시간 제약과 무관하다. 이 영역은 `gemini-4-argon`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol` 문서나 `muse-wonder` 문서를 따른다.
- **레지스터·타이밍을 모델의 기억에서 가져오지 않는다.** 환각 수치는 벤더가 고른 한 가지 시험(이미지가 빠진 질문 35.0%)뿐이고 부품 값 회상 능력의 증거가 아니다. 데이터시트·레퍼런스 매뉴얼의 개정판과 페이지를 사람이 확보한 텍스트로 주고, 확인하지 못했으면 값을 쓰지 않는다(§3.1). [부분: 벤더 주장]
- **써도 되는 작업.** UART·RTT 로그 분류, 맵 파일 요약, 컴파일러 경고 그룹화, 변경 이력 요약, 호스트에서 돌리는 테스트 코드(하드웨어 추상화 뒤쪽 로직)의 초안. 입력은 관련 구간만 준다. 출력은 원본 로그·맵 파일과 한 건씩 대조한다.
- **에이전트에게 장치 접근을 열어 주지 않는다.** 도구 사용에 강하다는 평이 있어 Muse Code 같은 에이전트에 프로그래머를 연결하고 싶어질 수 있다. 플래시 소거, 퓨즈·OTP, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금은 사람이 대상 장치와 이미지를 확인한 뒤 실행한다. 프로그래머·시리얼 제어 도구는 읽기 전용부터 연결하고 권한·훅으로 쓰기 명령을 차단한다. 에이전트 평가에서 입력 토큰이 늘었다는 독립 보고가 있어 반복 루프의 비용 한도도 둔다. [부분]
- **변경 후 검증을 강제한다.** 호스트 단위 테스트와 정적 분석을 직접 돌려 출력을 읽고, 경고를 억제하라는 제안은 따르지 않는다. 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.
- **펌웨어 소스·로그·서명 키·양산 이미지를 API로 보내지 않는다(약관 확인 전).** 데이터 처리 서술이 충돌하고 보관 기간이 공개돼 있지 않다. [미확인, 충돌] 서명 키와 디버그 인증 정보는 약관과 무관하게 보내지 않는다(§3.4). "Contributor" 등급은 쓰지 않는다.
