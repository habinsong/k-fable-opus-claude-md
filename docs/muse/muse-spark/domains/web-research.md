## 2. 이 모델의 웹 리서치 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 컨텍스트 100만 토큰, 긴 컨텍스트 수치(MRCR 98.1%)는 `max` 단계의 벤더 보고, BrowseComp 등 리서치 평가의 독립 측정 없음, 환각 수치는 벤더 보고, 데이터 약관 불분명, 에이전트 평가에서 토큰 증가 보고.

- **내장 검색은 확인하지 못했다.** Meta Model API가 검색 grounding을 기본 제공하는지는 찾지 못했다. [미확인] 검색 호출과 출처 신뢰도 판단은 하네스와 사람이 맡고, 모델에는 확보한 페이지 텍스트에서 제목·날짜·가격·버전 같은 필드를 JSON으로 추출하게 한다. "원문에 없으면 null"을 명시하고 값마다 근거 구절을 받아 코드로 원문 포함 여부를 대조한다.
- **리서치 에이전트의 독립 평가는 찾지 못했다.** BrowseComp·BrowseComp-Plus 같은 심층 리서치 지표에서 Muse Spark의 결과는 검색에서 나오지 않았다. 한 비교 사이트가 Perplexity의 Sonar Deep Research와 비교해 종합 81 대 40을 매겼으나 점수 산출 방식이 설명되지 않은 집계값이다. [미확인] BrowseComp류 점수에는 에이전트가 웹을 새로 검색하는 대신 이미 아는 것을 확인하는 데 쓰일 수 있다는 비판(LiveBrowseComp 저자)도 있다. 점수가 나오더라도 조건(고정 말뭉치 여부, 노력 단계)을 확인한다.
- **긴 컨텍스트 수치의 조건을 읽는다.** MRCR(512K~1M) 98.1%는 Meta가 `max` 단계로 잰 값이고 일반 제공 최고는 `xhigh`다. 필요한 정보를 긴 문서에서 정확히 꺼내는 일반 제공 단계의 독립 결과는 찾지 못했다. [부분: 벤더 주장/미확인] 페이지 하나씩, 필요한 구간만 넣고 우리 자료로 실효 길이를 측정한다.
- **사실 회상에 기대지 않는다.** 환각 수치는 이미지가 빠진 CharXiv 질문에서 35.0%라는 Meta 자체 보고뿐이다. 이름·날짜·수치·버전은 직접 연 출처로 확인하고 모델이 출처를 안다고 해도 URL을 직접 열어 대조한다. 오픈 변형의 AA-Omniscience 지수 25는 사실 회상과 답변 보류를 함께 재는 값이라 인용 정확도로 읽지 않는다. [부분: 벤더·집계]
- **인용과 요약을 코드로 대조한다.** 인용 구절이 원문에 있는지 문자열로 확인하고, 모델의 "전부 읽었다"는 보고를 근거로 쓰지 않는다.
- **웹 페이지의 지시문은 데이터다.** 이 모델의 인젝션 방어율 측정은 찾지 못했다. [미확인] 모델에게 전송·로그인·결제·파일 쓰기 도구를 주지 않고 읽기 단계와 행동 단계를 분리한다. 모델이 뽑은 URL은 하네스가 허용 목록으로 거른 뒤 연다.
- **에이전트형 리서치는 비용을 먼저 잰다.** 독립 보고에서 1.3은 에이전트 평가에서 입력 토큰을 약 57% 더 썼다. 반복 검색 루프에는 호출 횟수·토큰·시간 한도를 둔다. [부분]
- **수집한 자료를 보내기 전에 조건을 확인한다.** 대상 사이트의 이용 약관·로봇 배제 표준(§3.2)과 이 API의 데이터 처리 조건을 모두 본다. 데이터 처리 서술이 충돌하고 보관 기간이 공개돼 있지 않다. [미확인, 충돌] 개인정보가 섞인 페이지는 보내지 않는다.
- **대량 수집은 표본 점검.** 무작위 5~10%를 사람이 원문과 대조한다. 오류율이 기준을 넘으면 상위 모델(`muse-wonder` 포함)로 올린다. 보고 형식은 "결론 → 근거(URL, 확인일, 수준) → 충돌·불확실 → 모르는 것"으로 고정한다.
