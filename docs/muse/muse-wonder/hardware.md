## 2. 이 모델의 하드웨어 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 폐쇄형 API 모델, 컨텍스트 100만 토큰, 독립 지수 52(Full 56), 환각·사실성 평가 없음, 하드웨어 설계 평가 없음, 안전 분류기 적용, 데이터 약관 충돌.

- **설계 판단에 쓰지 않는다.** 핀 배치, 정격, 타이밍, 수식은 틀리면 보드가 망가지거나 위험해진다. 이 모델의 회로·PCB·HDL 평가는 찾지 못했다. [미확인] 독립 지수(Wonder 52, Full 56)와 코딩 점수는 일반 능력 지표이고 회로 설계 정확도를 대표하지 않는다. 설계는 `claude/opus-5.5`(독립 지수 58), `gemini-4-argon`, `gpt-6.1-sol` 같은 상위 모델 문서와 같은 과제로 비교하고, 그 결과도 데이터시트 원문과 도구 계산으로 확인한다. [부분]
- **값 회상을 믿지 않는다.** Wonder의 환각·사실성 평가는 찾지 못했다. [미확인] 부품 번호, 핀 번호, 레지스터 주소, 정격을 모델 기억에서 가져오게 하지 않는다. 값은 사람이 확보한 데이터시트 텍스트에서만 꺼내게 하고, 값마다 문서명·개정판·페이지를 같이 받아 원문 PDF와 한 건씩 대조한다. 원문에 없으면 null이다(§3.1).
- **긴 컨텍스트에 데이터시트를 통째로 넣지 않는다.** 컨텍스트가 100만 토큰이어도 필요한 장과 표만 넣는다. 토큰 소비가 많은 모델이라(AA 지수 실행에서 출력 토큰이 비교군 중앙값의 약 1.5배) 입력을 줄이는 쪽이 비용에도 유리하다. PDF 표를 텍스트로 변환한 결과도 원문과 대조한다. [부분]
- **이미지(회로도 사진·PCB 사진) 판독은 근거로 쓰지 않는다.** 이 모델의 이미지 입력 지원과 판독 정확도는 확인하지 못했다. [미확인] 읽은 값은 원문 텍스트·넷리스트·ERC 보고서와 대조하고, 읽기 어려운 부분은 추측하지 말고 "판독 불가"로 표시하게 한다.
- **써도 되는 작업.** BOM 정규화, 부품 번호 목록 변환, 시험 로그 분류, 데이터시트 텍스트에서 정해진 필드 추출, 측정·변환 스크립트(파이썬)의 초안. 단가가 높으므로($4/$20) 대량의 단순 정리는 `muse-spark`나 더 싼 모델로 처리한다. 스크립트는 알려진 값을 넣어 실행해 확인한다.
- **계산은 도구로 한다.** 전류 예산, 분압, 필터, 열 계산은 스크립트·시뮬레이터 출력으로 확인하고 식과 가정을 남긴다. `max` 단계의 긴 추론으로 낸 풀이도 마찬가지다.
- **안전 분류기가 정당한 요청을 거부할 수 있다.** 모델 카드는 시스템 수준 분류기를 적용한다고 밝혔다. 고전압·화학 물질·배터리 같은 위험 주제의 정당한 설계 질문이 거부될 수 있으므로 거부 시 우회하지 말고 사람의 검토 경로를 둔다. 반대로 분류기가 통과시켰다는 사실이 설계 안전을 뜻하지는 않는다. [부분/추정]
- **미공개 설계 자료를 API로 보내지 않는다(약관 확인 전).** 데이터 처리 서술이 충돌하고 Active Memory의 저장 정책이 공개돼 있지 않다. [미확인, 충돌] 회로도·레이아웃·펌웨어 이미지·부품 공급 정보는 영업비밀이므로 원문 약관을 읽고 승인받은 뒤에만 보낸다. 기억 기능이 켜진 경로에서는 대화 간에 설계 정보가 남을 수 있다.
- **인체·화재 위험 설계는 "안전하다"고 단정하지 않는다.** 고전압·대전류·배터리·모터는 사람의 검토를 요청한다.
