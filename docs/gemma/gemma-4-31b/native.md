## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 밀집 약 31B, 느림(약 3.4 토큰/초), 일반 코딩 후기는 호평과 혹평이 갈림, Rust 사례 1건, C++ 평가 없음.

**개발 보조로 쓸 때**
- **Rust 소규모 과제에서 쓸 만했다는 사례가 하나 있다.** 한 개발자의 시험에서 31B는 타입 힌트 일부가 빠졌지만 오류 처리가 견실하고 죽은 코드를 남기지 않았으며, 도구 호출 세 번 만에 테스트가 처음부터 통과했다. 같은 시험에서 26B MoE는 죽은 코드를 남겼고 재시도 때문에 31B보다 30%만 빨랐다. 개인 사례 하나다. [부분: 개인 후기]
- **Rust 컴파일 오류가 섞인 사례도 있다.** 한 일본어 후기는 네 언어 중 Rust 결과에만 컴파일 오류가 있었고 한 줄 수정이 필요했다고 했다. 이 후기는 31B가 아니라 더 작은 설정에서의 것이다. [부분] → 어느 쪽이든 컴파일러와 clippy 출력이 판정한다.
- **C++ 평가는 찾지 못했다.** [미확인] 메모리 관리, 동시성, 수명, ABI는 문법이 맞아도 틀리기 쉬운 영역이므로 핵심 변경에는 쓰지 않는다. 핵심 변경은 `claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon` 문서를 따른다.
- **코딩 비교 후기가 갈린다.** 한 사용자는 Qwen 3.5 27B가 훨씬 낫다고 했고, 다른 평가자는 코드 생성이 매우 좋다고 했으며, 8건의 실무 과제 중 7건을 통과했다는 보고도 있다. 모두 비공식이다. [부분: 개인 후기] 우리 코드베이스에서 같은 과제로 실측한 값을 쓴다.
- **전용 파인튜닝 모델은 근거 없이 쓰지 않는다.** "Rust 시스템 프로그래밍 최적화"를 내건 커뮤니티 파인튜닝이 있으나 벤치마크 결과는 찾지 못했다. [미확인] 가중치 출처, 학습 데이터, 라이선스(§1.5)를 확인하기 전에는 쓰지 않는다.
- **sanitizer 빌드와 테스트를 지시문으로 강제한다.** 돌리지 못한 검사는 "미실행"으로 보고하게 한다. 분석 결과로 설정을 바꾸지 않고, 억제 지시문을 넣는 제안을 따르지 않는다. 테스트·경고·sanitizer 설정이 바뀌었는지 `git diff`로 확인한다.
- **입력은 관련 구간만 준다.** 컨텍스트가 256K라도 긴 입력은 메모리(KV 캐시 약 20 GiB, bf16 추정)와 지연을 키운다. 속도가 느려 수정-확인 루프에 불리하므로 한 번에 크게 묻고 한 번에 검증한다. [부분]

**애플리케이션에 내장할 때**
- 로컬 런타임(llama.cpp 등)을 링크하면 런타임과 가중치 라이선스를 각각 확인한다. 가중치는 Apache 2.0이라고 모델 카드가 적었다. [부분] llama.cpp의 지원 상태는 사용할 빌드에서 확인한다(일부 사용자가 2026-06에 메인라인 지원을 기다린다고 썼다).
- **모델 출력은 신뢰하지 않는 입력이다.** 모델이 만든 경로·명령·코드를 그대로 실행하지 않고, 모델 호출은 별도 프로세스와 최소 권한으로 격리한다. 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1).
- 메모리(4비트 약 17.5~20 GB + KV 캐시)와 CPU 폴백 속도를 대상 기기에서 측정한다. 시스템 경로, 레지스트리, 드라이버, 부트 설정, 서명 키는 승인 없이 건드리지 않는다.
