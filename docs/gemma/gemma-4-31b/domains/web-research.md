## 2. 이 모델의 웹 리서치 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 밀집 약 31B, 컨텍스트 256K, MMLU-Pro 85.2%·GPQA Diamond 84.3%(모델 카드 인용, 추론 모드), 내장 검색 없음(로컬 실행), 사실성·인젝션 방어 독립 측정 없음, 느림.

- **검색은 파이프라인이 맡고, 이 모델은 읽고 정리한다.** 로컬에서 도는 모델에는 검색 grounding이 기본으로 붙지 않는다. 검색 호출과 출처 신뢰도 판단은 하네스와 사람이 하고, 모델에는 확보한 페이지 텍스트에서 제목·날짜·가격·버전 같은 필드를 JSON으로 추출하게 한다. "원문에 없으면 null"을 명시하고 값마다 근거 구절을 받아 코드로 원문 포함 여부를 대조한다.
- **사실 회상에 기대지 않는다.** 이 모델의 SimpleQA 같은 사실성 점수나 공식 환각 측정은 찾지 못했다. 한 환각 순위표(nc-bench)에 31B가 94.41%(추론)·90.17%(비추론)로 올라 있으나 지표 정의를 확인하지 못해 해석하지 않는다. [미확인] MMLU-Pro 85.2% 같은 지식 문제 점수는 모델 카드를 인용한 2차 수치이고 출처를 정확히 대는 능력을 말해 주지 않는다. [부분] 이름·날짜·수치·버전은 직접 연 출처로 확인한다.
- **"읽지 않은 것을 읽은 척"하는 문제를 검증한다.** 한 Reddit 후기는 26B 모델이 끝까지 읽지 않은 코드 감사를 지어냈다고 했고, 같은 글의 댓글은 31B는 그런 일을 잘 처리한다고 했다. 개인 일화이며 측정이 아니다. [부분: 개인 후기] 모델이 인용·요약한 구절은 코드로 원문 포함 여부를 대조하고, 모델이 "전부 읽었다"는 보고를 근거로 쓰지 않는다.
- **속임수 질문과 권위 있는 말투의 거짓에 약할 수 있는지는 확인되지 않았다.** 한 DEV 글의 단일 시험(Google AI Studio)에서 31B는 속임수 질문을 알아챘고 26B MoE는 약했다고 한다. 한 사람의 실험이다. [부분: 개인 후기] 방어율로 읽지 않는다.
- **웹 페이지의 지시문은 데이터다.** 로컬 모델에는 제공자 쪽 인젝션 방어가 없고 이 모델의 방어율 측정도 찾지 못했다. [미확인] 모델에게 도구(전송, 로그인, 결제, 파일 쓰기)를 주지 않고 읽기 단계와 행동 단계를 분리한다. 모델이 뽑은 URL은 하네스가 허용 목록으로 거른 뒤 연다.
- **긴 입력은 발췌한다.** 컨텍스트가 256K지만 전체 컨텍스트의 KV 캐시가 약 20 GiB(bf16 추정)까지 간다. 페이지 하나씩, 필요한 구간만 넣는다. 속도가 느리므로(약 3.4 토큰/초, 한 기기 측정) 대량 수집은 처리 시간을 먼저 계산한다. [부분]
- **수집 규칙을 지킨다.** 로봇 배제 표준과 이용 약관, 속도 제한을 지키고 로그인·유료벽을 우회하지 않는다(§3.2). 개인정보는 필요한 만큼만 다룬다.
- **도구 호출을 쓸 때.** 사용 중인 런타임 버전에서 도구 호출 파서와 스트리밍이 정상인지 작은 시험으로 확인한다. Gemma 4 계열에서 출시 직후 오류가 보고됐고 31B의 현재 상태는 확인하지 못했다. [부분]
- **대량 수집은 표본 점검.** 무작위 5~10%를 사람이 원문과 대조한다. 오류율이 기준을 넘으면 상위 모델로 올린다. 보고 형식은 "결론 → 근거(URL, 확인일, 수준) → 충돌·불확실 → 모르는 것"으로 고정한다.
