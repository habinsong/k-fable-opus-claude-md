## 2. 이 모델의 펌웨어 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 밀집 약 31B, 4비트 약 17.5~20 GB + KV 캐시, 느림, 일반 코딩 후기는 갈림, 임베디드 평가 없음, 제공자 안전장치 없음.

- **기기 안에서 돌릴 모델이 아니다.** 4비트 가중치만 약 17.5~20 GB라 MCU는 물론 일반적인 임베디드 리눅스 SBC에도 맞지 않는다. 개발 워크스테이션 쪽 도구로만 쓴다. 기기 내 추론이 필요하면 E2B·E4B나 더 작은 전용 모델을 검토한다(`gemma-4-e2b`, `gemma-4-e4b` 문서). [부분]
- **펌웨어 코드를 직접 쓰거나 고치게 하지 않는다.** 레지스터 값, 인터럽트, 부트·업데이트 경로, 서명 검증은 환각이 장치 고장이나 보안 구멍이 된다. 이 모델의 임베디드·C/C++ 평가는 찾지 못했다. [미확인] Rust 소규모 과제에서 쓸 만했다는 사례가 하나 있으나 개인 사례이고 하드웨어를 건드리지 않는 과제였다. [부분: 개인 후기] 이 영역은 `gemini-4-argon`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol` 문서를 따른다.
- **써도 되는 작업.** UART·RTT 로그 분류, 맵 파일 요약, 컴파일러 경고 그룹화, 변경 이력 요약, 호스트에서 돌리는 테스트 코드(하드웨어 추상화 뒤쪽 로직)의 초안. 입력은 관련 구간만 준다. 출력은 원본 로그·맵 파일과 한 건씩 대조한다. 로컬 실행이라 미공개 펌웨어 로그와 소스를 외부로 보내지 않는다.
- **레지스터·타이밍을 모델의 기억에서 가져오지 않는다.** 데이터시트·레퍼런스 매뉴얼의 개정판과 페이지를 사람이 확보한 텍스트로 주고, 확인하지 못했으면 값을 쓰지 않는다(§3.1). 추론 모드(thinking)로 낸 설명이 그럴듯해도 근거가 되지 않는다.
- **장치 쓰기는 모델이 실행하지 않는다.** 플래시 소거, 퓨즈·OTP, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금은 사람이 대상 장치와 이미지를 확인한 뒤 실행한다. 로컬 모델에는 제공자 쪽 안전장치가 없으므로 이 정지점은 더 중요하다. 도구 호출 하네스에서 프로그래머·시리얼 제어 도구를 모델에 열어 줄 때는 읽기 전용 도구부터 연결한다.
- **속도를 감안해 한 번에 크게 묻고 한 번에 검증한다.** 약 3.4 토큰/초(한 기기 측정)라 빌드-플래시-확인 루프를 모델이 직접 돌리면 지연이 크다. [부분]
- **변경 후 검증을 강제한다.** 호스트 단위 테스트와 정적 분석을 돌리게 하고, 경고를 억제하라는 제안은 따르지 않는다. 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.
