## 2. 이 모델의 기술 조사 운용, 그리고 이 모델을 평가할 때
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 밀집 약 31B, 4비트 약 17.5~20 GB + KV 캐시, Apache 2.0 가중치, 독립 평가 점수 척도 충돌, 집계 벤치마크 불일치, 경쟁 모델(Qwen3.6 27B)과 후기가 갈림, 느림.

**이 모델에게 기술 조사를 시킬 때**
- 분류·정리 단계에만 쓴다. 후보를 정해진 기준(라이선스 유형, 지원 언어, 릴리스 날짜)으로 분류해 표로 만들 때, 값은 사람이 확보한 1차 자료 텍스트에서 추출하게 하고 원문에 없으면 null로 둔다.
- 라이선스 호환성, 특허, 규정 적용 여부, 도입 권고는 단정시키지 않는다(§3.2, §3.5). 사람이나 상위 모델이 근거를 보고 판단한다.
- 입력은 후보 하나씩 발췌해서 준다. 속도가 느려(약 3.4 토큰/초, 한 기기 측정) 후보가 많으면 처리 시간을 먼저 계산한다. [부분]

**Gemma 4 31B를 도입 후보로 평가할 때**
- **용도 적합성.** 48 GB급 메모리 또는 24 GB GPU에서 짧은 컨텍스트로 쓰는 로컬 코딩 보조·요약·분류·추출, 어려운 단발 추론, 데이터를 외부로 보낼 수 없는 환경의 후보다. 지연이 중요한 서비스에는 맞지 않는다. [부분]
- **가성비를 따져 본다.** 같은 계열의 26B A4B는 활성 약 3.8B로 훨씬 빠르고(약 12.5 대 3.4 토큰/초) 4비트 메모리도 약 14.4 GB로 작다. 31B가 어려운 수학·다단계 추론에서 낫다는 설명이 있으나 그 차이가 내 과제에서 속도 손실을 정당화하는지는 실측으로 정한다. [부분]
- **경쟁 모델과 같은 과제로 비교한다.** 같은 급인 Qwen3.6 27B와는 후기가 엇갈린다. 에이전트·도구 호출에서는 Qwen이 낫다는 후기가 많았고, 일부 코드 생성 과제에서는 31B가 앞섰다는 후기도 있다. Qwen은 긴 추론 때문에 같은 벤치에서 두 배 넘는 토큰을 낸다는 보고가 있어 속도·비용 비교는 출력 토큰 수까지 포함한다. 모두 개인 후기다. 두 모델을 같은 하드웨어, 같은 양자화 수준, 같은 과제, 같은 샘플링으로 실측한다(`qwen/qwen3.6-27b` 문서). [부분]
- **벤치마크 수치를 선택 근거로 쓰지 않는다.** 집계 사이트의 SWE-bench Verified 값이 18~68%로 흩어져 있어 어느 값도 신뢰하지 못한다. 독립 평가 점수도 버전에 따라 순서가 뒤바뀐다(31B 39 대 26B A4B 31 → 15 대 17). 벤치마크 버전을 확인하지 않은 비교와 출처를 알 수 없는 점수는 쓰지 않는다. [부분, 충돌]
- **라이선스.** Apache 2.0이라고 모델 카드가 적었다. 호스팅 플랫폼을 거치면 그쪽 약관이 붙는다는 지적이 있다. 수령 경로와 재배포 계획에 따라 LICENSE와 약관, 상표·사용 정책을 원문으로 확인한다(§3.2). 번들이나 파인튜닝 시 고지·NOTICE 의무와 학습 데이터 출처 정책도 점검한다. 커뮤니티 파인튜닝 가중치는 원 모델 라이선스와 별개로 출처·라이선스를 확인한다. [부분]
- **총소유비용.** API 비용이 없는 대신 GPU·전력·운영·평가 비용이 든다. 전체 컨텍스트의 KV 캐시가 약 20 GiB(bf16 추정)라 컨텍스트 길이에 따라 필요한 메모리가 크게 달라진다. 동시 사용자 수와 처리량을 대상 하드웨어에서 실측한다. [부분]
- **런타임 성숙도.** 출시 직후 도구 호출·스트리밍·토크나이저 오류가 Gemma 4 계열에서 보고됐고, 2026-06 시점 한 사용자는 llama.cpp 메인라인 지원을 기다린다고 썼다. 31B의 현재 상태는 확인하지 못했으므로 채택할 런타임 버전에서 작은 시험을 한다. [부분/미확인]
- **제공자 안전장치 부재.** 입력 필터, 출력 검증, 권한 제한을 직접 구축한다. 규제 적합성은 모델이 아니라 시스템 전체에 대해 판단하며 모델 카드나 가중치 라이선스를 규정 준수의 근거로 쓰지 않는다.
