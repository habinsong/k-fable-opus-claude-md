## 2. 이 모델의 하드웨어 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 밀집 약 31B, GPQA Diamond 84.3%·MMLU-Pro 85.2%(추론 모드, 도구 없음, 2차 출처가 모델 카드를 인용한 값), 하드웨어 설계 평가 없음, 로컬 실행으로 자료 외부 전송 없음.

- **설계 판단에 쓰지 않는다.** 핀 배치, 정격, 타이밍, 수식은 틀리면 보드가 망가지거나 위험해진다. 이 모델의 회로·PCB·HDL 평가는 찾지 못했다. [미확인] GPQA Diamond 84.3% 같은 과학 문제 점수는 모델 카드를 인용한 2차 출처 수치이고 회로 설계 정확도를 대표하지 않는다. 같은 점수대(Qwen 3.5 27B 85.5%)의 모델이 있다는 점도 이 점수가 변별력이 크지 않음을 보여 준다. [부분] 설계는 `gemini-4-argon`, `claude/opus-5.5`, `gpt-6.1-sol` 같은 상위 모델 문서를 따르고, 그 결과도 데이터시트 원문과 도구 계산으로 확인한다.
- **값 회상은 믿지 않는다.** 부품 번호, 핀 번호, 레지스터 주소, 정격 같은 외운 값은 지어내기 쉽다. 값은 항상 사람이 확보한 데이터시트 텍스트에서만 꺼내게 하고, 값마다 문서명·개정판·페이지를 같이 받아 원문 PDF와 한 건씩 대조한다. 원문에 없으면 null이다(§3.1). 31B가 26B A4B보다 낫다는 일부 후기(코드 감사 보고서를 읽지 않고 지어낸 사례가 26B에서 나왔다는 보고)는 일화일 뿐 측정이 아니다. [부분: 개인 후기]
- **데이터시트는 발췌해서 준다.** 컨텍스트는 256K지만 전체 컨텍스트의 KV 캐시가 약 20 GiB(bf16 추정)까지 간다. 필요한 장과 표만 넣고, 한 번에 한 부품·한 질문만 시킨다. PDF 표를 텍스트로 변환할 때 열이 어긋나기 쉬우므로 변환 결과를 원문과 대조한다. [부분]
- **써도 되는 작업.** BOM 정규화, 부품 번호 목록 변환, 시험 로그 분류, 데이터시트 텍스트에서 정해진 필드 추출, 측정·변환 스크립트(파이썬)의 초안. 스크립트는 알려진 값을 넣어 실행해 확인한다. 속도가 느리므로(약 3.4 토큰/초, 한 기기 측정) 대량 처리는 배치와 시간 예산을 잡는다. [부분]
- **계산은 도구로 한다.** 전류 예산, 분압, 필터, 열 계산은 스크립트·시뮬레이터 출력으로 확인하고 식과 가정을 남긴다. 모델이 쓴 암산 결과를 그대로 신뢰하지 않는다. 추론 모드로 낸 풀이도 마찬가지다.
- **이미지(회로도 사진·PCB 사진) 판독은 근거로 쓰지 않는다.** 이미지 입력은 지원하지만 회로도 판독 정확도 평가를 찾지 못했다. [미확인] 넷리스트·ERC 보고서와 대조한다.
- **로컬 실행의 이점과 책임.** 미공개 설계 자료를 외부로 보내지 않고 정리할 수 있다. 정확도를 보증하지는 않는다. 제공자 쪽 안전장치가 없으므로 모델이 만든 스크립트는 격리된 환경에서 실행하고, 측정 장비·전원·프로그래머를 제어하는 스크립트는 사람이 읽고 승인하기 전에 실제 장비에 연결하지 않는다.
- **인체·화재 위험 설계는 "안전하다"고 단정하지 않는다.** 고전압·대전류·배터리·모터는 사람의 검토를 요청한다.
