## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 4비트 약 2.9 GB, 코딩 평가 없음, 런타임별 도구 호출 버그 이력, 제공자 안전장치 없음.

**데스크톱·CLI 프로그램에 내장할 때**
- llama.cpp 같은 C/C++ 런타임을 앱에 링크하면 런타임과 모델 가중치의 라이선스를 각각 확인한다. 가중치는 Apache 2.0이라고 모델 카드가 적었다. [부분] 런타임 라이선스와 배포 형태(링크, 번들)에 따른 의무는 별도다.
- **하드닝을 유지한다.** 모델 출력은 신뢰하지 않는 입력이다. 모델이 만든 경로·명령·코드를 그대로 실행하지 않고, 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1). 모델 호출은 별도 프로세스와 최소 권한으로 격리한다.
- **메모리와 CPU 폴백.** 가중치 4비트 약 2.9 GB에 KV 캐시가 붙는다. GPU가 없을 때의 속도, 메모리 부족 시의 동작을 설계한다. 기기별로 측정한다. [부분]
- **스트리밍과 도구 호출은 런타임 버전마다 다르다.** 출시 직후 Ollama와 llama.cpp에서 도구 호출 파서·스트리밍 오류가 보고됐다. [부분] 사용하는 런타임 버전에서 작은 시험으로 확인한다.

**개발 보조로 쓸 때**
- 시스템 코드의 구현·수정에는 쓰지 않는다. 메모리 관리, 동시성, ABI는 문법이 맞아도 틀리기 쉽고 E2B의 코딩 평가는 찾지 못했다. [미확인] 컴파일러 오류 분류, 빌드·크래시 로그 그룹화, 이름 바꾸기 같은 기계적 변환에만 쓰고 도구 출력과 대조한다.
- 분석 결과로 설정을 바꾸지 않는다("이 경고는 무시해도 된다"는 말로 억제 지시문을 넣지 않는다). 테스트·경고·sanitizer 설정이 바뀌었는지 `git diff`로 확인한다.
- 시스템 경로, 레지스트리, 드라이버, 부트 설정, 서명 키는 승인 없이 건드리지 않는다.
