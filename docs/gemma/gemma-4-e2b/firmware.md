## 2. 이 모델의 펌웨어 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 4비트 가중치 약 2.9 GB, 임베디드 평가 없음, 제공자 안전장치 없음.

- **이 모델은 MCU 펌웨어에 올릴 수 있는 크기가 아니다.** 4비트 가중치만 약 2.9 GB(Google 표)이고 KV 캐시가 더해진다. 일반적인 MCU의 RAM·플래시를 크게 넘는다. 임베디드 리눅스급 SBC나 모바일 SoC 같은 기기에서의 온디바이스 추론은 기기별로 메모리·속도·발열을 측정해야 한다. [부분/미확인]
- **개발 보조로도 펌웨어 코드를 쓰거나 고치게 하지 않는다.** 레지스터 값, 인터럽트, 부트·업데이트 경로, 서명 검증은 환각이 장치 고장이나 보안 구멍이 된다. E2B의 임베디드 평가는 찾지 못했다. [미확인] 이 영역은 `gemini-4-argon`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol` 문서를 따른다.
- **써도 되는 좁은 일.** UART·RTT 로그의 형식별 분류, 맵 파일에서 심볼 크기 표 만들기, 컴파일러 경고 그룹화, 변경 이력 요약. 출력은 원본 로그·맵 파일과 한 건씩 대조할 수 있어야 한다. 로컬 실행이라 미공개 펌웨어 로그를 외부로 보내지 않아도 된다.
- **레지스터·타이밍을 모델의 기억에서 가져오지 않는다.** 데이터시트·레퍼런스 매뉴얼의 개정판과 페이지를 확인하고, 못 했으면 값을 쓰지 않는다(§3.1).
- **장치 쓰기는 모델이 실행하지 않는다.** 플래시 소거, 퓨즈·OTP, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금은 사람이 대상 장치와 이미지를 확인한 뒤 실행한다. 로컬 모델에는 제공자 쪽 안전장치가 없으므로 이 정지점은 더 중요하다.
- **정적 분석 경고를 억제하는 제안을 따르지 않는다.** 경고는 억제하지 않고 원인을 고친다(§3.1).
- **변경 후 검증을 강제한다.** 호스트 단위 테스트·정적 분석을 돌리게 하고, 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.

## 4. 근거와 한계
- 메모리 크기: [Gemma 4 model card](https://ai.google.dev/gemma/docs/core/model_card_4) (스니펫만) [부분]
- 한계: 임베디드에 대한 E2B 평가는 없다. 사용 범위 제한은 모델 크기와 비가역 작업의 위험에서 도출한 안전 권고다.
