## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 4비트 약 4.5 GB, 출력 속도 약 15.7 토큰/초(DGX Spark 한 측정), 코딩 평가 없음, 런타임별 도구 호출 버그 이력.

**데스크톱·CLI 프로그램에 내장할 때**
- 로컬 런타임(llama.cpp 등)을 링크하면 런타임과 가중치 라이선스를 각각 확인한다. 가중치는 Apache 2.0이라고 모델 카드가 적었다. 런타임 라이선스와 배포 형태에 따른 의무는 별도다. [부분]
- **모델 출력은 신뢰하지 않는 입력이다.** 모델이 만든 경로·명령·코드를 그대로 실행하지 않고, 모델 호출은 별도 프로세스와 최소 권한으로 격리한다. 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1).
- **GPU가 없을 때의 속도와 메모리를 측정한다.** 가중치 4비트 약 4.5 GB에 KV 캐시가 붙는다. 출력 속도는 기기마다 크게 다르다. [부분]
- **스트리밍과 도구 호출은 런타임 버전마다 다르다.** 출시 직후 Ollama·llama.cpp의 도구 호출·스트리밍 버그가 보고됐다. 사용할 버전에서 작은 시험으로 확인한다. [부분]

**개발 보조로 쓸 때**
- 시스템 코드의 구현·수정에는 쓰지 않는다. E4B의 코딩 평가를 찾지 못했고 [미확인], 메모리 관리·동시성·ABI는 문법이 맞아도 틀리기 쉽다. 컴파일러 오류 분류, 빌드·크래시 로그 그룹화, 이름 바꾸기 같은 기계적 변환, 짧은 코드 조각에만 쓰고 도구 출력과 대조한다.
- 분석 결과로 설정을 바꾸지 않는다("이 경고는 무시해도 된다"는 말로 억제 지시문을 넣지 않는다). 테스트·경고·sanitizer 설정이 바뀌었는지 `git diff`로 확인한다.
- 시스템 경로, 레지스트리, 드라이버, 부트 설정, 서명 키는 승인 없이 건드리지 않는다.
