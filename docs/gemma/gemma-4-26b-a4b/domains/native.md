## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 단발 코딩은 강하고 에이전트 코딩에서 약하다는 평가, 큰 입력·큰 출력에서 성능 급락, 런타임·템플릿 버전에 따라 도구 호출 품질이 갈림.

**개발 보조로 쓸 때**
- **단발 질문과 함수 단위 작업에 쓴다.** 컴파일러 오류 설명, 짧은 함수의 초안, 단위 테스트 초안, 빌드·크래시 로그 그룹화, 이름 바꾸기 같은 기계적 변환. 한 커뮤니티 평가에서 단발 코딩은 강했고 에이전트 코딩은 고전했다. [부분] 결과는 컴파일러·sanitizer·테스트 출력과 대조한다.
- **시스템 코드의 핵심 변경에는 쓰지 않는다.** 메모리 관리, 동시성, ABI는 문법이 맞아도 틀리기 쉽고 이 모델의 시스템 코드 평가는 찾지 못했다. [미확인] 핵심 변경은 `claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon` 문서를 따른다.
- **입력을 작게 준다.** 큰 입력과 큰 출력이 필요한 작업에서 성능이 급락한다는 평가가 있다. [부분] 관련 함수와 호출부, 오류 메시지만 주고, 파일 전체나 긴 빌드 로그를 통째로 넣지 않는다. 출력은 파일로 한 번 저장한 뒤 실패한 구간만 읽는다.
- **sanitizer 빌드와 테스트를 지시문으로 강제한다.** 돌리지 못한 검사는 "미실행"으로 보고하게 한다. 분석 결과로 설정을 바꾸지 않는다("이 경고는 무시해도 된다"는 말로 억제 지시문을 넣지 않는다). 테스트·경고·sanitizer 설정이 바뀌었는지 `git diff`로 확인한다.
- 공개 헤더·ABI 변경은 호출자 영향부터 확인하고 범위 밖 변경은 되돌린다.

**애플리케이션에 내장할 때**
- 로컬 런타임(llama.cpp 등)을 링크하면 런타임과 가중치 라이선스를 각각 확인한다. 가중치는 Apache 2.0이라고 모델 카드가 적었다. [부분]
- **모델 출력은 신뢰하지 않는 입력이다.** 모델이 만든 경로·명령·코드를 그대로 실행하지 않고, 모델 호출은 별도 프로세스와 최소 권한으로 격리한다. 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1).
- 메모리(4비트 약 14.4 GB, 26B 전체 상주)와 CPU 폴백 속도를 대상 기기에서 측정한다. 스트리밍과 도구 호출은 런타임 버전마다 다르니 작은 시험으로 확인한다. [부분]
- 시스템 경로, 레지스트리, 드라이버, 부트 설정, 서명 키는 승인 없이 건드리지 않는다.
