## 2. 이 모델의 웹 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 약 11.95B, 256K 컨텍스트, 소비자 GPU 한 장 후보, 후속 추가 모델이라 독립 평가가 얕음, 에이전트 구성은 약하다는 평가가 큰 형제 모델에 있음.

- **웹 작업의 보조 모델로 쓴다.** 모델 카드 기준 LiveCodeBench v6 72.0%는 Google 보고 수치이고 [부분], 웹 UI·프런트엔드에 대한 독립 평가는 찾지 못했다. [미확인] 컴포넌트 단위의 작은 수정, 스타일 변환, 마크업 정리, 테스트 코드 초안에 쓰고 결과를 린터·타입체크·테스트로 검증한다.
- **복잡한 로직은 올린다.** 라우팅, 상태 관리, 동시성, 인증 흐름은 `gemini-4-argon`, `claude/sonnet-5.5`, `gpt-6.1-sol` 같은 상위 모델 문서를 따른다. 같은 오류에서 두 번 막히면 같은 재현 절차를 상위 모델에 넘긴다.
- **보안·접근성 판단을 맡기지 않는다.** 인가, 입력 검증, 비밀 노출, 접근성 "충족" 여부는 도구 출력과 §3.1 기준으로 사람이 점검한다.
- **사실은 직접 확인한다.** API·CSS·브라우저 지원은 공식 문서와 린터·컴파일러 출력으로 확인한다.
- **에이전트 구성은 단순하게.** 큰 형제 모델(26B A4B)도 에이전트 코딩에서 약하다는 평가가 있어 [부분] 한 번에 한 가지를 시키고 단계마다 검증한다. 도구 호출 하네스는 사용 중인 런타임 버전에서 작은 시험으로 확인한다.
- **로컬 실행의 이점.** 미공개 소스를 외부로 보내지 않고 쓸 수 있다. 이 이점은 데이터 보호에 한하고 정확도를 보증하지 않는다. 제공자 쪽 안전장치가 없으니 모델이 만든 코드를 격리된 환경에서 실행한다.
- **지침은 짧게.** §0과 §1.2·§1.3·§1.6의 핵심을 발췌하고 웹 규칙은 해당 작업에만 붙인다. 준수율을 측정한다. [권고]
