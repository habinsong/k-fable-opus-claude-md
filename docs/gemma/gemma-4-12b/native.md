## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 약 11.95B, LiveCodeBench v6 72.0%(벤더 수치), 에이전트 구성은 약하다는 평가가 큰 형제 모델에 있음, 제공자 안전장치 없음.

**개발 보조로 쓸 때**
- **시스템 코드의 핵심 변경에는 쓰지 않는다.** 메모리 관리, 동시성, ABI는 문법이 맞아도 틀리기 쉽다. 12B의 시스템 코드 평가는 찾지 못했다. [미확인] 컴파일러 오류 분류, 빌드·크래시 로그 그룹화, 이름 바꾸기, 짧은 함수의 초안, 단위 테스트 초안에 쓰고 도구 출력과 대조한다. 핵심 변경은 `claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon` 문서를 따른다.
- **sanitizer 빌드와 테스트를 지시문으로 강제한다.** 소형 모델은 자기 검증이 약할 수 있으므로 [추정] 변경 후 sanitizer 빌드와 해당 테스트를 돌리게 하고 못 돌린 검사는 "미실행"으로 보고하게 한다.
- 분석 결과로 설정을 바꾸지 않는다("이 경고는 무시해도 된다"는 말로 억제 지시문을 넣지 않는다). 테스트·경고·sanitizer 설정이 바뀌었는지 `git diff`로 확인한다.
- 공개 헤더·ABI 변경은 호출자 영향부터 확인하고, 범위 밖 변경은 되돌린다.

**애플리케이션에 내장할 때**
- 로컬 런타임(llama.cpp 등)을 링크하면 런타임과 가중치 라이선스를 각각 확인한다. 가중치는 Apache 2.0이라고 모델 카드가 적었다. [부분]
- **모델 출력은 신뢰하지 않는 입력이다.** 모델이 만든 경로·명령·코드를 그대로 실행하지 않고, 모델 호출은 별도 프로세스와 최소 권한으로 격리한다. 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1).
- 메모리(4비트 약 6~8 GB, 2차 추정)와 CPU 폴백 속도를 대상 기기에서 측정한다. 스트리밍과 도구 호출은 런타임 버전마다 다르니 작은 시험으로 확인한다. [부분/추정]
- 시스템 경로, 레지스트리, 드라이버, 부트 설정, 서명 키는 승인 없이 건드리지 않는다.
