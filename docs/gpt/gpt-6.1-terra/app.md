## 2. 이 모델의 앱 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 컴퓨터 사용·시각 추론용 중간 티어, 코딩은 Sol보다 낮음, 컴퓨터 사용 수치는 소규모 세트 기준.

- **시뮬레이터·에뮬레이터 화면 조작과 검수에 후보로 쓴다.** OpenAI는 Terra를 컴퓨터 사용에 맞춘 모델로 안내한다. [부분] 그러나 OpenAI의 OSWorld 2.1 오프라인 74.2%는 82개 작업의 소규모 하위 집합 기준이고, 검증된 최고 점수는 Claude Opus 5.5의 87.2%로 보고된다. 측정 프로토콜도 서로 다르다. [부분]
  → 앱의 핵심 화면 흐름 몇 개로 자체 비교(Terra, Sol, 다른 제공자)를 해 본 뒤에 고른다. 조작 결과는 모델의 말이 아니라 스크린샷·로그·테스트 출력으로 확인한다.
- **화면 캡처 비교 같은 반복 검수는 비용 이점이 있다.** 입력 $1 / 출력 $5로 Sol의 절반이다. [부분] 다만 Sol이 성공률이 높아 재시도가 줄면 총비용이 더 낮을 수 있다는 반론이 있어, 비용은 "성공한 작업당"으로 비교한다.
- **네이티브 코드·플랫폼 API 구현은 Sol로 올린다.** 코딩 평가에서 Sol보다 낮다. [부분] Swift·Kotlin 코드에서 존재하지 않는 API를 쓰는 환각은 컴파일 단계에서 걸러지므로, 컴파일 출력을 먼저 확인한다. 환각률이 38%로 측정됐다. [부분]
- **스토어 규정과 플랫폼 요건은 모델에게 묻지 않는다.** §3.2 표를 작업 시점에 공식 문서로 다시 확인한다.
- **`max` effort를 쓰지 않는다.** 한 테스트에서 `medium`보다 낮았다. [부분]
- **서명 키, 프로파일, 스토어 제출·배포는 승인 후에만.**

## 4. 근거와 한계
- 컴퓨터 사용 수치: [BenchLM](https://benchlm.ai/models/gpt-6-1-terra), [GPT-6.1 Terra for Browser Agents](https://www.orcarouter.ai/blog/gpt-6-1-terra-browser-agent) [부분: 벤더 수치와 집계 혼합]

- 한계: 모바일 앱 개발에 대한 Terra 전용 평가가 없다. 컴퓨터 사용 우위는 OpenAI의 포지셔닝일 뿐 독립 확인되지 않았다.
