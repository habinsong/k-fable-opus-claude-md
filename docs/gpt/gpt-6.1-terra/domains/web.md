## 2. 이 모델의 웹 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 시각 추론에 맞춘 중간 티어, 코딩은 Sol보다 낮음, `max`가 `medium`보다 나쁜 사례, 환각률 38%.

- **화면을 보고 판단하는 일에 쓴다.** 스크린샷을 읽어 레이아웃 어긋남, 텍스트 잘림, 상태 누락을 찾는 일은 Terra가 맞춰진 영역이다. [부분] 다만 UI 생성 품질에 대한 Terra 전용 평가는 찾지 못했다. [미확인]
- **복잡한 로직은 Sol로 올린다.** 라우팅, 상태 관리, 동시성, 인증 흐름처럼 코딩 난도가 높은 부분은 OpenAI도 Sol이나 Astra를 권한다. [부분] 같은 오류에서 두 번 막히면 같은 재현 절차를 Sol에 넘긴다.
- **effort는 `medium`에서 시작하고 `max`를 쓰지 않는다.** 한 저장소 테스트에서 `max`(36.0%)가 `medium`(43.7%)보다 낮았다. [부분] 올리기 전에 같은 과제로 비교한다.
- **API·CSS·브라우저 동작을 기억에 맡기지 않는다.** 독립 테스트의 환각률이 38%다. [부분] 속성 이름, 브라우저 지원 여부, 라이브러리 API는 공식 문서나 컴파일러·린터 출력으로 확인한다. 존재하지 않는 API를 만들어내면 빌드 단계에서 걸러진다.
- **접근성·성능·보안은 도구 출력으로 확인한다.** 모델의 "충족했다"는 판단은 증거가 아니다. 서버 인가, 입력 검증, 비밀 노출은 §3.1 기준으로 따로 점검한다.
- **화면 확인.** 렌더링 결과는 직접 열어 대조하고, 확인하지 못했으면 "화면 미확인"이라고 보고한다.
- **작성 작업.** UI 문구를 쓸 때 "기존 문구와 톤을 맞추고 근거 없는 기능 설명을 덧붙이지 않는다"를 명시한다.
