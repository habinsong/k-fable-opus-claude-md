## 2. 이 모델의 앱 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 밀집 27B(비전 언어 입력), Apache 2.0, 휴대 기기용이 아님, 로컬 속도는 기기마다 큰 차이, 앱 개발 독립 평가 없음.

**앱에 내장할 때**
- **휴대 기기에 올릴 모델이 아니다.** 밀집 27B는 4비트로도 GPU 메모리를 20 GB대로 쓰는 급이다(후속 `qwen3.8-27b`는 4비트로 24 GB GPU라는 서술, 이 모델의 수치는 확인하지 못함). 모바일 온디바이스는 `gemma-4-e2b`, `gemma-4-e4b` 문서를 본다. 이 크기는 앱의 서버 측 로컬 추론이나 개발자 워크스테이션에 맞는다. [부분/추정]
- **서버 측에 올릴 때 처리량을 먼저 잰다.** 한 보고에서 9070 XT 기준 초당 약 13~15 토큰이었다. 동시 사용자가 늘면 처리량이 급격히 줄고 긴 컨텍스트와 이미지 입력은 메모리를 더 쓴다. 대상 하드웨어에서 동시성·지연·메모리를 실측하고 개인정보가 서버를 거치는 경로를 앱의 개인정보 선언(Apple 개인정보 영양 표시, Google Play 데이터 보안 양식)과 일치시킨다. [부분: 개인 후기]
- **라이선스 고지.** 여러 목록이 Apache 2.0을 적었다(Unsloth GGUF 저장소 태그 포함). 가중치를 번들·배포하면 LICENSE·NOTICE를 지키고 받는 경로의 약관도 확인한다. 공식 저장소의 LICENSE 원문으로 확인한 뒤에 번들한다(§1.5). [부분]
- **제공자 쪽 안전장치가 없다.** 입력 필터, 출력 검증, 위험한 기능(결제, 계정 변경, 외부 전송)의 권한 제한을 앱이 직접 한다. 모델 출력은 신뢰하지 않는 입력으로 취급해 서버에서 검증한 뒤 앱에 전달한다.
- **이미지 입력(사진)을 쓰면 서버에 개인정보가 쌓인다.** 자체 호스팅이라 제3자 학습 사용 위험은 없으나 보관·삭제 정책과 동의를 설계한다. [추정]
- **모델 교체를 앱 업데이트 없이 할 수 있게 설계한다.** 후속 `qwen3.8-27b`가 나왔다. 서버 쪽 모델 설정, 폴백 모델, 회귀 시험, 기능 플래그를 둔다. 공식 저장소에서만 가중치를 받고 커밋 해시를 고정한다.

**개발 보조로 쓸 때**
- **모바일(Kotlin·Swift) 코드에 대한 독립 평가는 찾지 못했다.** [미확인] 컴파일·린트·단위 테스트·UI 테스트로 검증하고, 수명주기·권한·비동기 처리가 걸린 구현은 상위 모델 문서(`claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon`)와 같은 과제로 비교한다.
- 스토어 규정은 기억으로 답하지 않고 공식 문서로 확인한다(§3.2). 서명 키, 프로파일, 스토어 제출·배포는 승인 후에만 한다.
