## 2. 이 모델의 기술 조사 운용, 그리고 이 모델을 평가할 때
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 밀집 27B(비전 언어 입력), Apache 2.0(여러 목록), 로컬 코딩·에이전트 기준선으로 거론, 개인 후기 중심, 독립 지수 부재, 후속 `qwen3.8-27b`와 경쟁 `gemma-4-31b` 존재.

**이 모델에게 기술 조사를 시킬 때**
- 분류·정리 단계에만 쓴다. 후보를 정해진 기준(라이선스 유형, 지원 언어, 릴리스 날짜)으로 분류해 표로 만들 때, 값은 사람이 확보한 1차 자료 텍스트에서 추출하게 하고 원문에 없으면 null로 둔다.
- 라이선스 호환성, 특허, 규정 적용 여부, 도입 권고는 단정시키지 않는다(§3.2, §3.5). 후보를 지나치게 높게 평가하는 경향(아첨)은 측정된 바 없으므로 사람이나 상위 모델이 근거를 보고 판단한다.

**Qwen3.6-27B를 도입 후보로 평가할 때**
- **기준선으로서의 가치와 후속 모델을 구분한다.** 이 모델은 로컬 코딩 모델의 기준선으로 거론되고 후기가 많다는 점이 강점이다. 그러나 후속 `qwen3.8-27b`(8월)가 나왔고 그쪽은 독립 후기가 아직 얕다. 새 도입이면 두 모델과 `gemma-4-31b`를 같은 기기·양자화·과제·샘플링으로 비교한다. 후기가 풍부하다는 이유로 최신 모델보다 낫다고 결론내리지 않는다. [부분: 개인 후기]
- **라이선스.** 여러 목록이 Apache 2.0을 적었다(Unsloth GGUF 저장소 태그 포함). 공식 저장소의 LICENSE 원문으로 확인하고 SPDX 식별자와 NOTICE 의무를 기록한다(§3.2). 학습 데이터 출처와 저작권 이슈는 확인하지 못했다. 양자화 변환본은 변환자의 저장소 라이선스·출처도 따로 본다. [부분]
- **벤더 수치로 결정하지 않는다.** SWE-bench Verified 최대 77.2(35B-A3B 73.4)는 안내 글이 인용한 벤더 수치이고 하네스 조건과 독립 재현이 확인되지 않았다. 독립 지수는 찾지 못했다. 후보 비교는 같은 과제, 같은 조건의 자체 실측으로 한다. [부분: 벤더 주장]
- **27B 밀집과 35B-A3B MoE의 선택.** 35B-A3B가 약 3배 빠르지만(9070 XT 기준 약 35 대 13~15 토큰/초, RTX 3090에서 101 토큰/초라는 보고) Q4에서 루프를 돈다는 후기가 있어 27B를 선호하는 후기가 있다. 반대로 속도가 중요한 단발 작업에는 MoE가 맞을 수 있다. 양자화 수준이 다른 후기를 직접 비교로 읽지 않고 `qwen3.6-35b-a3b` 문서와 함께 우리 과제로 측정한다. [부분: 개인 후기]
- **총소유비용.** API 비용이 없는 대신 GPU·전력·운영·평가 비용이 든다. 속도(9070 XT 기준 초당 약 13~15 토큰)와 메모리를 대상 하드웨어에서 컨텍스트 길이별로 실측한다. [부분: 개인 후기]
- **런타임 성숙도.** 서빙 파서(`qwen3`, `qwen3_coder`)와 llama.cpp `--jinja` 도구 호출 지원이 안내돼 있고 Unsloth가 도구 호출 중첩 객체 파싱 개선을 언급한다. 열린 버그의 현재 상태는 확인하지 못했으므로 채택할 런타임 버전에서 작은 시험을 한다. [부분]
- **제공자 안전장치 부재.** 입력 필터, 출력 검증, 권한 제한을 직접 구축한다. 규제 적합성은 모델이 아니라 시스템 전체에 대해 판단하며 모델 카드나 가중치 라이선스를 규정 준수의 근거로 쓰지 않는다.
- **공급망.** 공식 조직 저장소에서만 받고 커밋 해시를 고정하며, 제3자 재업로드와 양자화 변환본은 출처를 확인하기 전에는 쓰지 않는다. [추정]
