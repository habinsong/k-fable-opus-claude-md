## 2. 이 모델의 웹 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 밀집 27B(비전 언어 입력), Apache 2.0, 로컬 코딩·에이전트 기준선으로 거론, 개인 후기 중심, 독립 평가 점수 부재, 후속 `qwen3.8-27b` 존재.

- **웹 UI 생성의 독립 평가는 찾지 못했다.** [미확인] 후기는 코딩·도구 호출 일반에 관한 것이다. 컴포넌트 단위 수정, 새 화면, 스크린샷 재현을 우리 코드베이스에서 `qwen3.8-27b`, `gemma-4-31b`와 같은 기기·양자화·과제로 비교하고, 스크린샷 대조와 린터·타입체크·테스트 출력으로 판정한다. 기존 UI 체계가 우선한다(§3.1).
- **로컬 코딩 기준선이라는 평가는 후기에 기대고 있다.** 한 후기는 벤치마크와 여론이 27B 쪽으로 크게 기울었다고 하지만 다른 후기는 Gemma 4 31B가 코드 품질에서 앞섰다고 했다. 둘 다 개인 경험이고 프롬프트·양자화·런타임에 따라 달라진다. 선택 근거로 쓰지 말고 우리 과제로 측정한다. [부분: 개인 후기]
- **스크린샷 입력은 직접 시험한다.** 비전 언어 입력을 네이티브로 지원하나 레이아웃·간격·색 재현 정확도를 측정한 자료는 찾지 못했다. [부분/미확인]
- **도구 호출 하네스를 쓸 때는 파서와 템플릿을 확인한다.** 서빙 예시는 `qwen3` 추론 파서와 `qwen3_coder` 도구 호출 파서를 쓰고 llama.cpp는 `--jinja`로 네이티브 도구 호출을 쓴다. 사용하는 런타임 버전에서 작은 시험으로 확인한다. 도구 호출은 Gemma 4 26B A4B보다 낫다는 후기가 많았으나 이는 다른 크기와의 비교다. [부분: 개인 후기]
- **속도를 설계에 반영한다.** 한 보고에서 9070 XT 기준 초당 약 13~15 토큰이었다. 대화형 UI 수정 루프에서는 지연이 커서 단발 요청 위주로 쓴다. [부분: 개인 후기]
- **로컬 실행의 이점과 책임.** 미공개 소스를 외부로 보내지 않는다. 대신 제공자 쪽 안전장치가 없으므로 모델이 만든 코드는 격리된 환경에서 실행하고 의존성 추가는 라이선스·유지 상태를 확인한 뒤에 한다(§1.5).
- **보안·접근성 판단을 맡기지 않는다.** 인가, 입력 검증, 비밀 노출, 접근성 "충족" 여부는 도구 출력과 §3.1 기준으로 사람이 점검한다. API·CSS·브라우저 지원은 공식 문서와 린터·컴파일러 출력으로 확인한다.
