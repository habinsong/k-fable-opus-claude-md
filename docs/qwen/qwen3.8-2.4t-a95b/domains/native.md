## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 공개 가중치(텍스트 전용), 자체 라이선스(모델 제공자 조항), 전체 가중치 TB 규모, 이 체크포인트의 독립 평가 없음, C/C++·Rust 평가 없음.

**개발 보조로 쓸 때**
- **API Max의 벤더 수치를 이 체크포인트에 옮기지 않는다.** Terminal-Bench 2.1 86.6 등은 클라우드 Max의 Alibaba 내부 실행(외부 에이전트 하네스 기반)이다. 공개 체크포인트는 비전·비추론 모드가 없고 네이티브 컨텍스트도 다르다. 이 체크포인트의 코딩 수치는 찾지 못했다. [미확인]
- **C++·Rust·시스템 코드의 언어별 평가는 찾지 못했다.** [미확인] 메모리 관리, 동시성, 수명, ABI는 문법이 맞아도 틀리기 쉬우므로 핵심 변경에는 쓰지 않고, 쓴다면 sanitizer(ASan·UBSan·TSan)와 테스트를 지시문으로 강제한다. 핵심 변경은 `claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon` 문서를 따르거나 우리 코드로 같은 과제를 비교한다.
- **미공개 소스를 밖으로 내보내지 않으려는 목적이면 자체 호스팅이 선택지지만 비용이 매우 크다.** 4비트에서도 약 1.5 TB급(계산기 추정), 1비트에서도 400 GB 이상이다. 호스트 서비스를 쓰면 코드가 호스트로 나가므로 호스트 약관을 확인한다. [부분, 충돌]
- **추론 모드가 항상 켜져 있다는 서술이 있다.** 짧은 수정에도 긴 추론이 따른다. 지연과 토큰 소비를 과제당으로 측정하고 단순 작업은 `qwen3.8-27b` 같은 작은 모델로 라우팅한다. [부분/추정]
- **에이전트 루프에 안전장치를 먼저 둔다.** 파괴적 명령 차단(권한·훅), 작업 디렉터리 격리, 시간·토큰 한도를 설정하고, 완료 보고는 빌드·테스트·sanitizer 출력과 `git diff`로 확인한다. 테스트·경고·sanitizer 설정이 바뀌었는지도 확인한다. 억제 지시문을 넣거나 검사를 끄는 제안은 따르지 않는다.
- **도구 호출 형식은 서빙 런타임 버전에서 시험한다.** 이 계열의 이전 공개 모델은 `qwen3_coder` 도구 호출 파서와 `qwen3` 추론 파서를 서빙 예시에서 쓴다. 이 체크포인트의 파서 지원은 사용하는 런타임(vLLM, SGLang 등)의 최신 버전에서 작은 시험으로 확인한다. [부분/추정]

**애플리케이션에 내장할 때**
- **모델은 서버에서 호출한다.** 수 TB 규모라 번들할 수 없다. 클라이언트에 API 키를 두지 않고 자체 백엔드를 거친다. 모델 출력으로 만든 경로·명령·코드를 그대로 실행하지 않으며 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1).
- **재배포·서비스 제공 형태는 라이선스 원문을 확인한다.** 모델 제공자 조항(12개월 5,000만 달러 초과 시 상업 라이선스라는 2차 요약)이 소프트웨어 제품에 모델을 포함하는 형태에 적용되는지 법무가 판단한다(README.md가 안내하는 개요·운용 문서.2). 오프라인 요구에는 소형 모델(`qwen3.8-27b`, `gemma-4-e4b`)을 본다. [부분/미확인]
