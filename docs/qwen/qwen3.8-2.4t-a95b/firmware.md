## 2. 이 모델의 펌웨어 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 공개 가중치(텍스트 전용)라 기기 내 실행 불가, 임베디드 평가 없음, 환각 값 미확인, 자체 호스팅이면 펌웨어 소스가 외부로 나가지 않으나 TB 규모 장비 필요.

- **기기 안에서 돌릴 모델이 아니다.** 가중치만 수 TB 규모다. 개발 서버에서 쓰는 보조 도구로만 쓴다. 기기 내 추론이 필요하면 소형 모델 문서(`gemma-4-e2b`, `gemma-4-e4b`)를 본다. [부분]
- **펌웨어 코드를 직접 쓰거나 고치게 하지 않는다.** 레지스터 값, 인터럽트, 부트·업데이트 경로, 서명 검증은 환각이 장치 고장이나 보안 구멍이 된다. 임베디드·펌웨어 평가는 찾지 못했다. [미확인] 클라우드 Max의 터미널 작업 점수(벤더 내부 실행, 외부 하네스 기반)는 이 체크포인트의 값이 아니며 장치 쓰기나 실시간 제약과 무관하다. 이 영역은 `gemini-4-argon`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol` 문서를 따른다.
- **레지스터·타이밍을 모델의 기억에서 가져오지 않는다.** 환각 값을 찾지 못했다. 데이터시트·레퍼런스 매뉴얼의 개정판과 페이지를 사람이 확보한 텍스트로 주고, 확인하지 못했으면 값을 쓰지 않는다(§3.1). [미확인]
- **자체 호스팅의 이점은 펌웨어 소스·서명 키 후보 자료·양산 이미지가 외부 API로 나가지 않는다는 점이다.** 그러나 서명 키와 디버그 인증 정보는 어떤 모델에도 입력하지 않는다(§3.4). 로그 분류, 맵 파일 요약, 컴파일러 경고 그룹화, 호스트 테스트 초안 같은 보조 작업은 `qwen3.8-27b`(24 GB급 GPU에서 4비트 양자화로 가능하다는 서술) 같은 작은 모델로도 가능한지 먼저 시험한다. 이 체크포인트는 4비트에서도 약 1.5 TB급(계산기 추정)이라 보조 작업에 과하다. [부분, 충돌/추정]
- **호스트 서비스를 쓰면 펌웨어 소스·로그가 호스트로 나간다.** 호스트의 학습 사용·보관 조건을 원문으로 읽고 법무·보안 승인을 받은 뒤에만 보낸다. 수출 통제·고객 계약상 국외 이전이 제한된 코드는 확인 전에 보내지 않는다.
- **에이전트에게 장치 접근을 열어 주지 않는다.** 플래시 소거, 퓨즈·OTP, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금은 사람이 대상 장치와 이미지를 확인한 뒤 실행한다. 프로그래머·시리얼 제어 도구는 읽기 전용부터 연결하고 권한·훅으로 쓰기 명령을 차단한다.
- **변경 후 검증을 강제한다.** 호스트 단위 테스트와 정적 분석을 직접 돌려 출력을 읽고, 경고를 억제하라는 제안은 따르지 않는다. 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.
