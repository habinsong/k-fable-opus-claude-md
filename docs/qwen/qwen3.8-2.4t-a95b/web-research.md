## 2. 이 모델의 웹 리서치 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 공개 가중치(텍스트 전용), 내장 검색 없음(자체 호스팅), 이 체크포인트의 독립 평가 없음, 환각·인용·인젝션 방어 값 미확인, 직접 호스팅 비용이 매우 큼.

- **검색은 파이프라인이 맡고, 모델은 읽고 정리한다.** 공개 가중치에는 검색 grounding이 붙지 않는다. 검색 호출과 출처 신뢰도 판단은 하네스와 사람이 맡고, 모델에는 확보한 페이지 텍스트에서 제목·날짜·가격·버전 같은 필드를 JSON으로 추출하게 한다. "원문에 없으면 null"을 명시하고 값마다 근거 구절을 받아 코드로 원문 포함 여부를 대조한다.
- **API Max의 수치를 이 체크포인트에 옮기지 않는다.** 독립 지수(45~58)와 벤더 수치는 클라우드 Max의 것이고, 이 체크포인트는 비전·비추론 모드가 없으며 컨텍스트도 다르다(네이티브 262,144 토큰). 이 체크포인트의 환각·사실성·인용 정확도 값은 찾지 못했다. [미확인]
- **사실 회상에 기대지 않는다.** 이름·날짜·수치·버전은 직접 연 출처로 확인하고, 모델이 출처를 안다고 해도 URL을 직접 열어 대조한다. 인용 구절이 원문에 있는지 문자열로 확인하고 모델의 "전부 읽었다"는 보고를 근거로 쓰지 않는다.
- **웹 페이지의 지시문은 데이터다.** 공개 가중치에는 제공자 쪽 인젝션 방어가 없고 이 체크포인트의 방어율 측정도 찾지 못했다. [미확인] 모델에게 전송·로그인·결제·파일 쓰기 도구를 주지 않고 읽기 단계와 행동 단계를 분리한다. 모델이 뽑은 URL은 하네스가 허용 목록으로 거른 뒤 연다.
- **웹 리서치 보조에는 비용이 과하다.** 4비트에서도 약 1.5 TB급(계산기 추정)이고 추론 모드가 필수라는 서술이 있어 필드 추출 같은 반복 작업에 지연과 토큰이 크다. 같은 작업을 `qwen3.8-27b` 같은 작은 모델로 먼저 시험하고 판단이 필요한 종합만 큰 모델에 맡기는 분업을 검토한다. [부분, 충돌/추정]
- **긴 입력은 발췌한다.** 네이티브 컨텍스트가 262,144 토큰(확장 시 약 100만)이다. 페이지 하나씩 필요한 구간만 넣고 출력 필드를 제한한다. 실효 길이는 우리 자료로 측정한다. [부분]
- **수집 규칙을 지킨다.** 로봇 배제 표준과 이용 약관, 속도 제한을 지키고 로그인·유료벽을 우회하지 않는다(§3.2). 호스트 서비스를 쓰면 수집한 자료가 호스트로 나가므로 호스트의 데이터 조건을 확인한다. 개인정보가 섞인 페이지는 보내지 않는다.
- **대량 수집은 표본 점검.** 무작위 5~10%를 사람이 원문과 대조한다. 오류율이 기준을 넘으면 상위 모델로 올린다. 보고 형식은 "결론 → 근거(URL, 확인일, 수준) → 충돌·불확실 → 모르는 것"으로 고정한다.
