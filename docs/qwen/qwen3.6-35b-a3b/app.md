## 2. 이 모델의 앱 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: MoE(총 35B·활성 약 3B)라 메모리는 35B 전체, 휴대 기기용이 아님, 빠름, Apache 2.0, 앱 개발 독립 평가 없음.

**앱에 내장할 때**
- **휴대 기기에 올릴 모델이 아니다.** 활성 파라미터가 약 3B여도 35B 전체를 메모리에 올려야 한다(4비트 GGUF가 데스크톱 앱 수준에서 돈다는 서술이 있을 뿐 VRAM 수치는 확인하지 못함). 모바일 온디바이스는 `gemma-4-e2b`, `gemma-4-e4b` 문서를 본다. 이 크기는 앱의 서버 측 로컬 추론이나 개발자 워크스테이션에 맞는다. [부분/미확인]
- **서버 측에서는 속도가 강점이다.** 초당 35~101 토큰이라는 보고(기기별)가 있어 같은 하드웨어에서 밀집 27B보다 동시 처리량이 유리할 수 있다. 동시성·지연·메모리를 대상 하드웨어에서 실측한다. 개인정보가 서버를 거치는 경로는 앱의 개인정보 선언(Apple 개인정보 영양 표시, Google Play 데이터 보안 양식)과 일치시킨다. [부분: 개인 후기/추정]
- **품질이 속도와 맞교환일 수 있다.** 3배 빠르지만 27B를 선호한다는 후기와 Q4에서 루프를 돈다는 후기가 있다. 사용자 응답을 생성하는 기능이라면 루프(반복 출력)를 서버에서 감지해 끊는 장치와 폴백 모델을 둔다. [부분: 개인 후기]
- **라이선스 고지.** 여러 목록이 Apache 2.0을 적었다. 공식 저장소의 LICENSE 원문으로 확인한 뒤에 가중치를 번들·배포하고 NOTICE를 지킨다(§1.5). [부분]
- **제공자 쪽 안전장치가 없다.** 입력 필터, 출력 검증, 위험한 기능(결제, 계정 변경, 외부 전송)의 권한 제한을 앱이 직접 한다. 모델 출력은 신뢰하지 않는 입력으로 취급해 서버에서 검증한 뒤 앱에 전달한다. 사진 입력을 쓰면 보관·삭제 정책과 동의를 설계한다.
- **모델 교체를 앱 업데이트 없이 할 수 있게 설계한다.** 서버 쪽 모델 설정, 폴백 모델, 회귀 시험, 기능 플래그를 둔다. 공식 저장소에서만 가중치를 받고 커밋 해시를 고정한다.

**개발 보조로 쓸 때**
- **모바일(Kotlin·Swift) 코드에 대한 독립 평가는 찾지 못했다.** [미확인] 컴파일·린트·단위 테스트·UI 테스트로 검증하고, 수명주기·권한·비동기 처리가 걸린 구현은 `qwen3.6-27b`나 상위 모델 문서(`claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon`)와 같은 과제로 비교한다.
- 스토어 규정은 기억으로 답하지 않고 공식 문서로 확인한다(§3.2). 서명 키, 프로파일, 스토어 제출·배포는 승인 후에만 한다.
