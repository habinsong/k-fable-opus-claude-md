## 2. 이 모델의 웹 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: MoE(총 35B·활성 약 3B), 빠름(초당 35~101 토큰 보고), Q4에서 루프를 돈다는 후기, Apache 2.0, 독립 평가 부재.

- **웹 UI 생성의 독립 평가는 찾지 못했다.** [미확인] 컴포넌트 단위 수정, 새 화면, 스크린샷 재현을 우리 코드베이스에서 `qwen3.6-27b`와 같은 기기·양자화·과제로 비교하고, 스크린샷 대조와 린터·타입체크·테스트 출력으로 판정한다. 기존 UI 체계가 우선한다(§3.1).
- **속도가 필요한 단발 UI 수정에 맞는다.** 초당 35~101 토큰이라는 보고(기기별)가 있어 컴포넌트 하나를 고치는 대화형 흐름에서는 27B보다 지연이 작다. 다만 속도와 완결성이 맞교환일 수 있다는 후기("3배 빠르지만 27B를 선호")가 있다. [부분: 개인 후기]
- **루프를 감시한다.** A3B의 Q4 양자화가 같은 자리를 돌았다는 후기가 있다. 같은 수정이 반복되거나 같은 파일을 계속 다시 쓰면 멈추도록 하네스에 반복 한도를 두고, 같은 실패가 3번 반복되면 접근을 바꾼다(§1.2). 양자화 수준을 올려(Q6 이상) 같은 과제를 시험한다. [부분: 개인 후기]
- **스크린샷 입력은 직접 시험한다.** 비전 언어 입력을 지원하나 재현 정확도를 잰 자료는 찾지 못했다. [부분/미확인]
- **긴 파일을 통째로 넣지 않는다.** 활성 약 3B 모델은 큰 입력에서 약할 수 있다(이 모델의 측정은 없고 유사 구조 모델의 후기에서 나온 우려다). 관련 컴포넌트와 타입, 오류 메시지만 주고 한 번에 한 가지만 시킨다. [추정]
- **도구 호출 하네스는 런타임 버전에서 작은 시험으로 확인한다.** 서빙 예시는 `qwen3` 추론 파서와 `qwen3_coder` 도구 호출 파서를 쓴다. 열린 버그의 현재 상태는 확인하지 못했다. [부분]
- **로컬 실행의 이점과 책임.** 미공개 소스를 외부로 보내지 않는다. 모델이 만든 코드는 격리된 환경에서 실행하고 의존성 추가는 라이선스·유지 상태를 확인한 뒤에 한다(§1.5). 보안·접근성 판단은 맡기지 않는다. 인가, 입력 검증, 비밀 노출, 접근성 "충족" 여부는 도구 출력과 §3.1 기준으로 사람이 점검한다.
