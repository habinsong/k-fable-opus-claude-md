## 2. 이 모델의 펌웨어 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: MoE(총 35B·활성 약 3B)라 기기 내 실행 불가, 임베디드 독립 평가 없음, 루프 후기, 제공자 안전장치 없음, 로컬 실행으로 펌웨어 소스 외부 전송 없음.

- **기기 안에서 돌릴 모델이 아니다.** 35B 전체를 메모리에 올려야 한다. MCU는 물론 일반적인 임베디드 리눅스 SBC에도 맞지 않는다. 개발 워크스테이션 쪽 도구로만 쓴다. 기기 내 추론이 필요하면 소형 모델 문서(`gemma-4-e2b`, `gemma-4-e4b`)를 본다. [부분/추정]
- **펌웨어 코드를 직접 쓰거나 고치게 하지 않는다.** 레지스터 값, 인터럽트, 부트·업데이트 경로, 서명 검증은 환각이 장치 고장이나 보안 구멍이 된다. 임베디드·펌웨어 독립 평가는 찾지 못했다. [미확인] 이 영역은 `gemini-4-argon`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol` 문서를 따른다.
- **레지스터·타이밍을 모델의 기억에서 가져오지 않는다.** 활성 약 3B라 값 회상이 불리할 수 있다는 구조상의 우려가 있다(이 모델에서 측정된 것은 아님). [추정] 데이터시트·레퍼런스 매뉴얼의 개정판과 페이지를 사람이 확보한 텍스트로 주고, 확인하지 못했으면 값을 쓰지 않는다(§3.1).
- **써도 되는 작업.** UART·RTT 로그 분류, 맵 파일 요약, 컴파일러 경고 그룹화, 변경 이력 요약, 호스트에서 돌리는 테스트 코드(하드웨어 추상화 뒤쪽 로직)의 초안. 입력은 관련 구간만 준다. 출력은 원본 로그·맵 파일과 한 건씩 대조한다. 서명 키와 디버그 인증 정보는 로컬 모델에도 입력하지 않는다(§3.4).
- **같은 자리를 도는 루프를 차단한다.** A3B의 Q4 양자화가 같은 자리를 돌았다는 후기가 있다. 빌드-플래시-확인 루프에서 같은 오류에 같은 수정이 반복되면 멈추고 같은 실패 3번이면 접근을 바꾼다(§1.2). 플래시 쓰기 같은 비가역 명령이 루프 안에 있으면 반복이 장치를 손상시킬 수 있으므로 루프에서 장치 쓰기를 분리한다. [부분: 개인 후기]
- **장치 쓰기는 모델이 실행하지 않는다.** 플래시 소거, 퓨즈·OTP, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금은 사람이 대상 장치와 이미지를 확인한 뒤 실행한다. 로컬 모델에는 제공자 쪽 안전장치가 없으므로 이 정지점은 더 중요하다. 프로그래머·시리얼 제어 도구는 읽기 전용부터 연결한다.
- **변경 후 검증을 강제한다.** 호스트 단위 테스트와 정적 분석을 돌리게 하고, 경고를 억제하라는 제안은 따르지 않는다. 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.
