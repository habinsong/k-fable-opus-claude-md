## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: MoE(활성 약 3B), SWE-bench Verified 73.4(벤더 수치 인용), 빠름, Q4에서 루프를 돈다는 후기, C/C++·Rust 독립 평가 없음.

**개발 보조로 쓸 때**
- **단발·소규모 작업에 맞는다.** 컴파일 오류 설명, 짧은 함수 초안, 단위 테스트 초안, 로그 분류, 이름 바꾸기 같은 기계적 변환처럼 입력이 작고 결과가 컴파일러·sanitizer·테스트로 검증되는 일에 쓴다. 활성 파라미터가 작아 큰 입력·긴 에이전트 루프에서 약할 수 있다는 구조상의 우려는 추정이다(이 모델의 측정은 없다). [추정]
- **C++·Rust·시스템 코드의 언어별 독립 평가는 찾지 못했다.** [미확인] 메모리 관리, 동시성, 수명, ABI는 문법이 맞아도 틀리기 쉬우므로 핵심 변경에는 쓰지 않고, 쓴다면 sanitizer(ASan·UBSan·TSan)와 테스트를 지시문으로 강제한다. 핵심 변경은 `qwen3.6-27b`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon` 문서를 따른다.
- **SWE-bench Verified 73.4는 벤더 수치 인용이다.** 밀집 27B(최대 77.2)보다 낮고 하네스 조건과 독립 재현이 확인되지 않았다. 점수 차이가 작은 만큼 속도와 완결성의 맞교환이 우리 과제에서 어떤지 측정으로 정한다. [부분: 벤더 주장]
- **루프와 반복을 감시한다.** A3B의 Q4 양자화가 같은 자리를 돌았다는 후기가 있다. 빌드-테스트 루프에서 같은 오류에 대한 같은 수정이 반복되면 멈추고(같은 실패 3번이면 접근을 바꾼다, §1.2) 양자화 수준을 올리거나 `qwen3.6-27b`로 올린다. 완료 보고는 빌드·테스트·sanitizer 출력과 `git diff`로 확인하고 테스트·경고·sanitizer 설정이 바뀌었는지도 확인한다. [부분: 개인 후기]
- **속도는 장점이다.** 초당 35~101 토큰이라는 보고(기기별)가 있어 반복 수정-확인 루프의 지연이 작다. 파괴적 명령 차단(권한·훅)과 작업 디렉터리 격리는 속도와 무관하게 둔다. [부분: 개인 후기]
- **도구 호출 파서와 템플릿을 런타임 버전에서 확인한다.** 서빙 예시는 `qwen3` 추론 파서와 `qwen3_coder` 도구 호출 파서를 쓰고 llama.cpp는 `--jinja`를 쓴다. 열린 버그의 현재 상태는 확인하지 못했다. [부분]

**애플리케이션에 내장할 때**
- 로컬 런타임을 링크하면 런타임과 가중치 라이선스를 각각 확인한다. 가중치는 여러 목록에 Apache 2.0이라고 적혀 있으나 LICENSE 원문으로 확인한다(§1.5). 모델 호출은 별도 프로세스와 최소 권한으로 격리하고 모델이 만든 경로·명령·코드를 그대로 실행하지 않는다. 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1). 시스템 경로, 레지스트리, 드라이버, 부트 설정, 서명 키는 승인 없이 건드리지 않는다. [부분]
