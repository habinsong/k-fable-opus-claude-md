## 2. 이 모델의 하드웨어 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: MoE(활성 약 3B), 독립 지수·환각 값 부재, 하드웨어 설계 평가 없음, 로컬 실행으로 설계 자료 외부 전송 없음.

- **설계 판단에 쓰지 않는다.** 핀 배치, 정격, 타이밍, 수식은 틀리면 보드가 망가지거나 위험해진다. 이 모델의 회로·PCB·HDL 평가는 찾지 못했다. [미확인] 코딩 후기와 벤더 수치(SWE-bench Verified 73.4)는 회로 설계 정확도를 대표하지 않는다. 설계는 `gemini-4-argon`, `claude/opus-5.5`, `gpt-6.1-sol` 같은 상위 모델 문서와 같은 과제로 비교하고, 그 결과도 데이터시트 원문과 도구 계산으로 확인한다.
- **활성 파라미터가 적으면 정확한 값 회상이 불리할 수 있다.** 부품 번호, 핀 번호, 레지스터 주소, 정격 같은 외운 값은 지어내기 쉽다는 구조상의 우려이며 이 모델에서 측정된 것이 아니다. [추정] 값은 사람이 확보한 데이터시트 텍스트에서만 꺼내게 하고, 값마다 문서명·개정판·페이지를 같이 받아 원문 PDF와 한 건씩 대조한다. 원문에 없으면 null이다(§3.1).
- **데이터시트는 발췌해서 준다.** 한 번에 한 부품·한 질문만 시키고 필요한 장과 표만 넣는다. PDF 표를 텍스트로 변환한 결과도 원문과 대조한다.
- **그림·표 이미지를 읽히는 용도는 직접 시험한다.** 비전 언어 입력을 지원하나 핀 표, 타이밍 다이어그램, 회로도의 판독 정확도를 잰 자료는 찾지 못했다. 읽은 값은 원문 텍스트·넷리스트·ERC 보고서와 대조하고, 읽기 어려운 부분은 추측하지 말고 "판독 불가"로 표시하게 한다. 이 용도에는 `qwen3.6-27b`나 후속 `qwen3.8-27b`가 더 적합할 수 있다. [부분/미확인]
- **써도 되는 작업.** BOM 정규화, 부품 번호 목록 변환, 시험 로그 분류, 데이터시트 텍스트에서 정해진 필드 추출, 측정·변환 스크립트(파이썬)의 초안. 속도가 빨라(초당 35~101 토큰 보고) 대량 정리에 유리하나 Q4에서 루프를 돈다는 후기가 있어 반복 한도를 둔다. 스크립트는 알려진 값을 넣어 실행해 확인한다. 로컬 실행이라 미공개 설계 자료를 외부로 보내지 않는다. [부분: 개인 후기]
- **계산은 도구로 한다.** 전류 예산, 분압, 필터, 열 계산은 스크립트·시뮬레이터 출력으로 확인하고 식과 가정을 남긴다.
- **로컬 모델이 만든 스크립트는 격리 환경에서 실행한다.** 측정 장비·전원·프로그래머를 제어하는 스크립트는 사람이 읽고 승인하기 전에 실제 장비에 연결하지 않는다. 인체·화재 위험 설계는 "안전하다"고 단정하지 않고 사람의 검토를 요청한다.
