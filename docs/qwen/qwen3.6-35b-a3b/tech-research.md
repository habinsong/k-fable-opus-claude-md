## 2. 이 모델의 기술 조사 운용, 그리고 이 모델을 평가할 때
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: MoE(총 35B·활성 약 3B), Apache 2.0(여러 목록), 빠름, Q4에서 루프를 돈다는 후기, 독립 지수 부재, 후속 세대와 경쟁 모델(`gemma-4-26b-a4b`) 존재.

**이 모델에게 기술 조사를 시킬 때**
- 분류·정리 단계에만 쓴다. 후보를 정해진 기준(라이선스 유형, 지원 언어, 릴리스 날짜)으로 분류해 표로 만들 때, 값은 사람이 확보한 1차 자료 텍스트에서 추출하게 하고 원문에 없으면 null로 둔다.
- 라이선스 호환성, 특허, 규정 적용 여부, 도입 권고는 단정시키지 않는다(§3.2, §3.5). 활성 약 3B 모델이라 선택지 비교·권고 작성 같은 판단은 맡기지 않는다. [추정]

**Qwen3.6-35B-A3B를 도입 후보로 평가할 때**
- **같은 급 모델과 같은 조건으로 비교한다.** 같은 계열의 밀집 `qwen3.6-27b`, 같은 MoE 구조의 `gemma-4-26b-a4b`, 후속 `qwen3.8-27b`와 같은 기기·양자화·과제·샘플링으로 측정한다. 속도가 3배(27B 대비) 빠르다는 보고와 완결성은 27B가 낫다는 후기가 갈리므로 우리 과제에서 속도 이득이 품질 손실을 정당화하는지 정한다. [부분: 개인 후기]
- **MoE의 비용 구조를 오해하지 않는다.** 활성은 약 3B지만 메모리는 35B 전체가 든다. 속도는 빠르고 메모리는 밀집 35B급이다. 같은 메모리 예산의 밀집 모델과 비교한다. 4비트 GGUF가 돈다는 서술 외에 VRAM 수치는 확인하지 못했다. [부분/미확인]
- **양자화 수준을 평가 조건에 넣는다.** Q4에서 루프를 돈 후기가 있고 비교 대상 27B는 Q6이었다. 양자화 수준을 통일하지 않은 후기를 모델 간 우열의 근거로 쓰지 않는다. [부분: 개인 후기]
- **라이선스.** 여러 목록이 Apache 2.0을 적었다. 공식 저장소의 LICENSE 원문으로 확인하고 SPDX 식별자와 NOTICE 의무를 기록한다(§3.2). 학습 데이터 출처와 저작권 이슈는 확인하지 못했다. 양자화 변환본은 변환자의 저장소 라이선스·출처도 따로 본다. [부분]
- **벤더 수치로 결정하지 않는다.** SWE-bench Verified 73.4는 안내 글이 인용한 수치이고 하네스 조건과 독립 재현이 확인되지 않았다. 독립 지수는 찾지 못했다. 후보 비교는 같은 과제, 같은 조건의 자체 실측으로 한다. [부분: 벤더 주장]
- **총소유비용.** API 비용이 없는 대신 GPU·전력·운영·평가 비용이 든다. 처리량(초당 35~101 토큰 보고, 기기별)과 메모리를 대상 하드웨어에서 컨텍스트 길이별로 실측한다. [부분: 개인 후기]
- **런타임 성숙도.** 서빙 파서(`qwen3`, `qwen3_coder`)와 llama.cpp `--jinja` 도구 호출 지원이 안내돼 있다. 열린 버그의 현재 상태는 확인하지 못했으므로 채택할 런타임 버전에서 작은 시험을 한다. [부분]
- **제공자 안전장치 부재와 공급망.** 입력 필터, 출력 검증, 권한 제한을 직접 구축한다. 공식 조직 저장소에서만 받고 커밋 해시를 고정하며 제3자 재업로드와 양자화 변환본은 출처를 확인하기 전에는 쓰지 않는다. 규제 적합성은 시스템 전체에 대해 판단하고 가중치 라이선스를 규정 준수의 근거로 쓰지 않는다. [추정]
