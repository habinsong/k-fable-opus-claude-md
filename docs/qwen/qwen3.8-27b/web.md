## 2. 이 모델의 웹 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 밀집 27B 비전 언어 모델, 4비트로 24 GB GPU, 라이선스 Apache 2.0이라는 서술(소수 출처), 독립 지수 `xhigh` 52, 벤더 코딩 수치는 Claude Code 하네스 기반, 독립 후기 부재.

- **웹 UI 생성의 독립 평가는 찾지 못했다.** [미확인] 컴포넌트 단위 수정, 새 화면, 스크린샷 재현을 우리 코드베이스에서 같은 조건으로 `qwen3.6-27b`, 상위 모델과 비교하고, 스크린샷 대조와 린터·타입체크·테스트 출력으로 판정한다. 기존 UI 체계가 우선한다(§3.1).
- **스크린샷을 입력으로 줄 수 있는 로컬 모델이 이 모델의 특징이다.** 비전 언어 모델이라 시안·스크린샷을 재현시키는 시험이 가능하지만, 레이아웃·간격·색 재현 정확도를 잰 독립 자료는 찾지 못했다. 이미지가 크면 입력 토큰이 늘어 메모리와 지연이 커진다. 우리 화면으로 직접 시험한다. [부분/미확인]
- **벤더 코딩 수치의 조건을 읽는다.** SWE-bench Pro 61.7, Terminal-Bench 2.1 73.0은 Qwen 자체 실행이고 일부는 Claude Code 하네스에서 돌렸다는 각주가 있다. 로컬 하네스(llama.cpp, vLLM + 자체 에이전트)에서 같은 성능을 기대하지 않는다. [부분: 벤더 주장]
- **추론이 기본으로 켜져 있다는 서술이 있다.** 작은 CSS 수정에도 추론 토큰이 많이 나오고 지연이 클 수 있다. 독립 평가에서 `xhigh` 출력 속도가 초당 53 토큰으로 느렸다(호스팅 환경 기준). 단계/모드를 요청마다 명시하고 단순 수정은 비추론(독립 지수 35)이나 `low`(43)로 시험한다. [부분]
- **도구 호출 하네스는 런타임 버전에서 작은 시험으로 확인한다.** 이전 세대 후기에서 Qwen 3.6 계열의 도구 호출이 Gemma 4보다 낫다는 보고가 많았으나 3.8-27B의 파서 지원은 확인하지 못했다. llama.cpp는 `--jinja` 옵션으로 네이티브 도구 호출을 쓰는 안내가 있다. [부분: 개인 후기, 이전 세대]
- **로컬 실행의 이점과 책임.** 미공개 소스를 외부로 보내지 않는다. 대신 제공자 쪽 안전장치가 없으므로 모델이 만든 코드는 격리된 환경에서 실행하고 의존성 추가는 라이선스·유지 상태를 확인한 뒤에 한다(§1.5).
- **보안·접근성 판단을 맡기지 않는다.** 인가, 입력 검증, 비밀 노출, 접근성 "충족" 여부는 도구 출력과 §3.1 기준으로 사람이 점검한다. API·CSS·브라우저 지원은 공식 문서와 린터·컴파일러 출력으로 확인한다.
- **라이선스를 원문으로 확인한 뒤 번들한다.** Apache 2.0이라는 서술이 소수 출처에 있다. 저장소의 LICENSE로 확인하기 전에는 배포 제품에 가중치를 넣지 않는다(general.md §2.1). [부분, 충돌]
