## 2. 이 모델의 펌웨어 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 밀집 27B 비전 언어 모델이라 기기 내 실행 불가, 4비트로 24 GB GPU, 임베디드 평가 없음, 환각 값 미확인, 제공자 안전장치 없음.

- **기기 안에서 돌릴 모델이 아니다.** 4비트 가중치만으로도 24 GB GPU가 필요하다. MCU는 물론 일반적인 임베디드 리눅스 SBC에도 맞지 않는다. 개발 워크스테이션 쪽 도구로만 쓴다. 기기 내 추론이 필요하면 소형 모델 문서(`gemma-4-e2b`, `gemma-4-e4b`)를 본다. [부분]
- **펌웨어 코드를 직접 쓰거나 고치게 하지 않는다.** 레지스터 값, 인터럽트, 부트·업데이트 경로, 서명 검증은 환각이 장치 고장이나 보안 구멍이 된다. 임베디드·펌웨어 평가는 찾지 못했다. [미확인] 벤더 코딩 수치(Terminal-Bench 2.1 73.0, Claude Code 하네스 기반)는 장치 쓰기나 실시간 제약과 무관하다. 이 영역은 `gemini-4-argon`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol` 문서를 따른다.
- **레지스터·타이밍을 모델의 기억에서 가져오지 않는다.** 환각 값을 찾지 못했다. 데이터시트·레퍼런스 매뉴얼의 개정판과 페이지를 사람이 확보한 텍스트로 주고, 확인하지 못했으면 값을 쓰지 않는다(§3.1). [미확인]
- **로컬 실행의 이점은 펌웨어 소스·로그·양산 이미지가 외부로 나가지 않는 것이다.** 로그 분류, 맵 파일 요약, 컴파일러 경고 그룹화, 변경 이력 요약, 호스트에서 돌리는 테스트 코드(하드웨어 추상화 뒤쪽 로직)의 초안에 쓴다. 입력은 관련 구간만 준다. 출력은 원본 로그·맵 파일과 한 건씩 대조한다. 서명 키와 디버그 인증 정보는 로컬 모델에도 입력하지 않는다(§3.4).
- **UART 캡처·오실로스코프 화면·보드 사진을 이미지로 읽히는 용도는 직접 시험한다.** 비전 언어 모델이라 입력은 가능하나 판독 정확도를 측정한 자료는 찾지 못했다. 읽은 값은 원자료(로그, 측정값)와 대조하고 추측하지 말고 "판독 불가"로 표시하게 한다. [부분/미확인]
- **장치 쓰기는 모델이 실행하지 않는다.** 플래시 소거, 퓨즈·OTP, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금은 사람이 대상 장치와 이미지를 확인한 뒤 실행한다. 로컬 모델에는 제공자 쪽 안전장치가 없으므로 이 정지점은 더 중요하다. 도구 호출 하네스에서 프로그래머·시리얼 제어 도구를 모델에 열어 줄 때는 읽기 전용 도구부터 연결한다.
- **추론 기본 켜짐으로 지연이 크다.** `xhigh` 출력 속도가 초당 53 토큰이었다(호스팅 기준). 빌드-플래시-확인 루프를 모델이 직접 돌리면 지연이 크므로 한 번에 크게 묻고 한 번에 검증한다. [부분]
- **변경 후 검증을 강제한다.** 호스트 단위 테스트와 정적 분석을 돌리게 하고, 경고를 억제하라는 제안은 따르지 않는다. 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.
