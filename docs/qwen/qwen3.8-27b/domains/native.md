## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 밀집 27B 비전 언어 모델, 벤더 코딩 수치(SWE-bench Pro 61.7, Terminal-Bench 2.1 73.0)는 Claude Code 하네스 기반, 독립 후기 부재, 추론 기본 켜짐, C/C++·Rust 평가 없음.

**개발 보조로 쓸 때**
- **벤더 수치의 조건을 읽는다.** SWE-bench Pro 61.7과 Terminal-Bench 2.1 73.0은 Qwen이 자체 실행했고 Claude Code 하네스에서 돌렸다는 모델 카드 각주가 있다. 독립 재현이 없다. 로컬에서 쓰는 하네스(llama.cpp·vLLM + 자체 에이전트, Qwen Code 등)에서 같은 점수를 기대하지 않는다. 직전 세대 `qwen3.6-27b`가 로컬 코딩 기준선으로 거론되므로 같은 과제로 직접 비교한다. [부분: 벤더 주장]
- **C++·Rust·시스템 코드의 언어별 평가는 찾지 못했다.** [미확인] 메모리 관리, 동시성, 수명, ABI는 문법이 맞아도 틀리기 쉬우므로 핵심 변경에는 쓰지 않고, 쓴다면 sanitizer(ASan·UBSan·TSan)와 테스트를 지시문으로 강제한다. 핵심 변경은 `claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon` 문서를 따르거나 우리 코드로 같은 과제를 비교한다.
- **로컬 실행의 이점은 소스가 외부로 나가지 않는 것이다.** 4비트로 24 GB GPU에 올릴 수 있다는 서술이 있어 미공개 시스템 코드를 로컬에서 다룰 수 있다. 이 이점은 정확도를 보증하지 않는다. 긴 컨텍스트의 KV 캐시와 이미지 입력은 메모리를 더 쓰므로 대상 기기에서 실측한다. [부분]
- **추론 기본 켜짐 때문에 지연과 토큰이 크다.** 독립 평가에서 `xhigh` 출력 속도가 초당 53 토큰이었다(호스팅 기준). 컴파일 오류 설명 같은 단발 질문에는 비추론이나 `low`를 시험한다. 추론 토큰이 컨텍스트와 `max_tokens`를 쓰므로 예산을 추론 길이까지 고려한다. [부분]
- **빌드·플래시·테스트를 오가는 긴 에이전트 루프는 시험 후에 쓴다.** 이 모델의 에이전트 루프 신뢰도에 대한 독립 후기는 없다. 파괴적 명령 차단(권한·훅), 작업 디렉터리 격리, 시간·토큰 한도를 먼저 설정하고 완료 보고는 빌드·테스트·sanitizer 출력과 `git diff`로 확인한다. 테스트·경고·sanitizer 설정이 바뀌었는지도 확인한다. 억제 지시문을 넣거나 검사를 끄는 제안은 따르지 않는다. [미확인]
- **도구 호출 파서와 채팅 템플릿을 런타임 버전에서 확인한다.** 이전 세대 후기에서 llama.cpp의 `--jinja`로 네이티브 도구 호출을 쓰는 안내가 있었다. 3.8-27B의 지원은 최신 런타임에서 작은 시험으로 확인한다. [부분/미확인]

**애플리케이션에 내장할 때**
- 로컬 런타임(llama.cpp, vLLM 등)을 링크하면 런타임과 가중치 라이선스를 각각 확인한다. 가중치는 Apache 2.0이라는 서술이 소수 출처에 있으므로 LICENSE 원문으로 확인한 뒤에만 번들한다(README.md가 안내하는 개요·운용 문서.1). [부분, 충돌]
- **모델 출력은 신뢰하지 않는 입력이다.** 모델이 만든 경로·명령·코드를 그대로 실행하지 않고 모델 호출은 별도 프로세스와 최소 권한으로 격리한다. 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1). 시스템 경로, 레지스트리, 드라이버, 부트 설정, 서명 키는 승인 없이 건드리지 않는다.
