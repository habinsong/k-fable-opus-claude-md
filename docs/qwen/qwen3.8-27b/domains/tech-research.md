## 2. 이 모델의 기술 조사 운용, 그리고 이 모델을 평가할 때
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 밀집 27B 비전 언어 모델, Apache 2.0이라는 서술(소수 출처, 과거 일부 Qwen 릴리스는 다른 라이선스), 4비트로 24 GB GPU, 독립 지수 `xhigh` 52, 벤더 수치는 Claude Code 하네스 기반, 독립 후기 부재.

**이 모델에게 기술 조사를 시킬 때**
- 분류·정리 단계에만 쓴다. 후보를 정해진 기준(라이선스 유형, 지원 언어, 릴리스 날짜)으로 분류해 표로 만들 때, 값은 사람이 확보한 1차 자료 텍스트에서 추출하게 하고 원문에 없으면 null로 둔다.
- 라이선스 호환성, 특허, 규정 적용 여부, 도입 권고는 단정시키지 않는다(§3.2, §3.5). 후보를 지나치게 높게 평가하는 경향(아첨)은 측정된 바 없으므로 사람이나 상위 모델이 근거를 보고 판단한다.

**Qwen3.8-27B를 도입 후보로 평가할 때**
- **라이선스를 원문으로 확인한다.** 두 출처가 Apache 2.0이라 쓰고 한 곳은 저장소가 표준 Apache License 2.0을 싣는다고 하나, 출시 전후의 다른 글은 불확실하다고 했고 과거 일부 Qwen 릴리스는 월간 활성 사용자 1억 명 임계값이 있는 "Tongyi Qianwen" 라이선스를 썼다. 같은 세대의 2.4T 체크포인트는 자체 라이선스(모델 제공자 조항)다. 저장소의 LICENSE로 확인한 뒤 SPDX 식별자와 NOTICE 의무를 기록한다(§3.2). 학습 데이터 출처와 저작권 이슈는 확인하지 못했다. [부분, 충돌]
- **직전 세대와 같은 과제로 비교한다.** `qwen3.6-27b`가 로컬 코딩 기준선으로 거론되고, 독립 후기는 3.6·Gemma 4 세대에 집중돼 있다. 3.8-27B가 그보다 나은지는 우리 과제의 실측으로 정한다. `gemma-4-31b`와도 같은 기기·양자화·과제·샘플링으로 비교한다. [부분: 이전 세대 후기]
- **벤더 수치로 결정하지 않는다.** SWE-bench Pro 61.7, Terminal-Bench 2.1 73.0은 Qwen 자체 실행이고 Claude Code 하네스에서 돌렸다는 각주가 있다. 독립 지수는 `xhigh` 52, `medium` 44, `low` 43, 비추론 35이며 지수 버전이 섞여 있다. [부분, 충돌]
- **총소유비용.** API 비용이 없는 대신 GPU·전력·운영·평가 비용이 든다. BF16 가중치만 약 55.6 GB이고 4비트로 24 GB GPU에 올릴 수 있다는 서술이 있으나 긴 컨텍스트의 KV 캐시와 이미지 입력은 별도다. 추론 기본 켜짐으로 토큰과 지연이 크므로(`xhigh` 출력 속도가 초당 53 토큰이라는 호스팅 기준 측정) 동시 사용자 수와 처리량을 대상 하드웨어에서 실측한다. [부분, 충돌]
- **런타임 성숙도.** 서빙 도구(vLLM, llama.cpp 등)의 도구 호출 파서·채팅 템플릿 지원이 모델마다 다르다. 3.8-27B의 상태는 확인하지 못했으므로 채택할 런타임 버전에서 작은 시험을 한다. [미확인]
- **제공자 안전장치 부재.** 입력 필터, 출력 검증, 권한 제한을 직접 구축한다. 규제 적합성은 모델이 아니라 시스템 전체에 대해 판단하며 모델 카드나 가중치 라이선스를 규정 준수의 근거로 쓰지 않는다.
- **공급망과 공급 연속성.** 공식 조직 저장소에서만 받고 커밋 해시를 고정하며 제3자 재업로드와 양자화 변환본은 출처를 확인하기 전에는 쓰지 않는다. 공개 후 불과 석 달이므로 후속 갱신에 대비해 교체 절차와 회귀 시험을 둔다. [추정]
