## 2. 이 모델의 앱 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 비용 중심 Flash, 코딩 지수 76.3(2차), 첫 토큰 지연이 큼, 장황함, 추론을 완전히 끌 수 없음.

- **모바일 앱 개발에 대한 독립 평가는 찾지 못했다.** [미확인] 코딩 지수와 낮은 단가로 보아 컴파일 오류·린트·단위 테스트 수정 같은 짧은 반복에는 맞지만 [부분], 실기기 검증을 생략하지 않는다.
- **번역·문자열 리소스 작업에 맞는다.** 다국어 문자열 변환(Android `strings.xml`, iOS `Localizable`), 스토어 메타데이터 초안은 `LOW`로 처리하고 비용을 줄인다. 번역은 원어민 검수 전에 출시하지 않고 용어집으로 일관성을 점검한다.
- **스토어 정책·플랫폼 요건은 기억에서 가져오지 않는다.** 지식 평가 정답 비율 55%(소형 모델 중 높은 편)라도 절반 가까이는 틀리거나 모른다. [부분] 검색 grounding의 출처를 직접 열어 확인하고 §3.2 표는 공식 문서로 다시 확인한다.
- **대화형 앱 기능에 이 모델을 호출할 때는 첫 토큰 지연을 설계에 넣는다.** 한 측정에서 첫 토큰까지 13.30초였다. [부분] `thinking_level: LOW`와 스트리밍, 진행 표시를 쓴다.
- **빌드·테스트 출력은 파일로 한 번 저장하고 실패한 구간만 읽는다.** 장황한 출력을 막기 위해 최종 보고는 5항목, 항목당 1~2줄로 제한한다.
- **변경 후 실제 검사를 강제한다.** 컴파일·린트·단위 테스트를 돌리고 출력을 읽고 실패하면 고치라고 지시한다. 못 돌렸으면 무엇을 왜 못 했는지 말하게 한다.
- **비용.** 도입가 입력 $0.75 / 출력 $3.75가 2027-01-01 이후 두 배가 될 수 있다는 정리가 있다. 생각 토큰은 출력 요금이다. [부분] 앱 빌드 자동화에 장기 예산을 잡을 때 인상 가격을 쓴다.
- **서명 키, 프로파일, 스토어 제출·배포는 승인 후에만.**
