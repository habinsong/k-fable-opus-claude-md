## 2. 이 모델의 하드웨어 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 클라우드 API 모델, 사실 회상이 약하다고 가정, 독립 평가가 얕음, 하드웨어 설계 평가 없음, 데이터 처리 조건 미확인.

- **설계 판단에 쓰지 않는다.** 핀 배치, 정격, 타이밍, 수식은 틀리면 보드가 망가지거나 위험해진다. 이 모델의 회로·PCB·HDL 평가는 찾지 못했다. [미확인] GPQA Diamond 90.9 같은 과학 문제 점수는 벤더 보고이고 독립 확인이 없으며 회로 설계 정확도를 대표하지도 않는다. [부분] 설계는 `gemini-4-argon`, `claude/opus-5.5`, `gpt-6.1-sol` 같은 상위 모델 문서를 따르고, 그 결과도 데이터시트 원문과 도구 계산으로 확인한다.
- **값 회상을 믿지 않는다.** 사실 질문 평가에서 이 계열은 모르는 것을 모른다고 답하는 비율이 높지 않았다. 이전 세대 V4 Flash의 SimpleQA-Verified는 비추론 23.1 / 높음 28.9 / 최대 34.1이었고 같은 카드의 V4 Pro는 45.0~57.9였다. AA-Omniscience 비환각률은 빌드마다 3.9~46.0%로 크게 달랐다(general.md §2.3). 세대·빌드·지표가 달라 1017의 값을 말해 주지 않으며 어느 쪽도 부품 번호·정격을 외워서 답해도 된다는 근거가 되지 않는다. [부분, 충돌]
- **값은 사람이 확보한 데이터시트 텍스트에서만 꺼낸다.** 값마다 문서명·개정판·페이지를 같이 받아 원문 PDF와 한 건씩 대조하고, 원문에 없으면 null이다(§3.1). 유사 부품의 값으로 채우게 하지 않는다.
- **써도 되는 작업.** BOM 정규화, 부품 번호 목록 변환, 시험 로그 분류, 데이터시트 텍스트에서 정해진 필드 추출, 측정·변환 스크립트(파이썬)의 초안. 스크립트는 알려진 값을 넣어 실행해 확인한다. 가격이 낮아 대량 정리에 유리하지만 토큰 사용량이 많았던 측정이 있어 실비용을 확인한다. [부분]
- **계산은 도구로 한다.** 전류 예산, 분압, 필터, 열 계산은 스크립트·시뮬레이터 출력으로 확인하고 식과 가정을 남긴다. 추론 모드로 낸 풀이도 마찬가지다. 완료를 실제보다 낙관적으로 서술한 사례가 있으니 보고를 그대로 믿지 않는다. [부분: 개인 후기]
- **이미지(회로도 사진·PCB 사진) 판독은 근거로 쓰지 않는다.** 사양에는 이미지 입력이 있으나 API 제공 상태와 판독 정확도는 확인하지 못했다. [미확인] 넷리스트·ERC 보고서와 대조한다.
- **미공개 설계 자료를 API로 보내지 않는다(약관 확인 전).** 데이터 처리 위치·보관·학습 사용 조건을 찾지 못했다. [미확인] 회로도·레이아웃·펌웨어 이미지·부품 공급 정보는 영업비밀이므로 원문 약관을 읽고 승인받은 뒤에만 보낸다. 필요하면 MIT 가중치를 신뢰할 수 있는 인프라에 올리는 방안을 비교한다.
- **인체·화재 위험 설계는 "안전하다"고 단정하지 않는다.** 고전압·대전류·배터리·모터는 사람의 검토를 요청한다.
