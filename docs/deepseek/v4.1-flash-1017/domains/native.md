## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 클라우드 API 모델, 같은 이름으로 갱신, 독립 평가가 얕음, C/C++·시스템 코드 평가 없음, 자기 작업을 부풀려 서술한 사례.

**개발 보조로 쓸 때**
- **Rust 사용 사례는 일화 한 건뿐이다.** 한 개발자가 OpenCode에서 Rust 함수의 u16 자릿수 세기를 `checked_ilog10`으로 최적화하게 했고 모델이 그 방식이 가장 빠른 이유를 설명했다고 한다. 단일 일화이며 체계적 평가가 아니다. [부분: 개인 후기] 컴파일러, clippy, 벤치마크로 확인한다.
- **C++·시스템 코드 평가는 찾지 못했다.** [미확인] 메모리 관리, 동시성, 수명, ABI는 문법이 맞아도 틀리기 쉬우므로 핵심 변경에는 쓰지 않고, 쓴다면 sanitizer(ASan·UBSan·TSan)와 테스트를 지시문으로 강제한다. 핵심 변경은 `claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon` 문서를 따른다.
- **작업 완료 서술을 믿지 않는다.** 이전 세대 Flash가 자기 작업을 실제보다 빈틈없다고 말하고, 기존 테스트 구조 대신 새 테스트 파일을 만든 사례가 있다. [부분: 개인 후기] 빌드·테스트·sanitizer 출력을 직접 읽고, 테스트·경고·sanitizer 설정이 바뀌었는지 `git diff`로 확인한다. 억제 지시문을 넣거나 검사를 끄는 제안은 따르지 않는다.
- **긴 컨텍스트에 기대지 않는다.** 컨텍스트가 100만 토큰이라고 해도 입력이 길수록 지연·비용이 늘고 정확도는 보장되지 않는다. 관련 함수·호출부·오류 메시지·빌드 설정만 준다. [추정]
- **사실 회상은 약하다고 가정한다.** 시스템 API의 시그니처, 플랫폼별 동작, 표준 라이브러리 세부는 지어낼 수 있다(README.md가 안내하는 개요·운용 문서.3). 공식 문서와 컴파일러로 확인한다. [부분]
- **추론 모드는 요청마다 명시하고, 도구 호출 루프에서 추론 내용을 다음 요청에 돌려줘야 하는지는 공식 문서로 확인한다**(README.md가 안내하는 개요·운용 문서.4).
- **미공개 소스를 API로 보내기 전에 약관을 확인한다.** 데이터 처리 조건을 찾지 못했다. [미확인] 확인 전에는 비밀·고객 코드를 보내지 않는다(§1.6).

**애플리케이션에 내장할 때**
- **모델은 서버 API로 호출한다.** 가중치가 수백 GB라 데스크톱 프로그램에 번들할 수 없다. 클라이언트에 API 키를 두지 않고 자체 백엔드를 거친다. 모델 출력으로 만든 경로·명령·코드를 그대로 실행하지 않으며, 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1).
- **오프라인 요구가 있으면 이 모델은 맞지 않는다.** MIT 가중치를 자체 인프라(다중 GPU 노드)에 올리는 구성은 가능하지만 데스크톱 배포용이 아니다. 소형 로컬 모델(`gemma-4-e4b`, `qwen3.6-27b` 등) 문서를 본다. [추정]
- **같은 이름의 모델이 바뀐다.** 애플리케이션의 AI 기능은 모델 교체 시 회귀 시험으로 감시하고, 스냅샷 ID 고정이 가능한 경로를 우선한다. 라이브러리·SDK를 추가할 때는 라이선스(§1.5)를 확인한다.
