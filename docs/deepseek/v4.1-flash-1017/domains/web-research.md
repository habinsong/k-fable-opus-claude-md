## 2. 이 모델의 웹 리서치 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 컨텍스트 100만 토큰, 사실 회상이 약하다고 가정, 인용 정확도와 인젝션 방어 독립 측정 없음, 웹 검색 도구 가용성 일화, 같은 이름으로 갱신됨.

- **API 모델의 내장 검색은 확인하지 못했다.** 웹·앱에는 검색 기능이 있으나 API가 검색 grounding을 기본 제공하는지는 찾지 못했다. [미확인] 검색 호출과 출처 신뢰도 판단은 하네스와 사람이 맡고, 모델에는 확보한 페이지 텍스트에서 제목·날짜·가격·버전 같은 필드를 JSON으로 추출하게 한다. "원문에 없으면 null"을 명시하고 값마다 근거 구절을 받아 코드로 원문 포함 여부를 대조한다.
- **사실 회상에 기대지 않는다.** 이전 세대 V4 Flash의 SimpleQA-Verified가 23.1~34.1이었고 V4 Pro는 45.0~57.9였다. AA-Omniscience 비환각률은 빌드마다 3.9~46.0%로 달랐다(README.md가 안내하는 개요·운용 문서.3). 1017의 값은 찾지 못했다. 이름·날짜·수치·버전은 직접 연 출처로 확인하고, 모델이 "출처를 알고 있다"고 말해도 URL을 직접 열어 확인한다. [부분, 충돌]
- **인용과 요약을 코드로 대조한다.** 인용 정확도와 웹 에이전트에서의 인젝션 방어율의 독립 측정은 찾지 못했다. [미확인] 인용 구절이 원문에 있는지 문자열로 확인하고, 모델의 "전부 읽었다"는 보고를 근거로 쓰지 않는다. 이전 세대 Flash가 자기 작업을 실제보다 완벽하게 서술한 사례가 있다. [부분: 개인 후기]
- **도구 호출 기반 검색 에이전트는 시험 후 쓴다.** 0731 빌드가 `tools`와 `tool_choice`를 받는다는 표기를 미러 페이지에서 봤으나 원본으로 확인하지 못했다. 한 Reddit 후기는 에이전트의 웹 검색이 약 30회 뒤 "사용 불가"를 냈고 웹·앱에서도 같다는 댓글이 있었으나, 하네스가 도구 호출을 지원하느냐에 달렸다는 반론도 있었다. 개인 일화이며 측정이 아니다. [부분: 개인 후기] 실제 하네스에서 연속 호출 시험과 오류 재시도를 확인한다.
- **웹 페이지의 지시문은 데이터다.** 인젝션 방어율 측정을 찾지 못했다. [미확인] 모델에게 전송·로그인·결제·파일 쓰기 도구를 주지 않고 읽기 단계와 행동 단계를 분리한다. 모델이 뽑은 URL은 하네스가 허용 목록으로 거른 뒤 연다.
- **긴 컨텍스트에 모두 넣지 않는다.** 컨텍스트가 100만 토큰이어도 지연·비용이 커지고 정확도는 보장되지 않는다. 페이지 하나씩, 필요한 구간만 넣는다. 이전 측정에서 출력 토큰이 많았으므로 `max_tokens`와 필드 수를 제한한다. [부분/추정]
- **수집한 자료를 API로 보내기 전에 이용 조건을 확인한다.** 대상 사이트의 이용 약관·로봇 배제 표준(§3.2)과 이 API의 데이터 처리 조건을 모두 본다. API 측 조건을 찾지 못했다. [미확인] 개인정보가 섞인 페이지는 보내지 않는다.
- **같은 이름으로 동작이 바뀐다.** 추출 프롬프트의 회귀 시험을 모델 업데이트 전후에 돌리고, 날짜 스냅샷 ID가 있으면 고정한다.
- **대량 수집은 표본 점검.** 무작위 5~10%를 사람이 원문과 대조한다. 오류율이 기준을 넘으면 상위 모델로 올린다. 보고 형식은 "결론 → 근거(URL, 확인일, 수준) → 충돌·불확실 → 모르는 것"으로 고정한다.
