## 2. 이 모델의 웹 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 같은 이름으로 갱신되는 API 모델, 독립 평가가 얕고 벤더 수치는 미확인, 토큰 사용량이 많았던 측정, 사실 회상이 약하다고 가정, 데이터 처리 조건 미확인.

- **웹 UI 코드 생성에 쓸 만하다는 근거는 단일 비교 글 한 건이다.** 같은 계열의 이전 세대 V4 Flash가 React+Vite+Express로 다중 페이지 대시보드(개요·계좌·거래·목표 화면, 다크 테마, 현금 흐름 차트, 지출 도넛 차트)를 동작하게 만들었고 비용은 $0.08이었다고 한다. 약점은 속도와 UI 마감이었고 글쓴이는 OpenAI 모델의 결과물이 일관되게 더 보기 좋았다고 평가했다. 이전 세대의 한 번 실행이다. [부분: 개인 후기]
- **V4.1 Flash의 UI 개선은 베타 단계의 중국어 보도뿐이다.** 한 리뷰어는 조종석 HUD 시연에서 UI·상호작용 세부가 나아졌다고 했으나 React 앱이 아니고 중간 시험 빌드였다. [부분] 1017 이후 웹 UI 품질 평가는 찾지 못했다. [미확인] 시각 마감은 스크린샷으로 직접 대조하고, 기존 UI 체계가 우선한다(§3.1).
- **에이전트가 스스로 한 일을 부풀릴 수 있다.** 실제 코딩 작업 비교에서 이전 세대 Flash는 기존 테스트 파일을 읽고 규약을 따르지 않고 새 테스트 파일을 만들었고, 자기 작업을 실제보다 더 빈틈없다고 서술했다. 파이썬(Rich 라이브러리) 과제의 한 건이다. [부분: 개인 후기] → 완료 보고는 린터·타입체크·테스트 출력과 `git diff`로 확인하고, 기존 테스트 구조와 규약을 따르게 지시한다.
- **토큰 사용량을 비용에 넣는다.** 같은 비교에서 Flash는 더 나은 결과를 냈지만 토큰을 더 써서 청구액이 거의 같아졌다. 지수 평가에서도 출력 토큰이 비교군의 두 배 수준이었다. 1017이 출력을 줄였다고 주장하므로 우리 작업으로 재측정한다. [부분]
- **같은 이름으로 동작이 바뀐다.** `deepseek-flash`가 1017로 갱신됐으므로 UI 생성 프롬프트와 템플릿의 회귀 시험(스냅샷·시각 비교)을 모델 업데이트 전후로 돌린다. 날짜 스냅샷 ID를 지원하는 경로가 있으면 고정한다(README.md가 안내하는 개요·운용 문서.4).
- **보안·접근성 판단을 맡기지 않는다.** 인가, 입력 검증, 비밀 노출, 접근성 "충족" 여부는 도구 출력과 §3.1 기준으로 사람이 점검한다. API·CSS·브라우저 지원은 공식 문서와 린터·컴파일러 출력으로 확인한다.
- **미공개 소스를 API로 보내기 전에 약관을 확인한다.** 데이터 처리 위치·보관·학습 사용 조건을 찾지 못했다. [미확인] 확인 전에는 비밀·고객 데이터가 담긴 코드를 보내지 않는다(§1.6).
- **추론 모드는 요청마다 명시하고, 도구 호출 루프의 추론 내용 전달 요건은 공식 문서로 확인한다**(README.md가 안내하는 개요·운용 문서.4).
