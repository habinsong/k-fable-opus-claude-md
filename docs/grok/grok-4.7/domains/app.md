## 2. 이 모델의 앱 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 폐쇄형 API 모델이라 기기 내 실행 불가, 컨텍스트 50만 토큰(20만 토큰부터 장문 요금), 출력 토큰 소비 많음, 이미지 입력, 모델 카드 부재, 데이터 정책은 2차 출처, 모바일 개발 독립 평가 없음.

**앱에 내장할 때**
- **기기 안에서 돌릴 모델이 아니다.** 폐쇄형이며 가중치를 받을 수 없다. 앱은 서버를 거쳐 호출하는 구조만 가능하다. 모바일 온디바이스는 `gemma-4-e2b`, `gemma-4-e4b` 문서를 본다.
- **API 키를 앱 바이너리나 리소스에 넣지 않는다.** 앱에서 직접 호출하지 말고 자체 백엔드에서 키 보관, 사용량 제한, 요청 검증, 로깅을 한다(§3.1 비밀 규칙). 모델 출력은 신뢰하지 않는 입력으로 취급해 서버에서 검증한 뒤 앱에 전달한다.
- **개인정보 선언과 실제 동작을 맞춘다.** 사용자 입력을 xAI API로 보내면 수집·전송 항목을 앱 스토어의 개인정보 선언(Apple 개인정보 영양 표시, Google Play 데이터 보안 양식)과 처리방침에 반영한다. 여러 집계는 API 입력·출력을 명시적 허락 없이 학습에 쓰지 않으며 기본 30일(남용 감사용) 보관한다고 정리하나 xAI 약관·DPA 원문을 읽지 못했고, 영 보관(ZDR)을 기업 전용으로 보는 곳과 콘솔 토글로 보는 곳이 갈린다. 소비자용 Grok의 정책은 API와 다르다. [부분, 충돌] 출시 전에 약관과 DPA를 원문으로 읽고, 아동·민감정보는 확인 전에 보내지 않는다. 앱 안에서 xAI의 소비자 서비스(X 연동 등)를 쓰는 경우와 API를 쓰는 경우를 구분한다.
- **이미지를 보내는 기능은 조심한다.** 이 모델은 이미지를 입력으로 받는다. 사진에 담긴 얼굴·위치·문서 정보가 서버와 제3자로 전송되므로 약관 확인과 사용자 동의 없이 보내지 않는다. [부분]
- **비용을 과제당으로 서버에서 제한한다.** 단가는 입력 $2 / 출력 $6이지만 벤치마크 실행에서 출력 토큰이 비교군 중앙값의 두 배 이상이었다. 프롬프트가 20만 토큰에 이르면 요청 전체에 장문 요금(입력 $4 / 출력 $12)이 적용된다는 서술이 있어 앱이 긴 대화 이력을 그대로 보내지 않게 한다. 사용자당 한도, `max_tokens`, 요청 빈도 제한을 서버에 두고 실제 청구서로 확인한다. [부분]
- **내장 도구(웹 검색, X 검색)의 과금을 앱 비용에 넣는다.** 도구 호출 1,000회당 $5가 토큰 요금과 별도로 청구되고 한 응답에 내부 검색이 여러 번 일어날 수 있다. 사용자별 호출 한도를 둔다. [부분]
- **모델 교체를 앱 업데이트 없이 할 수 있게 설계한다.** 직전 3개 버전(4.5·4.6·4.7)이 두 달 사이에 나왔고 후속(4.8, 5)이 예고돼 있다. 서버 쪽 모델 설정, 폴백 모델, 회귀 시험, 기능 플래그를 둔다. 구버전 폐기 일정은 공식 문서로 확인한다. [부분]
- **안전 문서가 없는 점을 제품 위험으로 기록한다.** 4.7 모델 카드·시스템 카드를 확인하지 못했고 출시 직후 탈옥 우회 주장 사례가 있었다. 앱 수준의 입력 필터, 출력 검증, 위험 기능의 권한 제한을 직접 둔다. [부분]

**개발 보조로 쓸 때**
- **모바일(Kotlin·Swift) 코드에 대한 독립 평가는 찾지 못했다.** [미확인] 코딩 에이전트 지수(Grok Build 함께, 56)는 일반 지표다. 컴파일·린트·단위 테스트·UI 테스트로 검증하고, 수명주기·권한·비동기 처리가 걸린 구현은 상위 모델 문서(`claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon`)와 같은 과제로 비교한다.
- 스토어 규정은 기억으로 답하지 않고 공식 문서로 확인한다(§3.2). 서명 키, 프로파일, 스토어 제출·배포는 승인 후에만 한다.
