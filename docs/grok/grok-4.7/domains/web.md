## 2. 이 모델의 웹 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 폐쇄형 API 모델, 컨텍스트 50만 토큰, 입력 $2 / 출력 $6, 독립 지수 46(`high`와 `xhigh` 동일), 출력 토큰 소비 많음, 이미지 입력, 모델 카드·안전 문서 부재.

- **4.7 자체의 웹 UI 평가는 찾지 못했다.** [미확인] 근거는 이전 세대뿐이다. Grok 4는 프런트엔드 작업에서 여러 번 반복해야 하고 토큰 소비가 많으며 기본 UI와 애니메이션에서 고전했다는 LogRocket 평가가 있었다(옛 모델). 한 모델 목록은 4.3이 창작 코드 생성에서 Design Arena의 UI 컴포넌트·웹사이트 부문 상위라고 서술했고 에이전트 과제 점수는 낮았다고 한다. 한 사용자의 비공식 같은 프롬프트 비교는 4.6이 4.5보다 크게 나아졌다고 판단했다. 어느 것도 4.7의 평가가 아니며 단일 후기·목록 서술이다. [부분: 개인 후기, 다른 버전]
- **디자인 취향에 기대지 않는다.** Grok Build 안내 글은 에이전트가 기본으로는 디자인 감각이 없어 디자인 시스템과 참고 자료 같은 제약이 필요하다고 한다. 기존 UI 체계가 우선하므로(§3.1) 디자인 토큰·컴포넌트 규약을 프롬프트에 주고 스크린샷 대조와 린터·타입체크·테스트 출력으로 판정한다. 타 모델 비교(Kilo Code의 GPT-5.5·Opus 4.7 시험)에서도 첫 시도 결과가 바로 출시할 수준이 아니었다. [부분]
- **스크린샷을 입력으로 줄 수 있다.** 이 모델은 이미지 입력을 지원한다. 참고 스크린샷으로 재현시킬 때 레이아웃·간격·색 재현 정확도를 측정한 자료는 찾지 못했으므로 우리 화면으로 직접 시험한다. [부분/미확인]
- **노력 단계와 비용.** 독립 지수에서 `high`와 `xhigh`가 같은 46이고 `xhigh`는 출력 토큰이 더 많다. 컴포넌트 수정에는 `high` 이하로 시작하고 과제당 입력·출력 토큰과 도구 호출 수를 기록한다. 지수 실행에서 출력 토큰이 비교군 중앙값의 두 배 이상이었다. [부분]
- **Grok Build를 쓰려면 권한 경계를 먼저 둔다.** 파일 쓰기·셸 실행 범위, 작업 디렉터리, 파괴적 명령 차단(권한·훅)을 설정하고 완료 보고는 린터·타입체크·테스트 출력과 `git diff`로 확인한다. 코딩 에이전트 지수 56(4.6보다 +9, 네이티브 하네스 4위라는 독일어 글의 서술, 원문 미확인)은 일반 지표이며 UI 품질이 아니다. [부분/미확인]
- **내장 도구 비용을 확인한다.** 웹 검색과 X 검색은 도구 호출 1,000회당 $5이고 토큰 요금과 별도로 청구된다. 한 응답에 내부 검색이 여러 번 일어나 모두 과금되며 에이전트가 필요 이상으로 검색한다는 보고가 있다. UI 구현에서 최신 라이브러리 문서를 검색시킬 때 호출 횟수 한도를 둔다. [부분]
- **버전·변형을 확인한다.** 출시 후 6주도 안 됐고 직전 3개 버전이 두 달 사이에 나왔다. 프롬프트·템플릿의 회귀 시험을 업데이트 전후에 돌린다.
- **보안·접근성 판단을 맡기지 않는다.** 인가, 입력 검증, 비밀 노출, 접근성 "충족" 여부는 도구 출력과 §3.1 기준으로 사람이 점검한다. API·CSS·브라우저 지원은 공식 문서와 린터·컴파일러 출력으로 확인한다.
- **미공개 소스를 보내기 전에 약관을 확인한다.** 여러 집계가 API 입력·출력을 학습에 쓰지 않고 기본 30일 보관이라고 정리하지만 xAI 약관·DPA 원문은 읽지 못했다. [부분, 충돌] 확인 전에는 비밀·고객 데이터가 담긴 코드를 보내지 않는다(§1.6).
