## 2. 이 모델의 펌웨어 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 폐쇄형 API 모델이라 기기 내 실행 불가, 코딩 에이전트 지수 56(Grok Build 함께, 원문 미확인), 임베디드 평가 없음, 모델 카드 부재, 탈옥 우회 주장, 데이터 정책은 2차 출처.

- **기기 안에서 돌릴 모델이 아니다.** 폐쇄형이며 가중치를 받을 수 없다. 개발 워크스테이션에서 API로 쓰는 보조 도구로만 쓴다. 기기 내 추론이 필요하면 소형 모델 문서(`gemma-4-e2b`, `gemma-4-e4b`)를 본다.
- **펌웨어 코드를 직접 쓰거나 고치게 하지 않는다.** 레지스터 값, 인터럽트, 부트·업데이트 경로, 서명 검증은 환각이 장치 고장이나 보안 구멍이 된다. 임베디드·펌웨어 평가는 찾지 못했다. [미확인] 코딩 에이전트 지수는 장치 쓰기나 실시간 제약을 재지 않는다. 이 영역은 `gemini-4-argon`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol` 문서를 따른다.
- **레지스터·타이밍을 모델의 기억에서 가져오지 않는다.** 환각 값을 확인하지 못했다(hardware.md). 데이터시트·레퍼런스 매뉴얼의 개정판과 페이지를 사람이 확보한 텍스트로 주고, 확인하지 못했으면 값을 쓰지 않는다(§3.1). 내장 웹 검색이 돌려준 URL은 제조사 원문으로 직접 열어 확인한다. [미확인]
- **써도 되는 작업.** UART·RTT 로그 분류, 맵 파일 요약, 컴파일러 경고 그룹화, 변경 이력 요약, 호스트에서 돌리는 테스트 코드(하드웨어 추상화 뒤쪽 로직)의 초안. 입력은 관련 구간만 준다. 출력은 원본 로그·맵 파일과 한 건씩 대조한다.
- **Grok Build 같은 에이전트에 장치 접근을 열어 주지 않는다.** 플래시 소거, 퓨즈·OTP, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금은 사람이 대상 장치와 이미지를 확인한 뒤 실행한다. 프로그래머·시리얼 제어 도구는 읽기 전용부터 연결하고 권한·훅으로 쓰기 명령을 차단한다. 에이전트 루프는 출력 토큰 소비가 많았던 측정이 있어(지수 실행에서 비교군 중앙값의 두 배 이상) 호출 횟수·토큰·시간 한도를 둔다. [부분]
- **탈옥 우회 주장과 모델 카드 부재를 위험으로 기록한다.** 임베디드 보안 분석(익스플로잇 재현, 취약점 탐색)은 모델의 거부 동작에 기대지 않고 격리된 환경과 입력·출력 필터를 별도로 둔다. [부분: 개인 주장]
- **변경 후 검증을 강제한다.** 호스트 단위 테스트와 정적 분석을 직접 돌려 출력을 읽고, 경고를 억제하라는 제안은 따르지 않는다. 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.
- **펌웨어 소스·로그·서명 키·양산 이미지를 API로 보내지 않는다(약관 확인 전).** 여러 집계가 API 입력·출력을 학습에 쓰지 않는다고 하나 원문을 읽지 못했고 ZDR 조건 서술이 갈린다. [부분, 충돌] 서명 키와 디버그 인증 정보는 약관과 무관하게 보내지 않는다(§3.4).
