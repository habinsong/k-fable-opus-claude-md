## 2. 모델 상태 — Grok 4.8 (2026-11-03 기준 미출시로 추정)

### 2.1 확인된 것과 확인되지 않은 것
- **공식 출시 발표를 찾지 못했다.** 이 환경의 검색은 2026-09 말까지의 자료만 보여 주므로 10월 이후 발표가 있었는지는 확인하지 못했다. xAI 공식 문서와 공지 페이지는 열리지 않는다. [미확인]
- **가장 구체적인 서술은 머스크의 2026-09-14 게시물을 전한 2차 보도다.** Grok 4.8은 약 2.5조 파라미터 규모이고 초기 학습을 마무리하며 강화학습 단계로 넘어가는 중이라고 했고, 같은 로드맵이 Grok 5 앞에 모델 두 개(4.8, 이어서 4.9)를 두되 날짜는 주지 않았다. 한 기사는 제목에서 3조 파라미터를 말해 수치가 어긋난다. [부분, 충돌]
- **일정 신뢰도가 낮다.** 머스크가 말한 일정은 반복해서 어긋났다. 4.6은 8월 7일경이라고 했으나 8월 12일에 나왔고, 한 출처는 4.7이 약 2.1조 규모로 지연에 걸렸다고 서술했는데 4.7은 9월 21일에 출시된 것으로 보인다. 날짜 없는 발언을 출시일로 읽지 않는다. [부분]
- **그래서 스펙을 쓰지 않는다.** 가격, 컨텍스트, 크기, 입력 방식, 도구, 안전 문서, 데이터 처리는 모두 [미확인]이다. 이 폴더의 어떤 문장도 Grok 4.8의 성능이나 동작을 단정하지 않는다.
- 출시 전에 모델 ID 문자열을 코드에 박지 않는다. 명명 규칙으로 추정한 ID가 틀릴 수 있다. xAI 공식 문서의 모델 목록에서 확인한 ID만 쓴다.

### 2.2 잠정 규칙: 출시 전까지는 Grok 4.7 문서를 따른다
- 같은 계열의 직전 모델이므로 `grok/grok-4.7/` 문서의 규칙을 그대로 쓴다. 그 규칙은 4.7에 대해 확인된 것(대부분 2차 출처)이며 4.8에서 같다는 보장은 없다.
- 상속 가능성이 높아 보이는 항목(추정): 폐쇄형 API, 낮은 단가 지향, 서버 측 검색 도구(웹·X)와 별도 과금, 노력 단계 변형(`low`/`high`/`xhigh`), 빠른 갱신 주기, 모델 카드·안전 문서 지연 경향. [추정]
- 바뀔 가능성이 큰 항목(추정): 가격과 장문 요금 문턱, 토큰 소비 특성(4.7은 비교군의 두 배 이상), 컨텍스트, 도구 요금, 데이터 정책, 호출 경로(4.7 Fast는 Cursor·Grok Build 전용이라는 서술). [추정]

### 2.3 출시 당일 확인 체크리스트 (공식 문서에서 직접, 하나씩)
1. xAI 공식 공지·문서의 발표일, 모델 ID, 별칭, 변형(Fast 등)과 각 변형의 호출 경로(공개 API, Grok Build, Cursor), 폐기 예정일.
2. 가격: 입력·출력·캐시·장문 요금 문턱과 요율. 서버 측 도구(웹 검색, X 검색, 코드 실행) 호출당 요금.
3. 컨텍스트, 최대 출력, 입력 방식, 추론 노력 지정 방식과 단계별 토큰 소비.
4. 모델 카드·시스템 카드 존재 여부와 내용(거부·탈옥 강건성, 위험 능력 평가). 4.7은 확인되지 않았다.
5. 벤더 벤치마크 공개 여부와 조건(노력 단계, 하네스, 보고 주체). 독립 평가(Artificial Analysis 등)의 지수 버전.
6. 데이터 정책: API 입력·출력의 학습 사용, 보관 기간, ZDR 조건, DPA. 회사명 표기(xAI 또는 SpaceXAI)와 계약 주체.
7. 서버 측 도구의 동작 변화와 출처 URL 반환 방식, 과다 검색 완화 여부.
8. 이행 가이드의 깨지는 변경, 이전 모델(4.5~4.7)의 폐기 일정.
9. 안전장치와 거부 범주, 탈옥 우회 보고.

### 2.4 비판적 점검
- **루머로 도입을 결정하지 않는다.** 출시일·규모·성능 글은 머스크 발언의 재인용, 예측 시장, SEO성 블로그가 대부분이다. 공식 발표 전에는 Grok 4.7과 다른 후보로 평가를 진행한다.
- **큰 파라미터 수가 곧 큰 성능은 아니다.** 규모 수치는 공개되지 않은 모델의 홍보 정보다. 독립 지수와 우리 과제의 실측으로 판단한다. [추정]
- **출시 직후 측정은 얕다.** 4.7도 출시 직후 벤더 벤치마크가 없었고 모델 카드가 확인되지 않았다. 같은 과제·같은 예산으로 직접 비교한다.
- **이 폴더를 출시 후 갱신한다.** 위 체크리스트를 채운 뒤 이 `general.md`의 §2를 실제 사양으로 바꾸고, 8개 분야 문서의 §2에 모델별 운용을 쓴다. 갱신 전의 이 문서는 추정을 단정으로 읽지 않기 위한 장치다.
