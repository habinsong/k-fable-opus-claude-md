## 2. 이 모델의 기술 조사 운용, 그리고 이 모델을 평가할 때 (잠정)
2026-11-03 기준 Grok 4.8의 공식 발표를 찾지 못했다. 모델 상태와 출시일 체크리스트는 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 출시 전에는 `grok/grok-4.7/tech-research.md`를 적용한다.

**이 모델에게 기술 조사를 시킬 때**
- 출시 전에는 이 모델을 쓸 수 없다. 출시 후에도 분류·정리 단계에만 쓰고, 값은 사람이 확보한 1차 자료 텍스트에서 추출하게 하며 원문에 없으면 null로 둔다. 라이선스 호환성, 특허, 규정 적용 여부, 도입 권고는 단정시키지 않는다(§3.2, §3.5).

**Grok 4.8을 도입 후보로 평가할 때 (출시 후)**
- **루머로 평가하지 않는다.** 규모(약 2.5조라는 서술과 3조라는 제목이 어긋남), 출시일(머스크의 날짜 없는 발언, 이전 일정 반복 지연), 성능 우월 주장은 발언의 재인용·예측 시장·SEO성 블로그에서 나왔다. 도입 판단 근거는 공식 문서와 독립 평가가 나온 뒤에만 쓴다. [미확인]
- **문서 공백을 먼저 점검한다.** 4.7은 모델 카드·시스템 카드를 확인하지 못했고 벤더 벤치마크가 공개되지 않았다. 4.8에서 모델 카드, 위험 능력 평가, 거부·탈옥 강건성 문서가 갖춰졌는지 확인하고, 없으면 "자료 미비"로 기록한다. 공급자 실사와 내부 AI 위험 심사에 필요한 문서가 없으면 도입 보류 사유가 된다.
- **총비용은 과제당 비용이다.** 4.7은 단가가 낮았으나 출력 토큰이 비교군 중앙값의 두 배 이상이었고, 프롬프트 20만 토큰부터 요청 전체에 장문 요금, 서버 측 검색 도구는 호출당 별도 과금이었다. 4.8의 요금 구조와 토큰 소비를 확인하고 우리 과제의 토큰·도구 호출 수로 비교한다. 규모가 커지면 단가가 오를 가능성이 있다. [추정]
- **독립 평가의 품질을 본다.** 벤치마크 버전, 노력 단계, 비교군을 명시해 같은 조건의 모델끼리 비교하고 최종 선택은 자체 실측으로 한다. 코딩 에이전트 지수는 하네스와 묶인 값이다.
- **데이터 거버넌스.** API 입력·출력의 학습 사용, 보관, ZDR, DPA가 4.7 시기에는 2차 출처뿐이었고 ZDR 조건 서술이 갈렸다. 4.8 출시 때 xAI 약관·DPA 원문이 공개되는지 확인하고 법무·보안 검토를 거친다. 회사명 표기(xAI, SpaceXAI)와 계약 주체도 확인한다.
- **서버 측 도구의 통제.** 웹·X 검색이 xAI 서버에서 실행되므로 조직의 네트워크 통제·허용 목록이 적용되지 않는다. 데이터 경계가 중요하면 도구를 끄고 하네스가 직접 검색한다.
- **공급 연속성.** 4.5(7월 8일), 4.6(8월 12일), 4.7(9월 21일) 간격이 두 달 안팎이고 예고된 일정이 반복해서 어긋났다. 4.9와 5가 뒤따를 예정이다(`grok-5` 문서). 구버전 폐기 일정, 모델 교체 절차, 폴백 모델, 회귀 시험을 도입 조건으로 둔다.
- **제공자 안전장치와 규정.** 규제 적합성은 모델이 아니라 시스템 전체에 대해 판단하고 모델 카드를 규정 준수의 근거로 쓰지 않는다. 탈옥 우회 주장 사례가 반복돼 입력·출력 필터를 직접 둔다.

**잠정 운용**
- 출시 전 기술 선정은 Grok 4.7과 다른 후보로 진행한다. 공식 발표와 독립 측정이 나오기 전에는 4.8을 도입 후보로 확정하지 않는다.
