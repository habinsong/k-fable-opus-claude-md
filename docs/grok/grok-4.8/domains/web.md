## 2. 이 모델의 웹 작업 운용 (잠정)
2026-11-03 기준 Grok 4.8의 공식 발표를 찾지 못했다. 모델 상태와 출시일 체크리스트는 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 출시 전에는 `grok/grok-4.7/web.md`를 적용한다.

**출시 후 웹 작업에서 따로 확인할 것**
- 4.7에는 웹 UI 생성의 독립 평가가 없었고 이전 세대의 단일 후기만 있었다(Grok 4는 프런트엔드에서 반복이 많고 토큰 소비가 컸다는 평가, 4.3은 디자인 부문 상위라는 목록 서술). 4.8에서도 같은 상황일 가능성이 높다. 같은 UI 과제(기존 컴포넌트 수정, 새 화면, 스크린샷 재현)를 상위 모델과 같은 조건으로 돌려 비교하고 스크린샷 대조와 린터·타입체크·테스트 출력으로 판정한다. [4.7 기준 확인 / 4.8 미확인]
- 4.7 시기에 Grok Build 안내는 에이전트가 기본으로 디자인 감각이 없어 디자인 시스템 같은 제약이 필요하다고 했다. 4.8에서 바뀌었는지 같은 과제로 확인하되, 기존 프로젝트에서는 기존 UI 체계가 우선한다는 규칙(§3.1)을 모델이 바뀌어도 유지한다.
- 토큰 소비: 4.7은 지수 실행에서 출력 토큰이 비교군 중앙값의 두 배 이상이었다. 4.8의 과제당 입력·출력 토큰과 도구 호출 수를 기록해 과제당 비용을 비교한다. 노력 단계별 이득(4.7은 `high`=`xhigh`)도 다시 측정한다.
- 장문 요금 문턱(4.7은 20만 토큰)과 서버 측 도구 요금(웹·X 검색 1,000회당 $5, 4.3·4.5 시기 자료)이 달라졌는지 공식 가격표로 확인한다. 에이전트의 과다 검색 경향이 줄었는지 호출 수로 본다.
- 이미지 입력으로 스크린샷을 재현하는 정확도는 4.7에서도 측정 자료가 없었다. 우리 화면으로 직접 시험한다.
- 호출 경로(공개 API, Grok Build, Cursor)별로 모델 변형과 한도가 달랐다. CI나 제품 코드 생성 파이프라인에 쓸 경로의 약관을 확인한다.
- 서버 쪽 인가, 입력 검증, 비밀 노출 점검은 모델의 자기 판단이 아니라 도구 출력으로 확인한다는 원칙은 그대로다. 데이터 처리 조건(학습 사용, 보관, ZDR)이 공개되기 전에는 비밀·고객 데이터가 담긴 코드를 보내지 않는다.

**잠정 운용**
- 출시 전 평가는 Grok 4.7과 상위 모델을 기준선으로 한다. 공식 발표와 독립 측정이 나오기 전에는 4.8을 웹 작업의 기본으로 지정하지 않는다.
