## 2. 이 모델의 네이티브 작업 운용 (잠정)
2026-11-03 기준 Grok 5의 공식 발표를 찾지 못했다. 모델 상태와 출시일 체크리스트는 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 출시 전에는 `grok/grok-4.7/native.md`를 적용한다(4.8이 먼저 나오면 `grok/grok-4.8/native.md`).

**출시 후 네이티브 작업에서 따로 확인할 것**
- Grok 계열의 코딩 에이전트 지수는 Grok Build 하네스와 묶인 값이었다. 5의 점수를 인용할 때 모델 능력과 하네스 효과를 구분하고, 벤치마크 이름·버전·노력 단계·보고 주체(벤더 또는 독립)를 함께 확인한다.
- C++·Rust·시스템 코드의 언어별 평가는 Grok 계열에 없었다. 출시 후 언어별 점수가 나오는지 확인하고, 없으면 우리 코드베이스의 같은 과제를 sanitizer(ASan·UBSan·TSan)와 테스트를 강제해 상위 모델과 비교한다. 핵심 변경은 상위 모델 문서(`claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon`)를 따른다.
- "AGI" 같은 홍보 표현을 코딩 능력의 근거로 읽지 않는다. 벤치마크 정의와 조건이 공개됐는지 확인한다.
- 모델이 커지면 자율 에이전트로 더 긴 작업을 맡기고 싶어질 수 있다. 에이전트 루프의 안전장치(파괴적 명령 차단, 작업 디렉터리 격리, 시간·토큰 한도, `git diff` 확인, 테스트·경고·sanitizer 설정 변경 감시)는 모델이 바뀌어도 유지하고 억제 지시문을 넣거나 검사를 끄는 제안은 따르지 않는다.
- 노력 단계별 이득과 토큰 소비를 다시 측정한다(4.7은 `high`=`xhigh`이고 출력 토큰이 비교군의 두 배 이상). 긴 디버그 루프의 비용은 과제당 토큰·도구 호출 수로 비교한다. 서버 측 도구의 반복 호출 경향도 호출 수로 확인한다.
- 안전 문서와 탈옥 우회 보고를 확인한다. 보안 분석 같은 위험한 주제에서는 모델의 거부 동작에 기대지 않는다.
- 미공개 소스를 API로 보내기 전에 데이터 처리 조건(학습 사용, 보관, ZDR)을 확인한다.
- 규모와 무관하게 데스크톱 프로그램에 번들할 수 없고 서버 API로만 호출한다.

**잠정 운용**
- 출시 전 네이티브 작업은 현재 확인된 Grok 모델과 상위 모델을 기준선으로 한다. 공식 발표와 독립 측정이 나오기 전에는 Grok 5를 네이티브 작업의 기본으로 지정하지 않는다.
