## 2. 이 모델의 앱 작업 운용 (잠정)
2026-11-03 기준 Grok 5의 공식 발표를 찾지 못했다. 모델 상태와 출시일 체크리스트는 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 출시 전에는 `grok/grok-4.7/app.md`를 적용한다(4.8이 먼저 나오면 `grok/grok-4.8/app.md`).

**출시 후 앱 작업에서 따로 확인할 것**
- 규모(6조라는 안내 글, 2.1조라는 머스크 주장, 모두 미검증)와 무관하게 폐쇄형 API 모델은 기기 안에서 돌릴 수 없다. 앱은 서버를 거쳐 호출하고 API 키는 자체 백엔드에 둔다(§3.1 비밀 규칙). 모바일 온디바이스는 `gemma-4-e2b`, `gemma-4-e4b` 문서를 본다.
- 데이터 정책: 학습 사용·보관·ZDR·DPA 정보가 4.7 시기에는 2차 출처뿐이었다. 5 출시 때 xAI 약관·DPA 원문이 공개되는지 확인하고 앱의 개인정보 선언(Apple 개인정보 영양 표시, Google Play 데이터 보안 양식)과 처리방침을 갱신한다. 회사명 표기(xAI, SpaceXAI)와 계약 주체도 확인한다. 아동·민감정보는 확인 전에 보내지 않는다.
- 비용: 모델이 커질수록 단가와 지연이 오를 수 있다(추정). 사용자당 한도, `max_tokens`, 요청 빈도 제한을 서버에 두고 실제 청구서로 확인한다. 장문 요금 문턱과 서버 측 도구의 호출당 과금도 앱 비용에 넣는다. 단순 질의는 더 싼 모델로 라우팅한다.
- 지연: 큰 모델의 응답 지연이 모바일 UX에 맞는지 측정한다. 스트리밍, 타임아웃, 재시도, 폴백 UX를 설계한다.
- 이미지·음성 입력이 있으면 사용자 개인정보가 서버로 가므로 약관 확인과 사용자 동의 없이 보내지 않는다.
- 안전 문서와 거부 동작을 확인하되 앱 수준의 입력 필터, 출력 검증, 위험 기능의 권한 제한은 모델과 무관하게 둔다.
- 모델 교체를 앱 업데이트 없이 할 수 있게 설계한다. 서버 쪽 모델 설정, 폴백 모델, 회귀 시험, 기능 플래그를 둔다.
- 모바일(Kotlin·Swift) 코드 평가는 Grok 계열에 없었다. 출시 후 언어별 평가가 있는지 확인하고, 없으면 컴파일·린트·단위 테스트·UI 테스트로 검증한다.

**잠정 운용**
- 출시 전 앱 내장 AI 기능은 현재 확인된 Grok 모델이나 다른 후보로 구현하되 모델 이름을 코드에 박지 않는다. 공식 발표와 독립 측정이 나오기 전에는 Grok 5를 기본 모델로 지정하지 않는다.
