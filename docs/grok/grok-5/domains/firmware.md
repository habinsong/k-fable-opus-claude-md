## 2. 이 모델의 펌웨어 작업 운용 (잠정)
2026-11-03 기준 Grok 5의 공식 발표를 찾지 못했다. 모델 상태와 출시일 체크리스트는 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 출시 전에는 `grok/grok-4.7/firmware.md`를 적용한다(4.8이 먼저 나오면 `grok/grok-4.8/firmware.md`).

**출시 후 펌웨어 작업에서 따로 확인할 것**
- 규모와 무관하게 폐쇄형 API 모델은 기기 안에서 돌리는 모델이 아니다. 개발 워크스테이션의 API 보조 도구로만 쓴다. 기기 내 추론이 필요하면 소형 모델 문서(`gemma-4-e2b`, `gemma-4-e4b`)를 본다.
- Grok 계열에는 임베디드·펌웨어 평가가 없었다. 출시 후 평가가 나오는지 확인하고, 없으면 펌웨어 코드를 직접 쓰거나 고치게 하지 않는 규칙을 유지한다. 이 영역은 상위 모델 문서(`gemini-4-argon`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol`)를 따른다.
- 환각 값이 공개되기 전까지 레지스터·타이밍을 모델의 기억에서 가져오지 않는다. 데이터시트·레퍼런스 매뉴얼의 개정판과 페이지를 사람이 확보한 텍스트로 주고, 내장 검색이 돌려준 URL은 제조사 원문으로 직접 열어 확인한다(§3.1).
- 더 큰 모델에 장시간 자율 에이전트를 맡기고 싶어질 수 있어도 장치 접근을 열어 주지 않는다. 플래시 소거, 퓨즈·OTP, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금은 사람이 확인한 뒤 실행하고, 프로그래머·시리얼 제어 도구는 읽기 전용부터 연결하며 권한·훅으로 쓰기 명령을 차단한다.
- 에이전트 루프의 호출 횟수·토큰·시간 한도를 5의 토큰 소비 특성에 맞춰 다시 정한다.
- 안전 문서와 탈옥 우회 보고를 확인한다. 임베디드 보안 분석은 모델의 거부 동작에 기대지 않고 격리 환경과 입력·출력 필터를 별도로 둔다.
- 펌웨어 소스·로그·서명 키·양산 이미지는 데이터 처리 조건이 공개되고 법무가 검토하기 전에는 API로 보내지 않는다. 서명 키와 디버그 인증 정보는 약관과 무관하게 보내지 않는다(§3.4).
- 변경 후 검증을 강제한다. 호스트 단위 테스트와 정적 분석 출력을 직접 읽고 경고를 억제하라는 제안은 따르지 않는다. 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.

**잠정 운용**
- 출시 전 펌웨어 작업은 상위 모델을 기준선으로 하고 Grok 계열은 로그 분류, 맵 파일 요약, 호스트 테스트 초안 같은 보조에만 쓴다. 공식 발표와 독립 측정이 나오기 전에는 Grok 5를 펌웨어 작업의 기본으로 지정하지 않는다.
