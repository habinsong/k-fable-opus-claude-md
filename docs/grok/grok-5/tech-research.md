## 2. 이 모델의 기술 조사 운용, 그리고 이 모델을 평가할 때 (잠정)
2026-11-03 기준 Grok 5의 공식 발표를 찾지 못했다. 모델 상태와 출시일 체크리스트는 같은 폴더의 `general.md` §2를 따른다. 출시 전에는 `grok/grok-4.7/tech-research.md`를 적용한다(4.8이 먼저 나오면 `grok/grok-4.8/tech-research.md`).

**이 모델에게 기술 조사를 시킬 때**
- 출시 전에는 이 모델을 쓸 수 없다. 출시 후에도 분류·정리 단계에만 쓰고, 값은 사람이 확보한 1차 자료 텍스트에서 추출하게 하며 원문에 없으면 null로 둔다. 라이선스 호환성, 특허, 규정 적용 여부, 도입 권고는 단정시키지 않는다(§3.2, §3.5).

**Grok 5를 도입 후보로 평가할 때 (출시 후)**
- **루머와 홍보로 평가하지 않는다.** 출시일(Q1 목표 미달, Q2 언급, "올해 안" 발언), 규모(6조, 2.1조), "AGI" 주장은 머스크 발언의 재인용·안내 글·예측 시장에서 나왔고 이전 일정이 모두 어긋났다. 도입 판단 근거는 공식 문서와 독립 평가가 나온 뒤에만 쓴다. [미확인]
- **문서 공백과 안전 평가를 먼저 점검한다.** 4.7은 모델 카드·시스템 카드를 확인하지 못했고 벤더 벤치마크가 공개되지 않았으며 2025년 Grok 4는 시스템 카드와 위험 능력 평가 결과 미공개로 비판받았다. 5에서 모델 카드, 위험 능력 평가, 거부·탈옥 강건성 문서가 갖춰졌는지 확인하고, 없으면 "자료 미비"로 기록한다. 규모가 큰 모델일수록 위험 평가 요구가 커지므로 공급자 실사와 내부 AI 위험 심사에 필요한 문서가 없으면 도입 보류 사유가 된다. [부분/추정]
- **총비용은 과제당 비용이다.** 4.7은 출력 토큰이 비교군의 두 배 이상이었고 20만 토큰부터 장문 요금, 서버 측 검색 도구는 호출당 별도 과금이었다. 5의 요금 구조와 토큰 소비를 확인하고 우리 과제의 토큰·도구 호출 수로 비교한다. 큰 모델의 지연이 업무 흐름에 맞는지도 측정한다. [추정]
- **독립 평가의 품질을 본다.** 지수 버전, 노력 단계, 비교군을 명시해 같은 조건의 모델끼리 비교하고 최종 선택은 자체 실측으로 한다. 규모가 커진 만큼 성능이 오른다는 가정은 하지 않는다.
- **데이터 거버넌스.** API 입력·출력의 학습 사용, 보관, ZDR, DPA는 Grok 계열에서 2차 출처뿐이었다. 5 출시 때 xAI 약관·DPA 원문이 공개되는지 확인하고 법무·보안 검토를 거친다. 회사명 표기(xAI, SpaceXAI)와 계약 주체도 확인한다.
- **서버 측 도구의 통제.** 웹·X 검색이 xAI 서버에서 실행되므로 조직의 네트워크 통제·허용 목록이 적용되지 않는다. 데이터 경계가 중요하면 도구를 끄고 하네스가 직접 검색한다.
- **공급 연속성.** 일정이 반복해서 어긋났고 4.8, 4.9가 먼저 나올 예정이다(`grok-4.8` 문서). 구버전 폐기 일정, 모델 교체 절차, 폴백 모델, 회귀 시험을 도입 조건으로 둔다.
- **제공자 안전장치와 규정.** 규제 적합성은 모델이 아니라 시스템 전체에 대해 판단하고 모델 카드를 규정 준수의 근거로 쓰지 않는다. 탈옥 우회 주장 사례가 반복돼 입력·출력 필터를 직접 둔다.

**잠정 운용**
- 출시 전 기술 선정은 현재 확인된 Grok 모델과 다른 후보로 진행한다. 공식 발표와 독립 측정이 나오기 전에는 Grok 5를 도입 후보로 확정하지 않는다.
