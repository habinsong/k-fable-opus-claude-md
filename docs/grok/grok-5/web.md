## 2. 이 모델의 웹 작업 운용 (잠정)
2026-11-03 기준 Grok 5의 공식 발표를 찾지 못했다. 모델 상태와 출시일 체크리스트는 같은 폴더의 `general.md` §2를 따른다. 출시 전에는 `grok/grok-4.7/web.md`를 적용한다(4.8이 먼저 나오면 `grok/grok-4.8/web.md`).

**출시 후 웹 작업에서 따로 확인할 것**
- Grok 계열은 웹 UI 생성의 독립 평가가 부족했다(4.7은 없음, 이전 세대는 단일 후기와 목록 서술). 규모가 커져도 같은 상황일 수 있다. 같은 UI 과제(기존 컴포넌트 수정, 새 화면, 스크린샷 재현)를 상위 모델과 같은 조건으로 돌려 비교하고 스크린샷 대조와 린터·타입체크·테스트 출력으로 판정한다. 기존 UI 체계가 우선한다는 규칙(§3.1)은 유지한다.
- 모델이 커지면 응답이 느리고 비싸질 수 있다. 컴포넌트 수정 한 건당 지연, 입력·출력 토큰, 도구 호출 수를 기록하고, 단순 수정에는 더 싼 모델을 쓰는 라우팅을 시험한다. [추정]
- 4.7의 토큰 소비(비교군 중앙값의 두 배 이상), 장문 요금 문턱(20만 토큰), 서버 측 도구 요금과 과다 검색 경향이 5에서 달라졌는지 공식 문서와 호출 수로 확인한다.
- 입력 방식에 이미지·영상이 늘어나면 스크린샷 재현 정확도를 우리 화면으로 직접 시험한다.
- 호출 경로(공개 API, Grok Build, Cursor)별 변형과 한도를 확인하고 CI나 제품 코드 생성 파이프라인에 쓸 경로의 약관을 읽는다.
- 서버 쪽 인가, 입력 검증, 비밀 노출 점검은 모델의 자기 판단이 아니라 도구 출력으로 확인한다는 원칙은 그대로다. 데이터 처리 조건(학습 사용, 보관, ZDR)이 공개되기 전에는 비밀·고객 데이터가 담긴 코드를 보내지 않는다.

**잠정 운용**
- 출시 전 평가는 현재 확인된 Grok 모델과 상위 모델을 기준선으로 한다. 공식 발표와 독립 측정이 나오기 전에는 Grok 5를 웹 작업의 기본으로 지정하지 않는다.
