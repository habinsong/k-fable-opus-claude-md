## 2. 이 모델의 펌웨어 작업 운용
모델 전체 특성은 같은 폴더의 `general.md` §2를 따른다. 요약: 744B급 MoE라 기기 내 실행 불가, 터미널·에이전트 지표는 벤더 보고, 임베디드 평가 없음, 환각률 값 미확인, 데이터 처리 조건 미확인.

- **기기 안에서 돌릴 모델이 아니다.** 총 약 744B(활성 약 40B)라 MCU는 물론 임베디드 리눅스 SBC에도 올릴 수 없다. 개발 워크스테이션에서 API로 쓰는 보조 도구로만 쓴다. 기기 내 추론이 필요하면 소형 모델 문서(`gemma-4-e2b`, `gemma-4-e4b`)를 본다. [부분/추정]
- **펌웨어 코드를 직접 쓰거나 고치게 하지 않는다.** 레지스터 값, 인터럽트, 부트·업데이트 경로, 서명 검증은 환각이 장치 고장이나 보안 구멍이 된다. 임베디드·펌웨어 평가는 찾지 못했다. [미확인] 터미널 작업 점수(벤더 보고)는 장치 쓰기나 실시간 제약과 무관하다. 이 영역은 `gemini-4-argon`, `claude/sonnet-5.5` 이상, `gpt-6.1-sol` 문서를 따른다.
- **레지스터·타이밍을 모델의 기억에서 가져오지 않는다.** 환각률의 독립 값이 확인되지 않았다(hardware.md). 데이터시트·레퍼런스 매뉴얼의 개정판과 페이지를 사람이 확보한 텍스트로 주고, 확인하지 못했으면 값을 쓰지 않는다(§3.1). [미확인]
- **써도 되는 작업.** UART·RTT 로그 분류, 맵 파일 요약, 컴파일러 경고 그룹화, 변경 이력 요약, 호스트에서 돌리는 테스트 코드(하드웨어 추상화 뒤쪽 로직)의 초안. 입력은 관련 구간만 준다. 출력은 원본 로그·맵 파일과 한 건씩 대조한다.
- **에이전트 루프에 장치 접근을 열어 주지 않는다.** 긴 터미널 작업에 이 모델을 쓰자는 조언이 있으나 현장 시험이 아닌 권고다. [부분] 플래시 소거, 퓨즈·OTP, 보호 비트, 부트로더 덮어쓰기, 디버그 포트 잠금은 사람이 대상 장치와 이미지를 확인한 뒤 실행한다. 프로그래머·시리얼 제어 도구를 열어 줄 때는 읽기 전용 도구부터 연결하고, 권한·훅으로 쓰기 명령을 차단한다.
- **변경 후 검증을 강제한다.** 호스트 단위 테스트와 정적 분석을 직접 돌려 출력을 읽고, 경고를 억제하라는 제안은 따르지 않는다. 실제 보드에서 확인하지 못했으면 "하드웨어 미검증"이라고 쓴다.
- **펌웨어 소스·로그·서명 키·양산 이미지를 API로 보내지 않는다(약관 확인 전).** 데이터 처리 조건을 찾지 못했다. [미확인] 서명 키와 디버그 인증 정보는 약관과 무관하게 보내지 않는다(§3.4).

## 4. 근거와 한계
- 규모·접근 방식·분업 조언: [Morph: GLM-5.3 대 Claude](https://www.morphllm.com/glm-5-3-vs-claude), [EvoLink: GLM-5.3 릴리스](https://evolink.ai/blog/glm-5-3-release) (스니펫만) [부분]
