## 2. 이 모델의 네이티브 작업 운용 (잠정)
2026-11-03 기준 GLM-5.5의 공식 발표를 찾지 못했다. 모델 상태와 출시일 체크리스트는 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 출시 전에는 `glm/glm-5.3/native.md`를 적용한다.

**출시 후 네이티브 작업에서 따로 확인할 것**
- 유출 보도는 장시간 자율 코딩 에이전트에 초점을 맞춘다고 한다. 사실이면 에이전트 루프의 안전장치가 더 중요하다. 파괴적 명령 차단(권한·훅), 작업 디렉터리 격리, 시간·토큰 한도를 먼저 두고, 완료 보고는 빌드·테스트·sanitizer 출력과 `git diff`로 확인한다. [미확인: 유출]
- GLM-5.3의 터미널·에이전트 점수는 벤더 보고였고 벤치마크 버전(Terminal-Bench 2.1 대 3.0)이 섞여 있었다. 5.5의 점수를 인용할 때 벤치마크 이름과 버전, 하네스, 보고 주체(벤더 또는 독립)를 함께 확인한다.
- GLM-5.3에는 C++·Rust·시스템 코드의 언어별 평가가 없었다. 출시 후 언어별 점수가 나오는지 확인하고, 없으면 우리 코드베이스의 같은 과제를 sanitizer(ASan·UBSan·TSan)와 테스트를 강제해 상위 모델과 비교한다. 핵심 변경은 상위 모델 문서(`claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon`)를 따른다.
- 추론 토큰이 출력 한도에 포함되는지, 병렬 도구 호출이 호출 경로마다 다른지 사용하는 경로에서 시험한다. 빌드·테스트 도구를 병렬로 부르는 하네스는 특히 확인한다.
- 환각률과 도구 호출 오류율의 독립 측정이 나오는지 확인한다. 나오기 전에는 시스템 API 시그니처와 표준 라이브러리 세부를 공식 문서와 컴파일러로 확인한다.
- 크기가 공개되면 데스크톱 프로그램에 번들할 수 있는지(대부분 불가) 확인하고, 자체 호스팅 시 라이선스와 공식 저장소 출처를 확인한다.
- 미공개 소스를 API로 보내기 전에 데이터 처리 조건과 약관을 확인한다.

**잠정 운용**
- 출시 전 네이티브 작업은 GLM-5.3과 상위 모델을 기준선으로 한다. 공식 발표와 독립 측정이 나오기 전에는 5.5를 네이티브 작업의 기본으로 지정하지 않는다.
