## 2. 이 모델의 하드웨어 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 총 약 320B·활성 약 18B MoE, 이미지 입력(영상은 출처 충돌), 차트·문서 이해 지표는 벤더 보고, 하드웨어 설계 평가 없음, 데이터 처리 조건 미확인.

- **설계 판단에 쓰지 않는다.** 핀 배치, 정격, 타이밍, 수식은 틀리면 보드가 망가지거나 위험해진다. 이 모델의 회로·PCB·HDL 평가는 찾지 못했다. [미확인] 종합 지수나 코딩 점수가 높아도 회로 설계 정확도를 대표하지 않는다. 설계는 `gemini-4-argon`, `claude/opus-5.5`, `gpt-6.1-sol` 같은 상위 모델 문서를 따르고, 그 결과도 데이터시트 원문과 도구 계산으로 확인한다.
- **값 회상을 믿지 않는다.** 환각률·사실 정확도의 독립 측정이 없다. [미확인] 부품 번호, 핀 번호, 레지스터 주소, 정격을 모델 기억에서 가져오게 하지 않는다. 값은 사람이 확보한 데이터시트 텍스트에서만 꺼내게 하고, 값마다 문서명·개정판·페이지를 같이 받아 원문 PDF와 한 건씩 대조한다. 원문에 없으면 null이다(§3.1).
- **데이터시트 표와 그림을 이미지로 읽히는 용도는 직접 시험한다.** 이 모델은 차트·문서 이해(OfficeQA Pro, CharXiv, Chartography with Tools)에서 강점이 있다고 Z.ai 보고를 옮긴 집계가 말한다. 그러나 이는 일반 차트·문서 과제이고 데이터시트의 작은 글씨, 핀 표, 타이밍 다이어그램, 회로도의 정확도를 측정한 자료는 찾지 못했다. 제3자 비전 평가는 종합 66.3%(33개 중 22위)로 중간이었다. [부분/미확인] 이미지에서 읽은 값은 원문 텍스트·넷리스트·ERC 보고서와 반드시 대조하고, 읽기 어려운 부분은 추측하지 말고 "판독 불가"로 표시하게 한다.
- **써도 되는 작업.** BOM 정규화, 부품 번호 목록 변환, 시험 로그 분류, 데이터시트 텍스트에서 정해진 필드 추출, 측정·변환 스크립트(파이썬)의 초안. 스크립트는 알려진 값을 넣어 실행해 확인한다. 가격이 낮아 대량 정리에 유리하나 호출 경로마다 가격·한도가 다르다(README.md가 안내하는 개요·운용 문서.2). [부분]
- **계산은 도구로 한다.** 전류 예산, 분압, 필터, 열 계산은 스크립트·시뮬레이터 출력으로 확인하고 식과 가정을 남긴다. 추론 모드로 낸 풀이도 마찬가지다.
- **컨텍스트가 크다고 데이터시트를 통째로 넣지 않는다.** 최대 100만 토큰이지만 정확도는 보장되지 않는다. 필요한 장과 표만 넣고 PDF 표를 텍스트로 변환한 결과도 원문과 대조한다. [추정]
- **미공개 설계 자료를 API로 보내지 않는다(약관 확인 전).** 데이터 처리 위치·보관·학습 사용 조건을 찾지 못했다. [미확인] 회로도·레이아웃·펌웨어 이미지·부품 공급 정보는 영업비밀이므로 원문 약관을 읽고 승인받은 뒤에만 보낸다. 제3자 호스트를 거치면 그쪽 약관도 확인한다.
- **인체·화재 위험 설계는 "안전하다"고 단정하지 않는다.** 고전압·대전류·배터리·모터는 사람의 검토를 요청한다.
