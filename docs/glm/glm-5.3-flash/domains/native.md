## 2. 이 모델의 네이티브 작업 운용
모델 전체 특성은 상위 폴더의 [`README.md`](../README.md)가 안내하는 개요·운용·비판 문서를 따른다. 요약: 총 약 320B·활성 약 18B MoE, 터미널·에이전트 수치는 벤더 보고, C/C++·Rust 평가 없음, 독립 시험은 소규모 과제뿐.

**개발 보조로 쓸 때**
- **벤더 수치는 플래그십보다 낮고 독립 확인이 없다.** Terminal-Bench 2.1 84.3, DeepSWE v1.1 63.4가 Z.ai 보고를 옮긴 집계에 있다(플래그십은 88.2와 66.9로 보도). 같은 출처가 이 모델이 두 지표에서 선두가 아니라고 밝힌다. 벤치마크 버전이 섞여 있어 다른 모델과 직접 비교하지 않는다. [부분: 벤더 주장]
- **C++·Rust·시스템 코드의 언어별 평가는 찾지 못했다.** [미확인] 독립 시험은 SVG 생성, 코딩 게임, 작은 함수 하나였고, 한 리뷰는 이를 근거로 "통제된 API 시험 대상, 무조건적 운영 권장은 아님"이라고 결론냈다. [부분: 개인 후기] 메모리 관리, 동시성, 수명, ABI는 문법이 맞아도 틀리기 쉬우므로 핵심 변경에는 쓰지 않고, 쓴다면 sanitizer(ASan·UBSan·TSan)와 테스트를 지시문으로 강제한다. 핵심 변경은 `claude/sonnet-5.5` 이상, `gpt-6.1-sol`, `gemini-4-argon` 문서를 따른다.
- **플래그십과의 격차는 직접 잰다.** "플래그십 지능의 대부분을 활성 파라미터 절반 이하로 유지"한다는 서술은 중개·블로그 글이고 측정 조건이 불명확하다. 싼 모델로 시작하고 막히면 올리는 구성이라면 `glm-5.3` 문서의 모델로 폴백하는 기준(같은 실패 3회, 테스트 미통과)을 정해 둔다. [부분]
- **긴 컨텍스트 주장은 시험해서 쓴다.** 하이브리드 희소·선형 어텐션으로 긴 컨텍스트를 정확하게 유지한다는 설명은 벤더 서술이고, 장문 지표 AA-LCR 80.0%를 인용한 집계가 있으나 직접 확인하지 못했다. 한 개인은 로컬에서 여러 날 이어진 개발 루프에서 컨텍스트 붕괴가 눈에 띄지 않았다고 했다(일화). [미확인/부분: 개인 후기] 그래도 관련 함수·호출부·오류 메시지·빌드 설정만 준다.
- **병렬 도구 호출은 경로마다 다르다.** 한 호스트는 자사 서빙에서 `parallel_tool_calls: false`를 강제하고 Z.ai 경로는 강제하지 않는다. 빌드·테스트 도구를 병렬로 부르는 하네스는 사용하는 경로에서 시험한다. [부분]
- **작업 완료 서술을 믿지 않는다.** 환각률·도구 호출 오류율의 독립 측정이 없다. [미확인] 빌드·테스트·sanitizer 출력을 직접 읽고, 테스트·경고·sanitizer 설정이 바뀌었는지 `git diff`로 확인한다. 억제 지시문을 넣거나 검사를 끄는 제안은 따르지 않는다.
- **추론 토큰이 출력 한도에 들어간다**는 서술이 있다. 긴 추론 뒤 코드가 잘리지 않도록 `max_tokens`를 넉넉히 잡고 응답이 중간에 끊겼는지 확인한다. [부분]
- **미공개 소스를 API로 보내기 전에 약관을 확인한다.** 데이터 처리 조건을 찾지 못했다. [미확인] 확인 전에는 비밀·고객 코드를 보내지 않는다(§1.6).

**애플리케이션에 내장할 때**
- **모델은 서버 API로 호출한다.** FP8 가중치만 약 306 GiB라 데스크톱 프로그램에 번들할 수 없다. 클라이언트에 API 키를 두지 않고 자체 백엔드를 거친다. 모델 출력으로 만든 경로·명령·코드를 그대로 실행하지 않으며 파서·역직렬화 코드는 퍼징 대상으로 본다(§3.1).
- **직접 호스팅하면 공식 저장소에서만 가중치를 받는다.** 제3자 재업로드 가중치와 실행 명령은 쓰지 않고 해시를 확인하며 LICENSE(MIT)와 NOTICE를 지킨다(README.md가 안내하는 개요·운용 문서.4). 오프라인 요구가 있으면 소형 모델 문서(`gemma-4-e4b`, `qwen3.6-27b` 등)를 본다.
