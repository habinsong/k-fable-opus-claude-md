# 근거와 출처

> 이 문서는 사람이 읽는 조사 기록이다. 엔진의 규칙마다 붙은 근거 등급(A/B/C)이 어디서 왔는지, 무엇을 직접 확인했고 무엇을 요약으로만 봤는지 적는다.

## 읽는 법

- **근거 등급** (규칙의 가중치 계수: A 1.0, B 0.75, C 0.45)
  - A: 누가 봐도 대화 껍데기인 잔재이거나, 서로 독립된 정량 근거가 둘 이상인 것
  - B: 정량 근거 하나이거나 편집자 합의(위키백과 AI Cleanup 등)와 실무 도구 둘 이상이 일치하는 것
  - C: 실무자 목록이나 일화뿐인 것
- **확인 수준**: **[확인]** 원문 페이지를 직접 읽음 / **[부분]** 검색 요약이나 2차 보도만 봄 / **[미확인]** / **[추정]** 일반 언어 지식에서 끌어냄.
- 이 환경에서는 `en.wikipedia.org`, `arxiv.org`(일부 미러 포함), `openrouter.ai`, `artificialanalysis.ai`, `cavac.at`, `wikiless.lunar.icu` 등이 열리지 않았다(DNS 해석 실패). 그래서 논문과 위키 원문은 대부분 검색 요약으로만 봤고 **[부분]**이다. 숫자를 인용할 때는 원문을 다시 확인한다.

## 1. 영어 어휘

| 주장 | 출처 | 수준 |
|---|---|---|
| PubMed 초록에서 LLM 이후 delves, showcasing, underscores 같은 낱말이 급증했고, 2024년 초록의 최소 10%가 LLM 처리를 거쳤다고 추정 | Kobak 외, arXiv:2406.07016 | [부분] |
| 'showcasing' 약 9.2배, 'delves' 약 25.2배 | 같은 논문에 대한 검색 요약 (원문 대조 못함) | [부분] |
| 34개 언어에서 AI 과다 어휘가 늘었고, 눈에 띄는 표지는 알려진 뒤 줄고 다른 낱말이 늘었다 | Juzek 외, arXiv:2605.25358 | [부분] |
| 모델이 달라지면 선호 구문이 다르다. 한 모델 목록이 다른 모델에 옮겨지지 않을 수 있다 | UMD 연구를 Pangram이 인용, 검색 요약 | [부분] |
| 2025~2026 챗봇 글에서 사람 글의 2배 이상 빈도인 구가 약 1만 3천 개. Claude Opus 5.5의 최상위 tell은 'dependable'(23배), 'this matters'(116배) | Graphite 보고를 다룬 기사(2026-10). 방법론 비판 있음(소규모 컨설팅사, 탐지기 오류율) | [부분], 신뢰 낮음 |
| 'load-bearing', 'smoke test', 'The honest answer:', 'Sit with that', 'quietly' 같은 낱말이 최근 어시스턴트 글에서 자주 보인다 | 커뮤니티 스레드와 블로그 | [추정]. 그래서 C등급, 군집일 때만 센다 |

**엔진에 반영한 방식**: delve, tapestry, showcase, underscore, intricate, pivotal, meticulous, commendable, notably, multifaceted만 A. 흔한 낱말(robust, seamless, vibrant 등)은 C이고 400자 안에 비슷한 낱말이 더 있을 때만 센다. 한 낱말만으로는 어떤 판단도 하지 않는다.

## 2. 영어 구조

| 주장 | 출처 | 수준 |
|---|---|---|
| 부정 병렬("It's not X, it's Y")은 AI 글의 대표 징후이지만 사람도 쓴다. 단독으로는 약한 증거 | 위키백과 'Signs of AI writing' 목차와 토크 페이지 요약 | [부분] |
| "not only X but also Y"가 사람보다 약 3배 | Pangram 수치를 인용한 2차 글 | [부분] |
| 3항 나열, 섹션 끝 요약, 홍보성 문구("stands as a testament", "plays a vital role", "underscores its importance"), 막연한 출처("experts say") | 위키백과 AI Cleanup 안내를 보도한 글 | [부분] |
| -ing 꼬리절("highlighting", "underscoring", "showcasing", "ensuring", "reflecting", "contributing to")이 무생물 주어와 함께 쓰이면 더 강한 신호 | 위키백과 'Signs of AI writing' 검색 요약 | [부분] |
| 'serves as', 'stands as', 'boasts'로 be 동사를 피하는 습관 | 편집자 가이드와 도구 다수. 빈도 수치는 출처 없음 | [부분] |
| 챗봇 잔재("Certainly!", "I hope this helps", "As an AI language model", "as of my last knowledge update") | 위키백과 catchphrases 미러, 여러 도구 | [부분]. 잔재 자체는 A |
| 누출된 표지: `oaicite`, `contentReference`, `turn0search`, `utm_source=chatgpt.com` | 위키백과 AI Cleanup 안내를 다룬 글 | [부분] |
| 서식: 불릿마다 굵은 라벨, 이모지 불릿, 짧은 글의 소제목 | tropes.fyi, 위키백과 요약 | [부분] |

**엔진에 반영한 방식**: 부정 병렬 정규식 7종(A 2, B 5), 분사 꼬리(B, strong에서만 삭제하고 숫자·고유명사가 있으면 건드리지 않음), be 동사 회피(B), 맺음 요약(B, 문단 첫머리·마지막 문장), 인용 표시가 뒤따르는 출처 서술은 센다 하지 않음.

## 3. 한국어

| 주장 | 출처 | 수준 |
|---|---|---|
| 한국어 학술 초록에서 한자어 학술 동사(시사하다, 규명하다, 기여하다 등) 12개의 합이 2018년 초록당 0.36에서 2026년 1.11로 약 3배, 고유어 표현 10개는 2022년 이후 감소. 신호는 2024년 하반기에 시작. 모델 사용은 가설 | arXiv:2609.07447 (프리프린트) | [부분] |
| 영어 뉴스 기반 목록과 한국어 신호는 거의 겹치지 않는다 | 같은 논문 요약 | [부분] |
| 부정 대구 후보: 1천자당 사람 0.6, AI 5.8. 당위 서술 AI가 3.7배. '~적' 체인 1.6배. 문장당 쉼표 사람 1.13, AI 2.56(수필). '~한다' 종결 편중 1.8배. **'~를 통해'와 '~것이다'는 사람이 더 많이 썼다** | im-not-ai 저자의 자체 보고(사람 60편 대 AI 60편, 편집된 전문 산문). 이 저장소 `scripts/ko_style_probe.py`와 `docs/_common/korean-writing/empirical-validation.md`에 기록 | [부분], 자체 보고 |
| 번역투(~에 대해, ~에 있어서, ~에 의해, 이중 피동, 가지고 있다), 상투 관용구(결론적으로, 시사하는 바가 크다, 주목할 만하다, 혁신적인), '첫째/둘째/셋째' 기계 나열, 과한 불릿·이모지 | 한국어 윤문 플러그인 README 다수. 실험 검증 없음 | [추정] |
| "~를 넘어 ~하다" 틀, 장단점을 나란히 늘어놓는 습관, 숫자 없는 칭찬 | 한국어 윤문 검증기 문서의 설명 | [추정] |
| 한국어 AI 글 판별 연구 | KatFishNet(ACL 2025; 띄어쓰기·품사 조합·문장부호), LREAD(arXiv:2601.19913; 사람 판별 루브릭에 어휘 격식 이동 포함) | [부분] |
| 도치·대구 남용 | 공개 근거를 찾지 못함. 사용자 관찰에서 나온 규칙 | [미확인] |

**엔진에 반영한 방식**: 실측이 있는 신호(부정 대구, 당위, 쉼표 밀도, '~한다' 편중)에 가중치를 주고, 사람이 더 많이 쓴 '~를 통해', '~것이다'는 **점수에서 뺐다**(참고로만 표시). 번역투는 C등급이고 2~10회 이상 반복될 때만 센다. 도치·분열문은 C등급이고 가중치가 낮다.

## 4. 점수와 가중치 설계

| 참고 | 내용 | 수준 |
|---|---|---|
| EQ-Bench Slop Score | 낱말 60%, "not X but Y" 대조 25%, 3-gram 15%를 합친다. '과다 사용 패턴을 찾을 뿐 AI와 사람을 가르는 것이 아니다'라고 밝힌다 | [부분] |
| Antislop (arXiv:2510.15061) | 사람 글보다 훨씬 자주 나오는 패턴 8천여 개를 억제하는 샘플러. 빈도비 접근 | [부분] |
| patina(devswha) | 자체 보정: 편집 핫스팟 포착률 67.3%(n=600), 사람 대조군 오탐률 16.0%(95% CI 11.6~21.7, n=200). 점수는 '편집 신호'일 뿐 저자 증명이 아니라고 명시 | [확인] README 원문, 자체 보고 |
| avoid-ai-writing(conorbronsdon) | 어휘 3단계, 장황함 교정(Tier 1B)은 가중치를 낮춰 AI 쪽으로 몰리지 않게 함, 인용된 AI 견본을 제외하는 ignore 표지, 근거 없는 주장은 지어내지 않고 표시, 보존 검증은 의미 검증이 아님 | [확인] README 원문 |
| 문장 길이 변동(burstiness) | 1:1 대응 비교에서 AUROC 0.521로 약한 신호이고 평균 문장 길이와 섞인다 | [부분] |
| AI 탐지기의 편향 | TOEFL 에세이 91편에서 일곱 탐지기 평균 오탐 61.3% (Liang 외 2023) | [부분] |
| AI 편집의 흔적 | AI가 쓴 글과 AI가 고친 글은 지문이 다르고, 상당히 AI에게 편집받은 초안은 작성자 본래 문체보다 AI 문체에 가깝다 (arXiv:2608.27855, UMD ACL 2026) | [부분] |

**엔진에 반영한 방식**: ① 지수는 '밀도'이지 확률이 아니다. ② 장황한 구절 단순화는 가중치 0.3으로 낮췄다. ③ 문장 길이 변동은 점수에 넣지 않고 `metrics`에만 둔다. ④ 인용 블록, 코드, URL, `ai-smell:ignore-start/end` 구간은 보지 않는다. ⑤ 고친 뒤 새 신호가 생겼는지 `verify`가 확인한다(AI 편집이 새 흔적을 남기므로). ⑥ 동의어 치환식 재작성을 하지 않도록 프롬프트에 명시한다.

## 6. 스킬 형식과 설치 경로

| 항목 | 내용 | 수준 |
|---|---|---|
| Agent Skills 규격 | SKILL.md 필수. `name` 1~64자 소문자·숫자·하이픈이며 폴더 이름과 같아야 함. `description` 1~1024자. 선택: license, compatibility, metadata, allowed-tools(실험적). 본문 5천 토큰 미만 권장 | [부분] 공식 페이지는 열리지 않았고 미러 다수가 일치 |
| Claude Code | `.claude/skills/<이름>/SKILL.md`, `~/.claude/skills/`. 서브에이전트는 `.claude/agents/*.md`(frontmatter: name, description, tools, model) | [부분] 공식 문서 검색 요약 |
| Gemini CLI | 작업공간 `.gemini/skills/`, 사용자 `~/.gemini/skills/`. `.agents/skills/`는 대체 경로라는 가이드 2건. 공식 확인은 못함 | [부분] |
| Codex CLI | 공식 문서 요약: `.agents/skills`를 현재 폴더에서 저장소 루트까지 찾음. 사용자 `$HOME/.agents/skills`. 구 경로 `~/.codex/skills`(실험 커밋) | [부분] |

설치기는 위치 불확실성을 줄이려고 `.agents/skills`(공통), `.claude/skills`, `.gemini/skills`와 구 `~/.codex/skills`에 모두 놓을 수 있고, 실제로 놓인 경로를 보고한다. 도구가 어느 경로를 읽는지는 **설치 환경에서 스킬 목록으로 확인**해야 한다.

## 8. 아직 못 한 것

- 실제 AI 출력과 실제 사람 글의 **대규모 표본으로 임계값을 검증하지 못했다.** 내장 표본은 이 저장소에서 직접 쓴 글이다.
- 한국어 어휘 편향 논문(arXiv:2609.07447)의 **낱말 목록 원문을 못 봤다.** 시사하다·규명하다·기여하다 외 한자어 동사는 추정이다.
- 영어 위키백과 목록 원문과 Kobak 논문의 부록 표를 못 봤다.
- GPT·Claude·Gemini 각각의 2026년 말 기준 고유 습관을 체계적으로 다룬 신뢰할 만한 자료를 찾지 못했다.
