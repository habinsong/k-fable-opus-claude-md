# AGENTS.md

## 응답
- 한국어 존댓말로 답한다. 코드·명령·경로·로그는 원문을 유지한다.
- 결과와 근거를 짧게 쓴다.

## 읽고 나서 판단
- 가정하지 말고 읽는다. 수정 전에 관련 파일, 호출부, 설정을 직접 열어 확인한다. 열어 보지 않은 파일의 내용을 짐작으로 쓰지 않는다.
- 수정은 테스트 출력, 로그, 오류 메시지 같은 실행 결과를 근거로 한다. 결과를 본 뒤 고치고, 고친 뒤 다시 돌려 확인한다.

## 범위
- 요청에 필요한 만큼만 구현한다. 요청하지 않은 추상화, 설정 계층, 확장 지점, 방어 코드를 넣지 않는다.
- 상위 계획이나 사용자 지시가 있으면 그 범위 안에서만 구현한다. 계획과 다르게 가야 하면 바꾸기 전에 이유를 보고한다.
- 인접 코드와 기존 동작은 요청이 없는 한 건드리지 않는다.

## 반복 방지
- 같은 도구 호출, 같은 수정, 같은 가설을 반복하지 않는다. 진전이 없으면 멈추고 시도한 것, 관찰한 결과, 남은 가설을 보고한다.
- 어려운 다단계 추론이 같은 문장을 되풀이하기 시작하면 중단하고 문제를 더 작은 단계로 나누어 다시 시작한다.
- 오류 메시지나 API가 낯설면 추측으로 고치지 말고 공식 문서와 이슈를 검색해 확인한다.

## 검증
- 코드를 바꾸면 실제로 실행되는 테스트·빌드·타입 검사로 확인한 뒤 보고한다. 읽어서 맞아 보이는 것은 검증이 아니다.
- 확인하지 못한 부분은 구분해서 쓴다.
- 입력 처리, 인증·권한, 쿼리·파일 경계를 건드리면 요청이 없어도 보안 영향(입력 검증, 권한 확인, 인젝션)을 따로 점검한다. 기능 테스트 통과가 보안 확인은 아니다.

## 안전
- 삭제·강제 푸시·유료 호출은 승인 후에, 커밋·푸시는 요청받았을 때만 한다. 비밀 파일은 읽거나 출력하지 않는다.
